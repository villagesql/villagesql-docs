`WHERE` 中的子查询提供一个值。`FROM` 中的子查询提供一整个表，外层查询随后把它当作真实的表来读取。这就是派生表，也是您查询一个查询的结果的方法。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## 派生表的工作原理 {#how-a-derived-table-works}

```sql
SELECT COLUMN_LIST
FROM (SELECT COLUMN_LIST FROM TABLE_NAME) AS ALIAS_NAME;
```

把 `COLUMN_LIST` 换成您想要的列，把 `TABLE_NAME` 换成内层查询读取的表，把 `ALIAS_NAME` 换成结果的名称。内层查询的列名，包括任何别名，成为派生表的列。

服务器先构建内层结果，然后在它之上运行外层查询。

## 它让什么成为可能 {#what-it-makes-possible}

`GROUP BY` 用每个组 1 行替换了明细行，所以分组查询无法向您展示那些行本身。派生表两者都保留：在内层查询中分组，然后把结果连接回明细。

这个查询列出比其自身分级的平均时长更长的电影，并在每一部旁边显示那个平均值。

```sql
SELECT f.title, f.length, r.mean_for_rating
FROM film AS f
INNER JOIN (
  SELECT rating, AVG(length) AS mean_for_rating
  FROM film
  GROUP BY rating
) AS r ON r.rating = f.rating
WHERE f.length > r.mean_for_rating
ORDER BY f.rating, f.title
LIMIT 5;
```

```text
+------------------+--------+-----------------+
| title            | length | mean_for_rating |
+------------------+--------+-----------------+
| AFFAIR PREJUDICE |    117 |        111.0506 |
| AFRICAN EGG      |    130 |        111.0506 |
| ALAMO VIDEOTAPE  |    126 |        111.0506 |
| ATLANTIS CAUSE   |    170 |        111.0506 |
| BAKED CLEOPATRA  |    182 |        111.0506 |
+------------------+--------+-----------------+
5 rows in set (0.00 sec)
```

`WHERE` 和 [HAVING](/zh/tutorial/having) 都无法单独写出这个查询。`HAVING` 筛选的是组，会把标题丢掉；`WHERE` 在任何平均值存在之前就运行了。这 5 个平均值在内层查询中只算一次，连接把正确的那一个附加到每部电影上。

[相关子查询](/zh/tutorial/correlated-subqueries)课程一次一行地回答同一个问题。这种形式则只计算一次平均值。

## 别名不是可选的 {#the-alias-is-not-optional}

```sql
SELECT rating, films
FROM (SELECT rating, COUNT(*) AS films FROM film GROUP BY rating)
WHERE films > 200;
```

```text
ERROR 1248 (42000): Every derived table must have its own alias
```

`ERROR 1248` 总是这个意思，修复方法也总是一样：在右括号后面加上 `AS SOME_NAME`。名称可以是任何东西，而让它描述这些行是值得的，因为读者会在读到产生它的查询之前先遇到它。

## 派生表还是 CTE {#derived-table-or-cte}

[公用表表达式](/zh/tutorial/cte)做的是同样的工作，只是把子查询提到顶部并给它一个名称。这 2 种形式产生同样的行，下一课介绍它们的区别。[什么时候 MySQL CTE 胜过派生表](/zh/guides/ctes-in-mysql)测量了优化器会区别对待哪一种。

## 总结 {#summary}

- 用派生表查询一个查询的结果。
- 给它一个别名，因为没有别名您得到的就是 `ERROR 1248`。
- 预期内层查询的列别名成为派生表的列。
- 当您需要在计算列上筛选或连接时使用它。
- 一旦查询有多个阶段或重复同一个子查询，优先使用 CTE。
