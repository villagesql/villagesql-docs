`LIKE` 用 2 个字符描述一个形状。`REGEXP` 用一整套模式语言来描述，所以它能提出 `LIKE` 无法表达的要求：多个备选之间的选择、重复的分组、字符范围。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## REGEXP 的工作原理 {#how-regexp-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME REGEXP 'PATTERN_TEXT';
```

把 `PATTERN_TEXT` 替换为要查找的正则表达式。

当模式在值内部的任何位置匹配时，条件为真。这是与 `LIKE` 的第一个区别，`LIKE` 必须描述整个值。

下面用到的片段：

| 片段 | 含义 |
|---|---|
| `^` | 值的开头 |
| `$` | 值的结尾 |
| `.` | 任意 1 个字符 |
| `*` | 它前面的东西，重复任意次 |
| `[AB]` | 方括号中的字符任意 1 个 |
| `(AL\|BE)` | 两个备选之一 |

## 示例 {#examples}

### 1) 以……开头 {#1-starts-with}

```sql
SELECT title FROM film WHERE title REGEXP '^ACA' ORDER BY title;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
+------------------+
1 row in set (0.01 sec)
```

没有 `^`，模式会匹配标题中任何位置的 `ACA`。

### 2) 以……结尾 {#2-ends-with}

```sql
SELECT title FROM film WHERE title REGEXP 'GOLDFINGER$' ORDER BY title;
```

```text
+----------------------+
| title                |
+----------------------+
| ACE GOLDFINGER       |
| BREAKFAST GOLDFINGER |
| SILVERADO GOLDFINGER |
+----------------------+
3 rows in set (0.00 sec)
```

### 3) 2 种开头之一 {#3-either-of-2-beginnings}

```sql
SELECT first_name FROM actor WHERE first_name REGEXP '^(AL|BE)' ORDER BY first_name LIMIT 5;
```

```text
+------------+
| first_name |
+------------+
| AL         |
| ALAN       |
| ALBERT     |
| ALBERT     |
| ALEC       |
+------------+
5 rows in set (0.00 sec)
```

`ALBERT` 出现了两次，因为有 2 位演员同名。`SELECT` 报告的是行，不是不同的值。

### 4) LIKE 无法描述的形状 {#4-a-shape-like-cannot-describe}

这个查询要求标题以 `A` 或 `B` 开头，并以 `S` 结尾。

```sql
SELECT title FROM film WHERE title REGEXP '^[AB].*S$' ORDER BY title LIMIT 5;
```

```text
+----------------------+
| title                |
+----------------------+
| ADAPTATION HOLES     |
| AMELIE HELLFIGHTERS  |
| AMERICAN CIRCUS      |
| ANACONDA CONFESSIONS |
| ANALYZE HOOSIERS     |
+----------------------+
5 rows in set (0.00 sec)
```

### 5) 所有不匹配的值 {#5-everything-that-does-not-match}

`NOT REGEXP` 反转测试，与 `NOT LIKE` 的做法相同。

```sql
SELECT title, rating
FROM film
WHERE title NOT REGEXP '^A'
ORDER BY title
LIMIT 5;
```

```text
+---------------------+--------+
| title               | rating |
+---------------------+--------+
| BABY HALL           | NC-17  |
| BACKLASH UNDEFEATED | PG-13  |
| BADMAN DAWN         | R      |
| BAKED CLEOPATRA     | G      |
| BALLOON HOMEWARD    | NC-17  |
+---------------------+--------+
5 rows in set (0.00 sec)
```

NULL 值既不匹配 `REGEXP` 也不匹配 `NOT REGEXP`，因为两者对它都返回 NULL。[IS NULL](/zh/tutorial/is-null) 介绍了这一点。

## RLIKE 是同一个运算符 {#rlike-is-the-same-operator}

```sql
SELECT title FROM film WHERE title RLIKE '^ACA' ORDER BY title;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
+------------------+
1 row in set (0.00 sec)
```

`RLIKE` 和 `REGEXP` 是同一个运算符的 2 种写法。选定一种并坚持使用。

## 大小写，以及如何强制区分 {#case-and-how-to-insist-on-it}

模式遵循它所匹配内容的排序规则，与 `LIKE` 相同。所以默认情况下，小写的模式会匹配大写的文本。`REGEXP_LIKE()` 是这个运算符的函数形式，它的第三个参数会覆盖这一点：`'c'` 表示区分大小写。

```sql
SELECT REGEXP_LIKE('ACADEMY DINOSAUR', '^aca') AS default_mode,
       REGEXP_LIKE('ACADEMY DINOSAUR', '^aca', 'c') AS case_sensitive;
```

```text
+--------------+----------------+
| default_mode | case_sensitive |
+--------------+----------------+
|            1 |              0 |
+--------------+----------------+
1 row in set (0.00 sec)
```

## LIKE 能表达时优先用 LIKE {#prefer-like-when-like-can-say-it}

没有任何索引能缩小 `REGEXP` 搜索的范围，因为匹配可能从任何位置开始，所以服务器要测试每一个值。模式以固定文本开头的 `LIKE` 可以直接跳到索引中匹配的部分。当两者都能表达这个筛选时，`LIKE` 是两者中开销更低的。[LIKE](/zh/tutorial/like) 课程解释了哪些模式能使用索引，哪些不能。

## 总结 {#summary}

- 用 `REGEXP` 匹配值中任何位置的模式。
- 当匹配必须在开头或结尾时，用 `^` 和 `$` 锚定。
- 把 `RLIKE` 理解为 `REGEXP` 的另一个名字。
- 用 `REGEXP_LIKE(value, pattern, 'c')` 强制区分大小写的匹配。
- 先考虑 `LIKE`，因为没有任何索引能缩小 `REGEXP` 搜索的范围。
