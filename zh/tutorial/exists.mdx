`EXISTS` 问的是一个是或否的问题：这个子查询找到了什么吗。它不关心子查询返回了什么，只关心是否有一行，这让它成为您想测试是否有相关行、而不需要它任何列时的正确工具。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## EXISTS 的工作原理 {#how-exists-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME AS OUTER_ALIAS
WHERE EXISTS (
  SELECT 1 FROM OTHER_TABLE AS INNER_ALIAS
  WHERE INNER_ALIAS.COLUMN_NAME = OUTER_ALIAS.COLUMN_NAME
);
```

把 `COLUMN_LIST` 换成您想要的列，把 `TABLE_NAME` 和 `OTHER_TABLE` 换成 2 个表，把 `OUTER_ALIAS` 和 `INNER_ALIAS` 换成您给它们起的名称，把 `COLUMN_NAME` 换成把它们联系起来的列，把里面的 `WHERE` 换成任何能让一行成为相关行的条件。

`SELECT 1` 是惯例。选择列表会被忽略，所以 `SELECT 1`、`SELECT *` 和 `SELECT column` 的行为完全相同，而 `1` 清楚地表明没有在读取任何东西。

这个子查询是相关的：它引用了外层行。服务器可以在第一个匹配行处停下，因为 1 行就足以回答"是"。

## 示例 {#examples}

### 1) 有匹配的行 {#1-rows-that-have-a-match}

```sql
SELECT l.name
FROM language AS l
WHERE EXISTS (SELECT 1 FROM film AS f WHERE f.language_id = l.language_id)
ORDER BY l.name;
```

```text
+---------+
| name    |
+---------+
| English |
+---------+
1 row in set (0.00 sec)
```

6 种语言中有 1 种有电影。

### 2) 没有匹配的行 {#2-rows-that-have-none}

`NOT EXISTS` 是另一半，也是您写反连接的方法。

```sql
SELECT l.name
FROM language AS l
WHERE NOT EXISTS (SELECT 1 FROM film AS f WHERE f.language_id = l.language_id)
ORDER BY l.name;
```

```text
+----------+
| name     |
+----------+
| French   |
| German   |
| Italian  |
| Japanese |
| Mandarin |
+----------+
5 rows in set (0.00 sec)
```

其余 5 种。[LEFT JOIN](/zh/tutorial/left-join) 课程用 `WHERE f.film_id IS NULL` 回答同一个问题，这 2 种形式返回同样的行。

## NOT EXISTS 在 NOT IN 不安全的地方是安全的 {#not-exists-is-safe-where-not-in-is-not}

[IN](/zh/tutorial/in) 课程展示了当列表包含 NULL 时 `NOT IN` 完全不返回任何行。`NOT EXISTS` 没有这样的陷阱，因为它从不比较值：它数的是行。

所以当子查询读取的列可能为 NULL 时，请优先使用 `NOT EXISTS`。`NOT IN` 在声明为 `NOT NULL` 的列上没有问题，而一旦这一点不再成立，它就成了隐患。

## EXISTS 从不让行成倍增加 {#exists-never-multiplies-rows}

连接到一个有多个匹配行的表会让外层行按匹配数重复，[INNER JOIN](/zh/tutorial/inner-join) 课程展示了这一点。`EXISTS` 不可能这样做：它回答是或否，所以不管有多少匹配，每个外层行只出现一次。

`EXISTS`、`IN` 和连接都能表达"有相关行"，哪一个最快取决于数据。[MySQL 中的子查询与 JOIN](/zh/guides/subqueries-vs-joins) 结合执行计划对它们做了比较。

## 总结 {#summary}

- 用 `EXISTS` 测试子查询是否找到任何行。
- 在里面写 `SELECT 1`，因为选择列表会被忽略。
- 用 `NOT EXISTS` 找出没有匹配的行。
- 当子查询的列可能为 NULL 时，优先用 `NOT EXISTS` 而不是 `NOT IN`。
- 预期不会出现连接会带来的行数倍增。
