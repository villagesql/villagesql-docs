`IN` 一次把一列与多个值进行比对。它在一个子句中表达了一串 `OR` 所表达的内容，当筛选条件超过 2 个值时，大多数人都会改用它。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## IN 的工作原理 {#how-in-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME IN (FIRST_VALUE, SECOND_VALUE);
```

把 `COLUMN_NAME` 替换为要测试的列，把 `FIRST_VALUE` 和 `SECOND_VALUE` 替换为要接受的值。

当该列等于括号中的任意一个值时，条件为真。用逗号分隔这些值，需要多少就写多少。

`x IN (a, b)` 与 `x = a OR x = b` 含义相同。哪种更易读就写哪种，而超过 2 个值时，`IN` 会更易读。

## 示例 {#examples}

### 1) 匹配多个值中的任意一个 {#1-match-any-of-several-values}

```sql
SELECT title, rating
FROM film
WHERE rating IN ('G', 'PG')
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACADEMY DINOSAUR | PG     |
| ACE GOLDFINGER   | G      |
| AFFAIR PREJUDICE | G      |
| AFRICAN EGG      | G      |
| AGENT TRUMAN     | PG     |
+------------------+--------+
5 rows in set (0.00 sec)
```

### 2) 一个都不匹配 {#2-match-none-of-them}

```sql
SELECT title, rating
FROM film
WHERE rating NOT IN ('G', 'PG')
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ADAPTATION HOLES | NC-17  |
| AIRPLANE SIERRA  | PG-13  |
| AIRPORT POLLOCK  | R      |
| ALABAMA DEVIL    | PG-13  |
| ALADDIN CALENDAR | NC-17  |
+------------------+--------+
5 rows in set (0.00 sec)
```

### 3) 一组数字 {#3-a-list-of-numbers}

```sql
SELECT first_name, last_name
FROM actor
WHERE actor_id IN (1, 5, 10)
ORDER BY actor_id;
```

```text
+------------+--------------+
| first_name | last_name    |
+------------+--------------+
| PENELOPE   | GUINESS      |
| JOHNNY     | LOLLOBRIGIDA |
| CHRISTIAN  | GABLE        |
+------------+--------------+
3 rows in set (0.00 sec)
```

数字不加引号。这些行按 `actor_id` 顺序返回，是因为 `ORDER BY` 要求如此，而不是因为列表是那个顺序。

### 4) 由服务器自己算出的列表 {#4-a-list-the-server-works-out-for-itself}

括号中可以放一个查询，而不是一个列表。`film_actor` 是把每部影片与其中每位演员配对的表，所以这条语句查询演员 1 出演的影片，而您不需要知道任何影片 id。

```sql
SELECT title
FROM film
WHERE film_id IN (SELECT film_id FROM film_actor WHERE actor_id = 1)
ORDER BY title
LIMIT 5;
```

```text
+-----------------------+
| title                 |
+-----------------------+
| ACADEMY DINOSAUR      |
| ANACONDA CONFESSIONS  |
| ANGELS LIFE           |
| BULWORTH COMMANDMENTS |
| CHEAPER CLYDE         |
+-----------------------+
5 rows in set (0.00 sec)
```

写在另一个查询里面的查询叫做子查询。后面有一节会正式介绍它们。在这里先见一见是值得的，因为 `IN` 列表正是大多数人第一次写子查询的地方。

## 列表中的 NULL 会让 NOT IN 失效 {#a-null-in-the-list-breaks-not-in}

`IN` 和 `NOT IN` 对列表中的 NULL 的处理方式并不相同，而且两者都不会警告您。

对于 `IN`，列表中的 NULL 没有危害。匹配到真实值的行仍然会被保留。

```sql
SELECT title, rating
FROM film
WHERE rating IN ('G', NULL)
ORDER BY title
LIMIT 3;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACE GOLDFINGER   | G      |
| AFFAIR PREJUDICE | G      |
| AFRICAN EGG      | G      |
+------------------+--------+
3 rows in set (0.00 sec)
```

对于 `NOT IN`，同样的列表什么都不返回。

```sql
SELECT title, rating
FROM film
WHERE rating NOT IN ('G', NULL)
ORDER BY title
LIMIT 3;
```

```text
Empty set (0.01 sec)
```

每部影片都有分级，其中 822 部的分级不是 `G`，所以空结果令人意外。原因是 `NOT IN` 问的是该列是否与列表中的每一个值都不同，而没有任何东西能被证明与 NULL 不同。任何东西与 NULL 比较得到的都是 NULL，而不是真或假，所以整个条件永远不为真，没有任何行能留下来。

当列表是一个子查询时，这一点最为重要，因为不是您手写的子查询可能返回一个您没有预料到的 NULL。在可能的情况下，请在子查询内部加上 `WHERE COLUMN_NAME IS NOT NULL`。[IS NULL](/zh/tutorial/is-null) 一课介绍了 NULL 如何参与比较。

## 小结 {#summary}

- 用 `IN` 在一个子句中把一列与一组值进行比对。
- 把 `x IN (a, b)` 理解为 `x = a OR x = b`。
- 列表中的字符串加引号，数字不加。
- 当列表本身是一个查询的答案时，在括号中放一个子查询。
- 不要让 NULL 出现在 `NOT IN` 列表中，因为那会一行都不返回。
