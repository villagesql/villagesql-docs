`=` 匹配整个值。`LIKE` 匹配一个模式，所以您可以查询以某个词开头、以某个词结尾或具有某种形状的片名。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## LIKE 的工作原理 {#how-like-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME LIKE 'PATTERN_TEXT';
```

把 `PATTERN_TEXT` 替换为要匹配的模式。模式是普通文本加上 2 个特殊字符：

| 字符 | 匹配 |
|---|---|
| `%` | 任意一串字符，包括一个都没有 |
| `_` | 恰好 1 个字符 |

模式中的其他一切都匹配其自身。既没有 `%` 也没有 `_` 的模式的行为几乎与 `=` 相同。两者在尾部空格上分道扬镳：在 `utf8mb4_general_ci` 这样的 `PAD SPACE` 排序规则下，`'a ' = 'a'` 为真而 `'a ' LIKE 'a'` 为假。在 `NO PAD` 排序规则下（每一个 `utf8mb4_0900` 排序规则都属于此类），两者都为假。

## 示例 {#examples}

### 1) 以……开头 {#1-starts-with}

```sql
SELECT title FROM film WHERE title LIKE 'ACADEMY%' ORDER BY title;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
+------------------+
1 row in set (0.00 sec)
```

### 2) 以……结尾 {#2-ends-with}

```sql
SELECT title FROM film WHERE title LIKE '%GOLDFINGER' ORDER BY title;
```

```text
+----------------------+
| title                |
+----------------------+
| ACE GOLDFINGER       |
| BREAKFAST GOLDFINGER |
| SILVERADO GOLDFINGER |
+----------------------+
3 rows in set (0.00 sec)
```

### 3) 固定数量的字符 {#3-a-fixed-number-of-characters}

`J` 后面的 3 个下划线要求一个恰好 4 个字符的名字。

```sql
SELECT first_name, last_name
FROM actor
WHERE first_name LIKE 'J___'
ORDER BY first_name, last_name;
```

```text
+------------+-------------+
| first_name | last_name   |
+------------+-------------+
| JADA       | RYDER       |
| JANE       | JACKMAN     |
| JEFF       | SILVERSTONE |
| JOHN       | SUVARI      |
| JUDE       | CRUISE      |
| JUDY       | DEAN        |
+------------+-------------+
6 rows in set (0.00 sec)
```

`JOHNNY` 不在列表中，因为 `J___` 匹配 4 个字符，不多不少。

### 4) 不匹配 {#4-does-not-match}

```sql
SELECT title FROM film WHERE title NOT LIKE 'A%' ORDER BY title LIMIT 5;
```

```text
+---------------------+
| title               |
+---------------------+
| BABY HALL           |
| BACKLASH UNDEFEATED |
| BADMAN DAWN         |
| BAKED CLEOPATRA     |
| BALLOON HOMEWARD    |
+---------------------+
5 rows in set (0.00 sec)
```

## 这里 LIKE 忽略字母大小写 {#like-ignores-letter-case-here}

同一个模式改为小写，返回同一行。

```sql
SELECT title FROM film WHERE title LIKE 'academy%' ORDER BY title;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
+------------------+
1 row in set (0.00 sec)
```

这不是关于 `LIKE` 的规则。这是关于列的规则，列的排序规则决定 2 个字符串是否算作相等。Sakila 的排序规则不区分大小写，MySQL 的默认值也是如此。[大小写敏感](/zh/tutorial/case-sensitivity) 一课展示了如何检查一个列，以及如何要求区分大小写的匹配。

## 匹配字面的 % 或 _ {#matching-a-literal--or-_}

除非您另有说明，否则搜索文本中的 `%` 就是通配符。`ESCAPE` 指定一个字符，让它后面的那个字符失去特殊作用，这样模式就可以要求一个真正的百分号。

```sql
SELECT 'axxb' LIKE 'a%b' AS wildcard, 'axxb' LIKE 'a!%b' ESCAPE '!' AS literal_percent;
```

```text
+----------+-----------------+
| wildcard | literal_percent |
+----------+-----------------+
|        1 |               0 |
+----------+-----------------+
1 row in set (0.00 sec)
```

`a%b` 匹配了 `axxb`，因为 `%` 代表了 `xx`。`a!%b` 要求 `a` 和 `b` 之间有一个字面的百分号，而 `axxb` 没有。

```sql
SELECT '50%' LIKE '50!%' ESCAPE '!' AS literal_percent;
```

```text
+-----------------+
| literal_percent |
+-----------------+
|               1 |
+-----------------+
1 row in set (0.00 sec)
```

下划线的处理方式相同。

```sql
SELECT 'a_b' LIKE 'a!_b' ESCAPE '!' AS underscore, 'axb' LIKE 'a!_b' ESCAPE '!' AS any_char;
```

```text
+------------+----------+
| underscore | any_char |
+------------+----------+
|          1 |        0 |
+------------+----------+
1 row in set (0.00 sec)
```

任何您确定数据中不含的字符都可以。不用 `ESCAPE` 时，反斜杠会转义下一个字符，所以 `'a\%b'` 含义相同。当服务器的 `sql_mode` 中带有 `NO_BACKSLASH_ESCAPES` 时，这个捷径就不再起作用，而 `ESCAPE` 在两种情况下都起作用。

## 开头的 % 是开销大的那个 {#a-leading--is-the-expensive-one}

`LIKE 'ACADEMY%'` 可以使用该列上的索引，因为每个匹配都以相同的已知文本开头，而索引按排序顺序保存，所以服务器可以直接跳到索引的那一部分。`LIKE '%GOLDFINGER'` 没有给它起点，因为匹配可以从任何位置开始，所以它读取该列中的每一个值并逐个测试。对这 2 个查询运行 `EXPLAIN` 就能看出区别：估计 1 行对 1,000 行。

在 1,000 部影片上没有人会注意到。在大表上，这是一次查找与一次全表扫描的区别。当您需要大规模地在文本内部搜索时，另一种工具更合适：请参阅 [MySQL 中的全文搜索](/zh/guides/full-text-search)。

## 小结 {#summary}

- 用 `LIKE` 匹配模式而不是整个值。
- 把 `%` 理解为任意一串字符，把 `_` 理解为恰好 1 个字符。
- 用 `ESCAPE` 指定一个转义字符，以匹配字面的 `%` 或 `_`。
- 决定大小写是否重要的是列的排序规则，而不是 `LIKE`。
- 在大表上避免开头的 `%`，因为没有索引能缩小搜索范围。
