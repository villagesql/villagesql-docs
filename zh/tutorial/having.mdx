`WHERE` 在分组之前丢弃行。`HAVING` 在分组建好之后丢弃整个分组。这 1 句话就是整课的内容，下面的一切都是它的推论。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## HAVING 的工作原理 {#how-having-works}

```sql
SELECT GROUPING_COLUMN, AGGREGATE_FUNCTION(COLUMN_NAME)
FROM TABLE_NAME
GROUP BY GROUPING_COLUMN
HAVING GROUP_CONDITION;
```

把 `GROUPING_COLUMN` 替换为定义分组的列，`TABLE_NAME` 替换为表，`AGGREGATE_FUNCTION(COLUMN_NAME)` 替换为要对每个分组计算的内容，`GROUP_CONDITION` 替换为作用于整个分组的测试，例如 `COUNT(*) > 200`。

服务器先建好每一个分组，然后保留条件为真的分组。

## 示例 {#examples}

### 1) 只保留大的分组 {#1-keep-only-the-large-groups}

```sql
SELECT rating, COUNT(*) AS films
FROM film
GROUP BY rating
HAVING COUNT(*) > 200
ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
+--------+-------+
2 rows in set (0.01 sec)
```

全部 5 个分级都被计数了。然后其中 3 个分组没有通过测试，被丢弃。

### 2) HAVING 可以使用别名 {#2-having-can-use-an-alias}

别名为结果中的一列命名，而到 `HAVING` 运行时，结果已经存在。

```sql
SELECT rating, COUNT(*) AS films
FROM film
GROUP BY rating
HAVING films > 200
ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
+--------+-------+
2 rows in set (0.00 sec)
```

还是同样的 2 行，而且写起来更短。`WHERE` 做不到这一点，因为它在有结果可以命名之前就运行了：[WHERE](/zh/tutorial/where) 一课展示了您会得到的 `ERROR 1054`。

### 3) 一个查询中同时使用两个子句 {#3-both-clauses-in-one-query}

大多数真实查询两者都用：`WHERE` 选择行，`HAVING` 选择分组。

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE length > 120
GROUP BY rating
HAVING COUNT(*) > 100
ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   118 |
+--------+-------+
1 row in set (0.00 sec)
```

`WHERE` 保留了超过 120 分钟的影片，分组按分级对它们计数，`HAVING` 则保留了数量超过 100 的那 1 个分级。

## 聚合不能放在 WHERE 中 {#an-aggregate-cannot-go-in-where}

把那个 `HAVING` 条件移进 `WHERE`，服务器会直接拒绝。

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE COUNT(*) > 200
GROUP BY rating;
```

```text
ERROR 1111 (HY000): Invalid use of group function
```

`WHERE` 在分组之前运行，所以没有计数可供它测试。聚合的别名也是如此，只是错误不同。

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE films > 200
GROUP BY rating;
```

```text
ERROR 1054 (42S22): Unknown column 'films' in 'where clause'
```

两者的含义相同，修复方法也相同：把条件移到 `HAVING`。

`WHERE` 中别名引起的 `ERROR 1054` 有 2 种修复方法，而聚合正是区分它们的依据。普通表达式的别名可以在 `WHERE` 中重复写一遍，[WHERE](/zh/tutorial/where) 一课展示了这一点。聚合的别名完全不能在那里重复，原因是上面的 `ERROR 1111`，所以它必须移到 `HAVING`。

## 哪个子句测试什么 {#which-clause-tests-what}

| 子句 | 运行时机 | 测试对象 | 示例 |
|---|---|---|---|
| `WHERE` | 分组之前 | 1 行 | `WHERE length > 120` |
| `HAVING` | 分组之后 | 1 个完整的分组 | `HAVING COUNT(*) > 50` |

只要条件测试的是一行，就把它放在 `WHERE`，把 `HAVING` 留给只有分组存在之后才有意义的条件。这也是开销更小的安排，[MySQL GROUP BY 性能](/zh/guides/group-by-having) 指南测量了其中的原因。

<Note>
在 `HAVING` 中引用选择列表的别名是 MySQL 的扩展。当同一段 SQL 必须在其他数据库上运行时，请重复写聚合，而不是别名。
</Note>

## 小结 {#summary}

- 用 `HAVING` 丢弃整个分组，用 `WHERE` 丢弃行。
- `HAVING` 在 `GROUP BY` 之后运行，所以它可以测试聚合。
- 把 `ERROR 1111` 理解为：有一个聚合放在了 `WHERE` 中，而它本该在 `HAVING` 中。
- 在 `HAVING` 中引用列别名，这是 `WHERE` 做不到的。
- 当条件测试的是一行而不是一个分组时，把它放在 `WHERE`。
