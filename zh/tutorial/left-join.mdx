内连接报告匹配到了什么。`LEFT JOIN` 保留左表的每一行，无论它是否匹配，这就是您回答另一个问题的方式：什么没有匹配。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## LEFT JOIN 的工作原理 {#how-left-join-works}

```sql
SELECT COLUMN_LIST
FROM LEFT_TABLE
LEFT JOIN RIGHT_TABLE ON LEFT_TABLE.COLUMN_NAME = RIGHT_TABLE.COLUMN_NAME;
```

把 `COLUMN_LIST` 替换为您想要的列，`LEFT_TABLE` 替换为您想保留其每一行的表，`RIGHT_TABLE` 替换为您从中取出额外列的表，每个 `COLUMN_NAME` 替换为该侧用来关联两者的列。

对于匹配的行，服务器的行为与内连接相同。对于没有匹配到任何东西的左表行，它仍然保留该行，并把右表的每一列填为 NULL。`LEFT OUTER JOIN` 是同一个子句的完整写法，`OUTER` 这个词不添加任何东西。

## 示例 {#examples}

### 1) 保留未匹配的行 {#1-keep-the-unmatched-rows}

Sakila 有 6 种语言，而每部影片都是英语，所以有 5 种语言没有匹配到任何影片。内连接会丢弃它们。这个连接不会。

```sql
SELECT l.name, f.title
FROM language AS l
LEFT JOIN film AS f ON l.language_id = f.language_id
ORDER BY l.name, f.title;
```

```text
+----------+-----------------------------+
| name     | title                       |
+----------+-----------------------------+
| English  | ACADEMY DINOSAUR            |
| English  | ACE GOLDFINGER              |
| English  | ADAPTATION HOLES            |
...
+----------+-----------------------------+
1005 rows in set (0.00 sec)
```

1,005 行：1,000 个匹配，加上 5 种没有匹配到任何东西的语言各 1 行。

### 2) 只列出没有匹配到任何东西的行 {#2-list-only-the-rows-that-matched-nothing}

对右表中一个在真实匹配中永远不会是 NULL 的列加上 `WHERE`，您就恰好保留了未匹配的行。

```sql
SELECT l.name, f.title
FROM language AS l
LEFT JOIN film AS f ON l.language_id = f.language_id
WHERE f.film_id IS NULL
ORDER BY l.name;
```

```text
+----------+-------+
| name     | title |
+----------+-------+
| French   | NULL  |
| German   | NULL  |
| Italian  | NULL  |
| Japanese | NULL  |
| Mandarin | NULL  |
+----------+-------+
5 rows in set (0.00 sec)
```

`f.film_id` 是 `film` 的主键，所以匹配的行总是有它。那里的 NULL 只可能来自连接为没有匹配到任何东西的行所做的填充。测试右表的任何 `NOT NULL` 列，同样的推理都成立。主键是最安全的选择，因为它在每个表上都是 `NOT NULL`。

### 3) 它在实践中回答的问题 {#3-the-question-this-answers-in-practice}

并不是目录中的每部影片都在货架上。`inventory` 保存着拷贝，所以没有 `inventory` 行的影片就是没有人能租到的影片。

```sql
SELECT f.title
FROM film AS f
LEFT JOIN inventory AS i ON f.film_id = i.film_id
WHERE i.film_id IS NULL
ORDER BY f.title;
```

```text
+------------------------+
| title                  |
+------------------------+
| ALICE FANTASIA         |
| APOLLO TEEN            |
| ARGONAUTS TOWN         |
...
+------------------------+
42 rows in set (0.00 sec)
```

1,000 部影片中有 42 部没有拷贝。这个模式，`LEFT JOIN` 加上 `WHERE <right key> IS NULL`，就是您在一个表中找出在另一个表中没有任何匹配的行的方式。

## WHERE 中的筛选会抵消外连接 {#a-filter-in-where-undoes-the-outer-join}

这是使用 `LEFT JOIN` 时让人花费最多时间的错误。给右表加一个普通条件看起来无害。

```sql
SELECT l.name, f.title
FROM language AS l
LEFT JOIN film AS f ON l.language_id = f.language_id
WHERE f.title LIKE 'ACADEMY%'
ORDER BY l.name, f.title;
```

```text
+---------+------------------+
| name    | title            |
+---------+------------------+
| English | ACADEMY DINOSAUR |
+---------+------------------+
1 row in set (0.00 sec)
```

1 行。5 种未匹配的语言不见了，所以不管查询字面上写的是什么，它现在都是一个内连接。原因是顺序：连接先运行，产生 5 行 `f.title` 为 NULL 的行，然后 `WHERE` 测试每一行，而 `NULL LIKE 'ACADEMY%'` 是 NULL 而不是真，所以 `WHERE` 丢弃了它们。

把同一个条件移进 `ON`，它就成为匹配判断的一部分。

```sql
SELECT l.name, f.title
FROM language AS l
LEFT JOIN film AS f ON l.language_id = f.language_id AND f.title LIKE 'ACADEMY%'
ORDER BY l.name, f.title;
```

```text
+----------+------------------+
| name     | title            |
+----------+------------------+
| English  | ACADEMY DINOSAUR |
| French   | NULL             |
| German   | NULL             |
| Italian  | NULL             |
| Japanese | NULL             |
| Mandarin | NULL             |
+----------+------------------+
6 rows in set (0.00 sec)
```

全部 6 种语言，其中只有 1 种找到了匹配的影片。这条规则值得记住：在 `LEFT JOIN` 中，针对右表的条件放在 `ON`，针对左表的条件放在 `WHERE`。唯一有意为之的例外是示例 2 中的 `IS NULL`，在那里丢弃已匹配的行正是目的所在。

## 小结 {#summary}

- 用 `LEFT JOIN` 保留左表的每一行，无论是否匹配。
- 没有匹配到任何东西的行，其右侧每一列都会是 NULL。
- 用 `IS NULL` 测试右表的一个 `NOT NULL` 列，只列出未匹配的行。
- 针对右表的条件放在 `ON`，因为放在 `WHERE` 中会丢弃未匹配的行。
- 把 `LEFT OUTER JOIN` 理解为同一个子句的另一种写法。
