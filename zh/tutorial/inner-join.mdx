`INNER JOIN` 只在匹配成功时保留行。只要一个表中的行指向另一个表中的行，而您两者都想要，它就是您需要的连接。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## INNER JOIN 的工作原理 {#how-inner-join-works}

```sql
SELECT COLUMN_LIST
FROM LEFT_TABLE
INNER JOIN RIGHT_TABLE ON LEFT_TABLE.COLUMN_NAME = RIGHT_TABLE.COLUMN_NAME;
```

把 `COLUMN_LIST` 替换为您想要的列，`LEFT_TABLE` 替换为您出发的表，`RIGHT_TABLE` 替换为您从中取出额外列的表，每个 `COLUMN_NAME` 替换为该侧用来关联两者的列。

`ON` 子句说明哪些行属于一起。MySQL 取左表的每一行，找出右表中该条件成立的行，并为每个匹配返回 1 行合并后的行。没有找到任何匹配的行会被丢弃，两侧都是如此。[LEFT JOIN](/zh/tutorial/left-join) 是改为保留它的子句。

## 示例 {#examples}

### 1) 连接 2 个表 {#1-join-2-tables}

`film.language_id` 指向 `language.language_id`。匹配这一对，您就能把语言名称打印在片名旁边。

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l ON f.language_id = l.language_id
ORDER BY f.title;
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

1,000 行，与 `film` 单独查询的行数相同。每部影片恰好匹配了 1 种语言，当连接列指向单独一行时，您得到的就是这样。

### 2) 跨外键连接 {#2-join-across-a-foreign-key}

客户的街道地址保存在一个单独的表中。

```sql
SELECT c.first_name, c.last_name, a.address
FROM customer AS c
INNER JOIN address AS a ON c.address_id = a.address_id
ORDER BY c.last_name, c.first_name;
```

```text
+-------------+--------------+----------------------------------------+
| first_name  | last_name    | address                                |
+-------------+--------------+----------------------------------------+
| RAFAEL      | ABNEY        | 48 Maracaíbo Place                     |
| NATHANIEL   | ADAM         | 786 Matsue Way                         |
| KATHLEEN    | ADAMS        | 334 Munger (Monghyr) Lane              |
...
+-------------+--------------+----------------------------------------+
599 rows in set (0.00 sec)
```

599 行，每位客户 1 行。

### 3) 连接 3 个表 {#3-join-3-tables}

每多一个表就再加一个 `INNER JOIN` 子句。Sakila 把地点拆分到 `address`、`city` 和 `country` 中，所以要取到城市名需要 2 跳。

```sql
SELECT c.first_name, c.last_name, ci.city
FROM customer AS c
INNER JOIN address AS a ON c.address_id = a.address_id
INNER JOIN city AS ci ON a.city_id = ci.city_id
ORDER BY c.last_name, c.first_name;
```

```text
+-------------+--------------+----------------------------+
| first_name  | last_name    | city                       |
+-------------+--------------+----------------------------+
| RAFAEL      | ABNEY        | Talavera                   |
| NATHANIEL   | ADAM         | Joliet                     |
| KATHLEEN    | ADAMS        | Arak                       |
...
+-------------+--------------+----------------------------+
599 rows in set (0.00 sec)
```

仍然是 599 行。每个连接都只匹配了单独一行，所以行数没有变化。

### 4) 用 USING 缩短它 {#4-shorten-it-with-using}

当 2 个列的名称相同时，`USING` 可以取代 `ON`，只把名称写一次。

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l USING (language_id)
ORDER BY f.title;
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

与示例 1 相同的 1,000 行。`USING` 只在两侧名称一致时可用，所以 `ON` 是始终适用的形式。

## 匹配多行会让行数成倍增加 {#matching-several-rows-multiplies-them}

连接为每个匹配返回 1 行，所以匹配了许多行的行会返回许多次。每部影片有多位演员。

```sql
SELECT f.title, fa.actor_id
FROM film AS f
INNER JOIN film_actor AS fa ON f.film_id = fa.film_id
ORDER BY f.title, fa.actor_id;
```

```text
+-----------------------------+----------+
| title                       | actor_id |
+-----------------------------+----------+
| ACADEMY DINOSAUR            |        1 |
| ACADEMY DINOSAUR            |       10 |
| ACADEMY DINOSAUR            |       20 |
...
+-----------------------------+----------+
5462 rows in set (0.00 sec)
```

997 部影片得到 5,462 行，每个片名按演员数重复。这是连接返回的行数比您预期多的常见原因，也是基于连接计算的合计可能偏高的原因。

## 2 件让人栽跟头的事 {#2-things-that-catch-people-out}

**未匹配的行是消失，而不是留空。** 从 `language` 而不是 `film` 出发，您仍然得到 1,000 行，而不是 1,005 行：Sakila 的另外 5 种语言没有匹配到任何影片，于是被丢弃。内连接报告的是匹配到了什么，而从不报告缺了什么。[LEFT JOIN](/zh/tutorial/left-join) 是提出另一个问题的方式。

**缺少 `ON` 不是错误。** MySQL 把没有 `ON` 的 `INNER JOIN` 读作两个表的所有组合，所以一个笔误会返回 1,000 乘以 6 行，而不是报错。[CROSS JOIN](/zh/tutorial/cross-join) 介绍了这种情况，无论是有意的还是无意的。

## 小结 {#summary}

- 用带 `ON` 的 `INNER JOIN` 合并各表中匹配的行。
- 每多一个表就加 1 个 `INNER JOIN` 子句。
- 未匹配的行会消失，因为内连接只报告匹配。
- 当 1 行匹配多行时，行数会增长。
- 只有当列在两侧名称相同时才用 `USING`。
