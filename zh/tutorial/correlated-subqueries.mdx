普通的子查询运行一次并交回一个答案。相关子查询引用了外层查询的一列，所以它对每个外层行都有不同的答案，服务器必须为每一行重新运行它。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## 相关子查询的工作原理 {#how-a-correlated-subquery-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME AS OUTER_ALIAS
WHERE COLUMN_NAME > (
  SELECT AGGREGATE_FUNCTION(COLUMN_NAME)
  FROM TABLE_NAME AS INNER_ALIAS
  WHERE INNER_ALIAS.COLUMN_NAME = OUTER_ALIAS.COLUMN_NAME
);
```

把 `COLUMN_LIST` 换成您想要的列，把 `TABLE_NAME` 换成表，把 `COLUMN_NAME` 换成被比较的列，把 `AGGREGATE_FUNCTION` 换成内层查询运行的函数，把 `OUTER_ALIAS` 和 `INNER_ALIAS` 换成所涉及的表的 2 个名称。
这 2 个别名是让它起作用的关键：内层查询按名称提到外层查询，这就是相关。

请把它读作对每个外层行提出一次的问题，并填入那一行的值。

## 它回答的问题 {#the-question-it-answers}

"哪些电影比平均时长长"需要 1 个平均值。"哪些电影比**其自身分级的**平均时长长"每一行需要一个不同的平均值，而这正是相关子查询给您的东西。

```sql
SELECT f.title, f.rating, f.length
FROM film AS f
WHERE f.length > (SELECT AVG(f2.length) FROM film AS f2 WHERE f2.rating = f.rating)
ORDER BY f.rating, f.title
LIMIT 5;
```

```text
+------------------+--------+--------+
| title            | rating | length |
+------------------+--------+--------+
| AFFAIR PREJUDICE | G      |    117 |
| AFRICAN EGG      | G      |    130 |
| ALAMO VIDEOTAPE  | G      |    126 |
...
+------------------+--------+--------+
5 rows in set (0.12 sec)
```

`f2.rating = f.rating` 是关键的那一行。它把内层查询绑定到正在测试的行，所以 `G` 电影与 `G` 平均值比较，`R` 电影与 `R` 平均值比较。

去掉那一行，子查询就对整个目录求平均，每次都是同一个值，而查询回答的就是另一个问题了。

## 它对每一行运行一次 {#it-runs-once-per-row}

把上面的耗时与[子查询](/zh/tutorial/subqueries)课程中的查询比较一下，那些查询返回得快到无法测量。这个查询在 1,000 行上花了十分之一秒，您的确切数字会有所不同，因为服务器是按外层行逐一求值内层查询，而不是只求值一次。

这就是全部的权衡。相关子查询是写出"把每一行与它自己的组比较"最清晰的方式，而代价随着表的增长而增长。

MySQL 会自行把某些相关子查询改写为连接，还有其他一些形式能用 1 趟回答同样的问题。[MySQL 中的子查询与 JOIN](/zh/guides/subqueries-vs-joins) 介绍了这两者，以及如何阅读告诉您得到了哪一种的执行计划。

## 总结 {#summary}

- 用相关子查询把每一行与从它自己的组计算出的东西比较。
- 给两个表都加别名，因为内层查询必须指名外层的表。
- 预期它对每个外层行运行一次。
- 当表很大时，把它改写为派生表加连接。
