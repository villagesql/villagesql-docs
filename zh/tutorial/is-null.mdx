NULL 表示值不存在。它不是 0，也不是空字符串。它需要自己的运算符，因为您已经知道的比较运算符看不见它。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## IS NULL 的工作原理 {#how-is-null-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME IS NULL;
```

把 `COLUMN_NAME` 替换为要测试的列。

`IS NULL` 在该列没有值时为真。`IS NOT NULL` 在它有值时为真。这 2 个是仅有的可靠测试，原因是它们底下的规则：任何涉及 NULL 的比较都得到 NULL，它既不是真也不是假，所以 `WHERE` 会丢弃该行。

## 示例 {#examples}

### 1) 找出缺失的值 {#1-find-the-missing-values}

Sakila 记录了影片最初制作时所用的语言，但从未填写它。

```sql
SELECT title, original_language_id
FROM film
ORDER BY title
LIMIT 3;
```

```text
+------------------+----------------------+
| title            | original_language_id |
+------------------+----------------------+
| ACADEMY DINOSAUR |                 NULL |
| ACE GOLDFINGER   |                 NULL |
| ADAPTATION HOLES |                 NULL |
+------------------+----------------------+
3 rows in set (0.00 sec)
```

客户端在值的位置打印 `NULL`。

```sql
SELECT title FROM film WHERE original_language_id IS NULL ORDER BY title LIMIT 3;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
| ACE GOLDFINGER   |
| ADAPTATION HOLES |
+------------------+
3 rows in set (0.00 sec)
```

### 2) 找出有值的行 {#2-find-the-rows-that-have-a-value}

全部 1,000 部影片都让该列为空，所以相反的测试什么都不返回。

```sql
SELECT title FROM film WHERE original_language_id IS NOT NULL ORDER BY title;
```

```text
Empty set (0.00 sec)
```

### 3) 有时缺失的列 {#3-a-column-that-is-sometimes-missing}

`address2` 是地址的第二行。Sakila 有 603 个地址，其中 4 个把第二行记录为缺失，另外 599 个记录为空字符串。

```sql
SELECT address_id, address, address2
FROM address
WHERE address2 IS NULL
ORDER BY address_id;
```

```text
+------------+----------------------+----------+
| address_id | address              | address2 |
+------------+----------------------+----------+
|          1 | 47 MySakila Drive    | NULL     |
|          2 | 28 MySQL Boulevard   | NULL     |
|          3 | 23 Workhaven Lane    | NULL     |
|          4 | 1411 Lillydale Drive | NULL     |
+------------+----------------------+----------+
4 rows in set (0.00 sec)
```

## 缺失的值与空字符串不同 {#a-missing-value-and-an-empty-one-are-different}

603 个地址中只有 4 个没有记录第二行。另外 599 个保存的是空字符串，这是一个值：有人故意在那里什么都没写。

```sql
SELECT address_id, address2
FROM address
WHERE address2 = ''
ORDER BY address_id
LIMIT 3;
```

```text
+------------+----------+
| address_id | address2 |
+------------+----------+
|          5 |          |
|          6 |          |
|          7 |          |
+------------+----------+
3 rows in set (0.00 sec)
```

客户端对缺失的值打印 `NULL`，对空字符串什么都不打印，所以这 2 种情况在屏幕上看起来几乎一样，而在查询中的行为完全不同。`IS NULL` 找到前 4 行，`= ''` 找到另外 599 行。两个测试都不能同时找到两者，所以混有这两种情况的列需要 `address2 IS NULL OR address2 = ''` 才能抓住每一个空白。

## = NULL 永远什么都匹配不到 {#-null-matches-nothing-ever}

每部影片的 `original_language_id` 都是 NULL，所以这条语句看起来应该返回 1,000 行。

```sql
SELECT title FROM film WHERE original_language_id = NULL ORDER BY title;
```

```text
Empty set (0.01 sec)
```

没有行，没有错误，没有警告。`=` 问的是 2 个值是否相同，而 NULL 不是一个值，所以答案既不是是也不是否。答案是 NULL，而 `WHERE` 只保留条件为真的行。

同样的陷阱也会抓住 `<> NULL`，它同样什么都匹配不到。`IS NULL` 和 `IS NOT NULL` 是为这项工作而设的运算符。

有一个运算符不受这条规则约束。`<=>` 是 NULL 安全等于：它总是回答 1 或 0，并且把 2 个 NULL 算作相等。当您比较 2 个可能都缺失的列，并希望这种情况算作匹配时，就用它。[运算符](/zh/tutorial/operators) 一课把它与它所取代的比较并列展示。

## 小结 {#summary}

- 用 `IS NULL` 和 `IS NOT NULL` 测试缺失的值。
- 永远不要写 `= NULL` 或 `<> NULL`，因为两者都匹配不到任何行，而且什么都不说。
- 任何与 NULL 的比较都得到 NULL，而 `WHERE` 把它视为不为真。
- 当 2 个 NULL 应当算作相等时，用 `<=>`。
- 单独测试空字符串，因为 `IS NULL` 找不到它。
