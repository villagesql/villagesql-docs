到目前为止，每个查询都只读取 1 个表。真实的数据库把信息分散在许多表中，而连接就是跨表读取的方式。本课解释连接做什么，以及不同种类的连接各有什么用。之后的几课会逐一介绍每一种。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## 为什么数据被拆开 {#why-the-data-is-split-up}

Sakila 把每部影片的语言记录为一个数字。

```sql
SELECT film_id, title, language_id FROM film ORDER BY film_id LIMIT 3;
```

```text
+---------+------------------+-------------+
| film_id | title            | language_id |
+---------+------------------+-------------+
|       1 | ACADEMY DINOSAUR |           1 |
|       2 | ACE GOLDFINGER   |           1 |
|       3 | ADAPTATION HOLES |           1 |
+---------+------------------+-------------+
3 rows in set (0.00 sec)
```

与数字对应的名称放在它自己的表中。

```sql
SELECT language_id, name FROM language ORDER BY language_id;
```

```text
+-------------+----------+
| language_id | name     |
+-------------+----------+
|           1 | English  |
|           2 | Italian  |
|           3 | Japanese |
|           4 | Mandarin |
|           5 | French   |
|           6 | German   |
+-------------+----------+
6 rows in set (0.00 sec)
```

把 `English` 这个词存储一次并指向它 1,000 次，比存储它 1,000 次占的空间少，而更正一处拼写只需要改 1 行，而不是 1,000 行。代价是想要片名和语言名称的查询必须读取两个表。

## 连接的工作原理 {#how-a-join-works}

```sql
SELECT COLUMN_LIST
FROM LEFT_TABLE
JOIN RIGHT_TABLE ON LEFT_TABLE.COLUMN_NAME = RIGHT_TABLE.COLUMN_NAME;
```

把 `COLUMN_LIST` 替换为您想要的列，`LEFT_TABLE` 替换为您出发的表，`RIGHT_TABLE` 替换为您从中取出额外列的表，每个 `COLUMN_NAME` 替换为该侧用来关联 2 个表的列。

服务器取左表的每一行，找出右表中 `ON` 条件为真的行，并为每个匹配返回 1 行合并后的行。

## 示例 {#examples}

### 1) 读取名称而不是数字 {#1-read-the-name-instead-of-the-number}

```sql
SELECT f.title, l.name
FROM film AS f
JOIN language AS l ON f.language_id = l.language_id
ORDER BY f.title
LIMIT 3;
```

```text
+------------------+---------+
| title            | name    |
+------------------+---------+
| ACADEMY DINOSAUR | English |
| ACE GOLDFINGER   | English |
| ADAPTATION HOLES | English |
+------------------+---------+
3 rows in set (0.00 sec)
```

`AS f` 和 `AS l` 是表别名，[下一课](/zh/tutorial/table-aliases) 会介绍它们。

## 各种连接各有什么用 {#what-the-kinds-of-join-are-for}

它们只在 1 件事上不同：没有找到匹配的行会怎样。

| 连接 | 保留 |
|---|---|
| `INNER JOIN` | 只有在两侧都找到匹配的行 |
| `LEFT JOIN` | 左表的每一行，无论是否匹配 |
| `RIGHT JOIN` | 右表的每一行，无论是否匹配 |
| `CROSS JOIN` | 左表的每一行与右表的每一行配对 |

外连接保留下来的未匹配行仍然需要填充它没有值的那些列，而它用 NULL 来填充。这就是为什么 [IS NULL](/zh/tutorial/is-null) 经常出现在 `LEFT JOIN` 旁边：它是您查询那些没有匹配到任何东西的行的方式。

`CROSS JOIN` 是特殊的一个，因为它不做任何匹配。当您想要所有组合时，您会特意要求它；而当您漏掉 `ON` 子句时，您会意外得到它。

## 条件比关键字更重要 {#the-condition-matters-more-than-the-keyword}

在 MySQL 中，`JOIN`、`INNER JOIN` 和 `CROSS JOIN` 是 1 回事，语法允许它们中的任何一个带 `ON` 子句或不带。所以您输入的关键字并不决定结果。`ON` 条件是否存在才决定：有它您得到匹配，没有它您得到所有组合，无论您写的是这 3 个词中的哪一个。

因为服务器不会替您区分它们，所以当您的意思是匹配时，请写 `INNER JOIN ... ON`；当您的意思是所有组合时，请写不带 `ON` 的 `CROSS JOIN`。这样关键字就是给下一位读者的说明，而不是给服务器的指令。

## 小结 {#summary}

- 信息会分散在多个表中，1 个表通过 id 指向另一个表。
- 用连接在 1 个查询中跨这些表读取。
- 把 `ON` 条件理解为哪些行属于一起的规则。
- 根据没有匹配到任何东西的行应当怎样来选择连接的种类。
- 外连接在没有匹配的情况下保留的行，其列中会是 NULL。
