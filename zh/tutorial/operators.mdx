运算符把值组合成一个新值。您已经用过一个：`rental_rate * 1.1` 中的 `*`。本课介绍日常使用的那一组，以及让每个人都栽跟头的一种行为，也就是 `NULL` 出现时会发生什么。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## 运算符的工作原理 {#how-an-operator-works}

```sql
SELECT LEFT_VALUE OPERATOR RIGHT_VALUE;
```

把 `LEFT_VALUE` 和 `RIGHT_VALUE` 替换为值，`OPERATOR` 替换为下面的某个符号。值可以是一个列，也可以是一个字面量，也就是直接写在语句中的数字或一段文本。

没有 `FROM` 的 `SELECT` 会计算它的表达式并返回单独一行，这使它成为试用运算符最快的方式。

## 示例 {#examples}

### 1) 比较返回 1 或 0 {#1-comparison-returns-1-or-0}

MySQL 没有独立的布尔类型。成立的比较返回整数 `1`，不成立的返回 `0`。`TRUE` 和 `FALSE` 这两个词是这 2 个整数的写法。

```sql
SELECT 1 = 1, 1 <> 2, 1 != 2, 2 > 3, 3 >= 3, 2 <= 2;
```

```text
+-------+--------+--------+-------+--------+--------+
| 1 = 1 | 1 <> 2 | 1 != 2 | 2 > 3 | 3 >= 3 | 2 <= 2 |
+-------+--------+--------+-------+--------+--------+
|     1 |      1 |      1 |     0 |      1 |      1 |
+-------+--------+--------+-------+--------+--------+
1 row in set (0.00 sec)
```

相等是单个 `=`，而不是大多数编程语言使用的双 `==`。`<>` 和 `!=` 都表示不等于，行为完全相同。本教程写 `<>`。

### 2) 算术，以及哪个运算符结合得更紧 {#2-arithmetic-and-which-operator-binds-tighter}

```sql
SELECT 2 + 3 * 4, (2 + 3) * 4, 7 / 2, 7 DIV 2, 7 % 2;
```

```text
+-----------+-------------+--------+---------+-------+
| 2 + 3 * 4 | (2 + 3) * 4 | 7 / 2  | 7 DIV 2 | 7 % 2 |
+-----------+-------------+--------+---------+-------+
|        14 |          20 | 3.5000 |       3 |     1 |
+-----------+-------------+--------+---------+-------+
1 row in set (0.00 sec)
```

`2 + 3 * 4` 是 14，所以乘法先发生。括号覆盖这一点，使它变成 20。`/` 即使在 2 个整数之间也给出小数结果，`DIV` 丢掉小数部分，`%` 给出余数。

### 3) DIV 和 % 与除法结合得一样紧 {#3-div-and--bind-as-tightly-as-division}

```sql
SELECT 10 - 4 / 2, 10 - 4 DIV 2, 1 + 7 % 3;
```

```text
+------------+--------------+-----------+
| 10 - 4 / 2 | 10 - 4 DIV 2 | 1 + 7 % 3 |
+------------+--------------+-----------+
|     8.0000 |            8 |         2 |
+------------+--------------+-----------+
1 row in set (0.00 sec)
```

3 个都给出先做除法或求余数所得到的答案。如果 `-` 比 `/` 结合得更紧，第一列就会是 3 而不是 8。

### 4) 运算符对列起作用 {#4-operators-work-on-columns}

能对字面量做的任何事，都能对列做。

```sql
SELECT title, length, length > 100 AS is_long FROM film ORDER BY title;
```

```text
+-----------------------------+--------+---------+
| title                       | length | is_long |
+-----------------------------+--------+---------+
| ACADEMY DINOSAUR            |     86 |       0 |
| ACE GOLDFINGER              |     48 |       0 |
| ADAPTATION HOLES            |     50 |       0 |
| AFFAIR PREJUDICE            |    117 |       1 |
| AFRICAN EGG                 |    130 |       1 |
...
+-----------------------------+--------+---------+
1000 rows in set (0.00 sec)
```

比较变成了一列 1 和 0，别名给了它一个名称。

## NULL 不等于任何东西，包括 NULL {#null-is-not-equal-to-anything-including-null}

您在排序一课中见过 `NULL`，它是从未记录的值的标记。在这里它的行为与任何真实的值都不同。

```sql
SELECT NULL = NULL, NULL <> NULL, NULL <=> NULL, 1 <=> NULL;
```

```text
+-------------+--------------+---------------+------------+
| NULL = NULL | NULL <> NULL | NULL <=> NULL | 1 <=> NULL |
+-------------+--------------+---------------+------------+
|        NULL |         NULL |             1 |          0 |
+-------------+--------------+---------------+------------+
1 row in set (0.00 sec)
```

问一个未记录的值是否等于另一个未记录的值，这无法回答，所以 `NULL = NULL` 返回 `NULL` 而不是 1 或 0。`NULL <> NULL` 也是如此。示例 1 中的每个运算符面对 `NULL` 时都是这样。

`<=>` 是例外。它比较 2 个值，并且总是返回 1 或 0，从不返回 `NULL`，它把 `NULL` 视为等于其自身。

结果就是 `= NULL` 永远什么都匹配不到。当您需要找出值缺失的行时，[IS NULL](/zh/tutorial/is-null) 才是那个测试，它像普通比较一样返回 1 或 0。

## 小结 {#summary}

- 比较返回的是 `1` 或 `0`，而不是真或假。
- 用 `=` 表示相等，用 `<>` 表示不等。
- 记住 `*`、`/`、`DIV` 和 `%` 比 `+` 和 `-` 结合得更紧。
- 用 `DIV` 做整数除法，用 `%` 求余数。
- 任何涉及 `NULL` 的普通比较都会得到 `NULL`，请改用 `<=>` 或 `IS NULL`。
