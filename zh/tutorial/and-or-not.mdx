一个条件回答一个问题。`AND`、`OR` 和 `NOT` 把条件连接起来，让一个 `WHERE` 能够提出复合问题。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## AND、OR 和 NOT 的工作原理 {#how-and-or-and-not-work}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE FIRST_CONDITION AND SECOND_CONDITION;
```

把 `COLUMN_LIST` 换成您想要的列，把 `TABLE_NAME` 换成表，把 `FIRST_CONDITION` 和 `SECOND_CONDITION` 各换成一个独立的测试。

`AND` 只在两个条件都为真时保留一行。`OR` 在至少一个条件为真时保留一行。`NOT` 反转它后面的条件。

它们的结合强度并不相同。3 个之中，`NOT` 结合得最紧，然后是 `AND`，然后是 `OR`。因此服务器把 `a OR b AND c` 读作 `a OR (b AND c)`，这很少是写它的人想要的意思。括号可以改变这一点，而且没有任何代价。

这 3 个都比比较运算结合得更松，这就是为什么下面的 `NOT rating = 'G'` 反转的是整个比较，而不只是列。

## 示例 {#examples}

### 1) 两个条件都满足 {#1-both-conditions}

```sql
SELECT title, rating, length
FROM film
WHERE rating = 'G' AND length > 180
ORDER BY title;
```

```text
+-----------------+--------+--------+
| title           | rating | length |
+-----------------+--------+--------+
| BAKED CLEOPATRA | G      |    182 |
| CATCH AMISTAD   | G      |    183 |
| CONTROL ANTHEM  | G      |    185 |
| DARN FORRESTER  | G      |    185 |
| INTRIGUE WORST  | G      |    181 |
| LAWLESS VISION  | G      |    181 |
| MOONWALKER FOOL | G      |    184 |
| MUSCLE BRIGHT   | G      |    185 |
| YOUNG LANGUAGE  | G      |    183 |
+-----------------+--------+--------+
9 rows in set (0.00 sec)
```

9 部电影分级为 `G` 且时长超过 180 分钟。

### 2) 任一条件满足 {#2-either-condition}

```sql
SELECT title, rating
FROM film
WHERE rating = 'G' OR rating = 'PG'
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACADEMY DINOSAUR | PG     |
| ACE GOLDFINGER   | G      |
| AFFAIR PREJUDICE | G      |
| AFRICAN EGG      | G      |
| AGENT TRUMAN     | PG     |
+------------------+--------+
5 rows in set (0.00 sec)
```

拿一列与一个值列表做测试非常常见，所以它有自己的运算符。[IN](/zh/tutorial/in) 用一个子句写出同样的筛选。

### 3) 反转一个条件 {#3-reverse-a-condition}

```sql
SELECT title, rating
FROM film
WHERE NOT rating = 'G'
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACADEMY DINOSAUR | PG     |
| ADAPTATION HOLES | NC-17  |
| AGENT TRUMAN     | PG     |
| AIRPLANE SIERRA  | PG-13  |
| AIRPORT POLLOCK  | R      |
+------------------+--------+
5 rows in set (0.00 sec)
```

`NOT rating = 'G'` 和 `rating <> 'G'` 选出相同的行。单个比较请优先用 `<>`，把 `NOT` 留给反转更大的东西。

## AND 比 OR 结合得更紧 {#and-binds-tighter-than-or}

这看起来像是"分级为 G 或 PG，并且超过 180 分钟"。

```sql
SELECT title, rating, length
FROM film
WHERE rating = 'G' OR rating = 'PG' AND length > 180
ORDER BY title;
```

```text
+---------------------------+--------+--------+
| title                     | rating | length |
+---------------------------+--------+--------+
| ACE GOLDFINGER            | G      |     48 |
| AFFAIR PREJUDICE          | G      |    117 |
| AFRICAN EGG               | G      |    130 |
...
+---------------------------+--------+--------+
182 rows in set (0.00 sec)
```

182 行，而且第一行的时长是 48 分钟。`AND` 结合到了它旁边的那一对，所以服务器回答的是"分级为 G，或者分级为 PG 并且超过 180 分钟"。每部 `G` 电影仅凭第一个分支就符合条件，不管它有多长。

括号说明了本来的意思。

```sql
SELECT title, rating, length
FROM film
WHERE (rating = 'G' OR rating = 'PG') AND length > 180
ORDER BY title;
```

```text
+-----------------+--------+--------+
| title           | rating | length |
+-----------------+--------+--------+
| BAKED CLEOPATRA | G      |    182 |
| CATCH AMISTAD   | G      |    183 |
| CONTROL ANTHEM  | G      |    185 |
| DARN FORRESTER  | G      |    185 |
| INTRIGUE WORST  | G      |    181 |
| LAWLESS VISION  | G      |    181 |
| MONSOON CAUSE   | PG     |    182 |
| MOONWALKER FOOL | G      |    184 |
| MUSCLE BRIGHT   | G      |    185 |
| RECORDS ZORRO   | PG     |    182 |
| STAR OPERATION  | PG     |    181 |
| WORST BANGER    | PG     |    185 |
| YOUNG LANGUAGE  | G      |    183 |
+-----------------+--------+--------+
13 rows in set (0.01 sec)
```

13 行。两个查询都不是无效的，也没有任何警告，所以唯一的防线是在写的时候给每一处 `AND` 和 `OR` 的混合加上括号。

## OR 不接受一个裸的第二个值 {#or-does-not-take-a-bare-second-value}

`rating = 'G' OR 'PG'` 用英语读起来是"分级为 G 或 PG"。对服务器来说它是 2 个独立的条件，第二个条件是单独存在的字符串 `'PG'`。

```sql
SELECT title, rating
FROM film
WHERE rating = 'G' OR 'PG'
ORDER BY title
LIMIT 5;
```

```text
+-------------------+--------+
| title             | rating |
+-------------------+--------+
| ACE GOLDFINGER    | G      |
| AFFAIR PREJUDICE  | G      |
| AFRICAN EGG       | G      |
| ALAMO VIDEOTAPE   | G      |
| AMISTAD MIDSUMMER | G      |
+-------------------+--------+
5 rows in set, 1 warning (0.00 sec)
```

只返回了 `G` 电影，而且结果末尾报告了一个警告。在同一个会话中运行 `SHOW WARNINGS`，服务器会解释自己：`Warning 1292 Truncated incorrect DOUBLE value: 'PG'`。

一个条件必须是真或假，所以服务器把 `'PG'` 转换成了数字。`'PG'` 不以数字开头，转换结果是 0，而 0 是假。因此整个第二个分支是死的。请在两侧都写出列名，或者使用 [IN](/zh/tutorial/in)。

## NOT 只反转紧随其后的东西 {#not-reverses-only-what-comes-next}

```sql
SELECT title, rating, length
FROM film
WHERE NOT rating = 'G' AND length > 180
ORDER BY title;
```

```text
+--------------------+--------+--------+
| title              | rating | length |
+--------------------+--------+--------+
| ANALYZE HOOSIERS   | R      |    181 |
| CHICAGO NORTH      | PG-13  |    185 |
| CONSPIRACY SPIRIT  | PG-13  |    184 |
...
+--------------------+--------+--------+
30 rows in set (0.00 sec)
```

`NOT` 取的是它旁边的比较，所以这是"分级不是 G，并且超过 180 分钟"。要反转整个一对条件，请给它加括号。

```sql
SELECT title, rating, length
FROM film
WHERE NOT (rating = 'G' AND length > 180)
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+--------+
| title            | rating | length |
+------------------+--------+--------+
| ACADEMY DINOSAUR | PG     |     86 |
| ACE GOLDFINGER   | G      |     48 |
| ADAPTATION HOLES | NC-17  |     50 |
| AFFAIR PREJUDICE | G      |    117 |
| AFRICAN EGG      | G      |    130 |
+------------------+--------+--------+
5 rows in set (0.00 sec)
```

`ACE GOLDFINGER` 分级为 `G`，时长 48 分钟。它不满足括号里的那一对条件，所以反转这一对就保留了它。

## 总结 {#summary}

- 当每个条件都必须成立时用 `AND`，任意一个成立即可时用 `OR`。
- 给任何混合了 `AND` 和 `OR` 的 `WHERE` 加括号，因为 `AND` 结合得更紧。
- 预期 `NOT` 只反转它旁边的那个条件。
- 在 `OR` 的两侧都重复列名，因为裸的值会被转换成数字。
- 留意结果末尾的警告计数，然后运行 `SHOW WARNINGS`。
