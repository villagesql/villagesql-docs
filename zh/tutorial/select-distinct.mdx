`SELECT DISTINCT` 把每个结果行只返回一次，无论它出现多少次。它回答"这一列中出现了哪些值"这类问题，这往往是您面对一个陌生的表时最先想知道的事。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## DISTINCT 的工作原理 {#how-distinct-works}

```sql
SELECT DISTINCT COLUMN_LIST
FROM TABLE_NAME;
```

把 `COLUMN_LIST` 替换为您想要的列，`TABLE_NAME` 替换为表。`DISTINCT` 紧跟在 `SELECT` 之后，作用于整个选择列表，而不是它旁边的那一列。仅这一个事实就解释了它带来的大多数意外。

## 示例 {#examples}

### 1) 一列中的值 {#1-the-values-in-one-column}

Sakila 给每部影片都定了分级。这个查询问的是存在哪些分级。

```sql
SELECT DISTINCT rating FROM film;
```

```text
+--------+
| rating |
+--------+
| PG     |
| G      |
| NC-17  |
| PG-13  |
| R      |
+--------+
5 rows in set (0.00 sec)
```

1,000 部影片共 5 个分级。它们的顺序没有什么用处，因为 `DISTINCT` 只去除重复，对顺序不做任何保证。当您需要顺序时，请加上 `ORDER BY`。

### 2) 另一列 {#2-another-column}

```sql
SELECT DISTINCT rental_rate FROM film;
```

```text
+-------------+
| rental_rate |
+-------------+
|        0.99 |
|        4.99 |
|        2.99 |
+-------------+
3 rows in set (0.00 sec)
```

目录中的每部影片都定价为 3 种价格之一。

### 3) 不同的组合 {#3-distinct-combinations}

写出 2 列，您得到的是每一种不同的配对，而不是每列各自的值。

```sql
SELECT DISTINCT rating, rental_rate
FROM film
ORDER BY rating, rental_rate;
```

```text
+--------+-------------+
| rating | rental_rate |
+--------+-------------+
| G      |        0.99 |
| G      |        2.99 |
| G      |        4.99 |
| PG     |        0.99 |
| PG     |        2.99 |
| PG     |        4.99 |
| PG-13  |        0.99 |
| PG-13  |        2.99 |
| PG-13  |        4.99 |
| R      |        0.99 |
| R      |        2.99 |
| R      |        4.99 |
| NC-17  |        0.99 |
| NC-17  |        2.99 |
| NC-17  |        4.99 |
+--------+-------------+
15 rows in set (0.00 sec)
```

5 个分级乘以 3 种价格等于 15，而且每种组合恰好都出现了。

## 为什么排序后的分级不是按字母顺序 {#why-the-sorted-ratings-are-not-alphabetical}

那个结果按 `rating` 排序，顺序却是 `G`、`PG`、`PG-13`、`R`、`NC-17`。按字母顺序 `NC-17` 应该排第二。`ORDER BY` 确实起了作用，原因在于这一列的类型：

`SHOW COLUMNS` 列出一个表的列，`LIKE` 后面的模式把它缩小到 1 个名字。

```sql
SHOW COLUMNS FROM film LIKE 'rating';
```

```text
+--------+------------------------------------+------+-----+---------+-------+
| Field  | Type                               | Null | Key | Default | Extra |
+--------+------------------------------------+------+-----+---------+-------+
| rating | enum('G','PG','PG-13','R','NC-17') | YES  |     | G       |       |
+--------+------------------------------------+------+-----+---------+-------+
1 row in set (0.00 sec)
```

`rating` 是一个 `ENUM`，这种列类型只接受一个固定列表中的值。MySQL 把每个值存为它在该列表中的位置，并按位置排序，所以 `ENUM` 按值声明的顺序排序。这里声明的顺序从限制最少的分级到限制最多的分级。

## 增加一列可能让它失效 {#adding-a-column-can-undo-it}

因为 `DISTINCT` 看的是整行，增加一个几乎唯一的列之后就几乎什么都去不掉了。

```sql
SELECT DISTINCT rating, title FROM film;
```

```text
+--------+-----------------------------+
| rating | title                       |
+--------+-----------------------------+
| PG     | ACADEMY DINOSAUR            |
| G      | ACE GOLDFINGER              |
| NC-17  | ADAPTATION HOLES            |
...
+--------+-----------------------------+
1000 rows in set (0.00 sec)
```

全部 1,000 行都返回了。每个标题都不同，所以每对 `rating` 和 `title` 都不同，没有任何重复。`DISTINCT` 在这里不可能给您 5 行，因为您要的那一列有 1,000 个不同的值。把许多行折叠成每个分级 1 行是另一种操作，[GROUP BY](/zh/tutorial/group-by) 才是做这件事的子句。

## 总结 {#summary}

- 用 `SELECT DISTINCT` 把每个结果行只返回一次。
- 预期它同时作用于选择列表中的每一列。
- 当您想让不同的值有序时，加上 `ORDER BY`。
- 预期 `ENUM` 列按声明顺序排序，而不是按字母顺序。
