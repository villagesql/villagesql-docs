本教程的每一课都查询同一个数据库，所以您只需加载一次，之后就不用再想它。这个数据库就是 Sakila，它模拟了一家有 2 个门店的 DVD 租赁连锁店：它们经营的影片、租影片的顾客、服务顾客的员工，以及由此产生的付款。

Sakila 适合做教程是因为它的规模。1,000 部影片和 16,044 条租赁记录足以让查询返回值得一看的结果，而表的数量又少到您可以把它的结构记在脑子里。

## 它包含什么 {#what-is-in-it}

Sakila 有 16 个数据表。以下是刚加载好的副本上的行数。

| 表 | 行数 | 内容 |
|---|---|---|
| `actor` | 200 | 每位演员一行 |
| `address` | 603 | 街道地址，由顾客、员工和门店共用 |
| `category` | 16 | 影片类型 |
| `city` | 600 | 城市，每个城市属于一个国家 |
| `country` | 109 | 国家 |
| `customer` | 599 | 任一门店的每位顾客一行 |
| `film` | 1000 | 影片目录，含租赁价格和时长 |
| `film_actor` | 5462 | 哪些演员出演哪些影片 |
| `film_category` | 1000 | 每部影片属于哪个类型 |
| `film_text` | 1000 | 影片标题和描述，用于全文搜索 |
| `inventory` | 4581 | 影片的实体拷贝，存放在某个门店 |
| `language` | 6 | 影片可用的语言 |
| `payment` | 16044 | 每笔收款一行 |
| `rental` | 16044 | 每次租赁一行，含借出和归还日期 |
| `staff` | 2 | 2 名员工 |
| `store` | 2 | 2 家门店 |

等下一课加载好 Sakila 之后，您可以自己核对其中任何一个行数。`COUNT(*)` 报告一个表有多少行：

```sql
SELECT COUNT(*) FROM actor;
```

```text
+----------+
| COUNT(*) |
+----------+
|      200 |
+----------+
1 row in set (0.00 sec)
```

Sakila 还带有 7 个视图，视图是保存下来的查询，而不是存储的行：`actor_info`、`customer_list`、`film_list`、`nicer_but_slower_film_list`、`sales_by_film_category`、`sales_by_store` 和 `staff_list`。没有任何一课使用它们，但如果您想读读别人是怎么写同样的连接的，它们就在那里。

## 课程依赖的表 {#the-tables-the-lessons-lean-on}

您不需要全部 16 个表。少数几个承担了大部分示例。

- `film` 是主力。它有文本、数字、日期和一个外键，所以大多数概念只靠它就能展示。
- `language` 有 6 行，所以针对它的查询会打印出您能用肉眼核对的完整结果。
- `customer`、`address` 和 `city` 通过外键串联在一起，这使它们成为讲解连接的几课的自然选择。

## 它来自哪里 {#where-it-comes-from}

Oracle 把 Sakila 作为示例数据库发布。它的结构文件和数据文件受 New BSD 许可证保护，该许可证允许商业使用，只要声明随文件一起传播。该声明完整转载于存放这些文档的仓库的 [`NOTICE` 文件](https://github.com/villagesql/villagesql-docs/blob/main/NOTICE)中。

下一课会从 Oracle 下载 Sakila 并把它加载到您的服务器中。
