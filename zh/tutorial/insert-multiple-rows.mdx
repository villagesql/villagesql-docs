一条 `INSERT` 可以携带任意多行。用逗号分隔每一行的括号。这比每行 1 条语句少打字，而且只需往返服务器 1 次而不是许多次。

这些示例使用 [INSERT](/zh/tutorial/insert) 中的 `sakila_practice` 数据库。开始之前，请再运行一次那里的设置代码块，然后用 `mysql -u root -p sakila_practice` 打开客户端。

## 多行 INSERT 的工作原理 {#how-a-multi-row-insert-works}

```sql
INSERT INTO TABLE_NAME (COLUMN_LIST) VALUES
  (FIRST_ROW_VALUES),
  (SECOND_ROW_VALUES);
```

把 `TABLE_NAME` 替换为表，`COLUMN_LIST` 替换为您提供的列，`FIRST_ROW_VALUES` 和 `SECOND_ROW_VALUES` 各替换为对应这些列的值，每列 1 个。

列清单只写一次，并约束每一行。每一组括号按该顺序提供值。

## 示例 {#examples}

### 1) 1 条语句插入 3 行 {#1-3-rows-in-1-statement}

```sql
INSERT INTO member (first_name, last_name, email, joined) VALUES
  ('Jennifer', 'Davis',  'jennifer.davis@example.com',  '2026-03-18'),
  ('Barbara',  'Jones',  'barbara.jones@example.com',   '2026-03-19'),
  ('Elizabeth','Brown',  'elizabeth.brown@example.com', '2026-03-21');
```

```text
Query OK, 3 rows affected (0.00 sec)
Records: 3  Duplicates: 0  Warnings: 0
```

只要一条语句可能写入超过 1 行，第二行就会出现，这包括多行 `VALUES` 列表和任何 [INSERT SELECT](/zh/tutorial/insert-select)。`Records` 统计您发送的行数，`Duplicates` 统计与已存储行冲突的行数，`Warnings` 统计服务器不得不调整的内容。这 3 个数字都与您发送的内容一致，就是没有任何东西被悄悄改动的标志。

```sql
SELECT member_id, first_name, last_name FROM member;
```

```text
+-----------+------------+-----------+
| member_id | first_name | last_name |
+-----------+------------+-----------+
|         1 | Mary       | Smith     |
|         2 | Patricia   | Johnson   |
|         3 | Linda      | Williams  |
|         4 | Jennifer   | Davis     |
|         5 | Barbara    | Jones     |
|         6 | Elizabeth  | Brown     |
+-----------+------------+-----------+
6 rows in set (0.00 sec)
```

id 按照各行写入的顺序接续下去。

## 一个坏行会让整条语句作废 {#one-bad-row-throws-the-whole-statement-away}

下面的语句携带 3 行。中间那行重复使用了 Mary Smith 的地址，而 `email` 上的 `UNIQUE` 索引拒绝了它。

```sql
INSERT INTO member (first_name, last_name, email, joined) VALUES
  ('Maria',  'Miller', 'maria.miller@example.com', '2026-04-02'),
  ('Susan',  'Wilson', 'mary.smith@example.com',   '2026-04-03'),
  ('Margaret','Moore', 'margaret.moore@example.com','2026-04-04');
```

```text
ERROR 1062 (23000): Duplicate entry 'mary.smith@example.com' for key 'member.uq_member_email'
```

另外 2 行也没有写入。

```sql
SELECT COUNT(*) AS members FROM member;
```

```text
+---------+
| members |
+---------+
|       6 |
+---------+
1 row in set (0.00 sec)
```

一条语句要么全部成功，要么全部失败，所以一批 10,000 行中只要有 1 个坏值，就什么都不会写入。全有或全无也意味着大批数据在发送前需要先检查，因为服务器只会指出 1 个违规行，然后停下。

## INSERT IGNORE 把错误变成警告 {#insert-ignore-turns-the-error-into-a-warning}

`INSERT IGNORE` 保留它能保留的行，跳过其余的行。

```sql
INSERT IGNORE INTO member (first_name, last_name, email, joined) VALUES
  ('Maria',  'Miller', 'maria.miller@example.com', '2026-04-02'),
  ('Susan',  'Wilson', 'mary.smith@example.com',   '2026-04-03');
SHOW WARNINGS;
```

```text
Query OK, 1 row affected, 1 warning (0.00 sec)
Records: 2  Duplicates: 1  Warnings: 1

+---------+------+---------------------------------------------------------------------------+
| Level   | Code | Message                                                                   |
+---------+------+---------------------------------------------------------------------------+
| Warning | 1062 | Duplicate entry 'mary.smith@example.com' for key 'member.uq_member_email' |
+---------+------+---------------------------------------------------------------------------+
1 row in set (0.00 sec)
```

`Records: 2  Duplicates: 1` 准确报告了发生的事：提供了 2 行，拒绝了 1 行。`SHOW WARNINGS` 随后指出了它，同样的 `ERROR 1062` 文本以警告而不是失败的形式出现。

```sql
SELECT COUNT(*) AS members FROM member;
```

```text
+---------+
| members |
+---------+
|       7 |
+---------+
1 row in set (0.00 sec)
```

当重复确实表示"已经有了"时，使用 `IGNORE`。在其他情况下，它是一件钝器，因为它也会把其他错误降级，包括对列来说过长的值，以及必填列没有值的行。每次 `INSERT IGNORE` 之后都要运行 `SHOW WARNINGS`，否则您不会知道它丢弃了什么。当正确的做法是更新已存储的行时，请改用 [upsert](/zh/tutorial/upsert)。

## 小结 {#summary}

- 用逗号分隔每一行的括号，列清单只写一次。
- 读取 `Records`、`Duplicates` 和 `Warnings`，确认没有任何东西被调整。
- 1 个被拒绝的行会中止整条语句，什么都不写入。
- 用 `INSERT IGNORE` 保留好的行，之后读取 `SHOW WARNINGS`。
- 优先使用 1 条多行语句，而不是许多条单行语句。
