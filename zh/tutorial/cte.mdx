公用表表达式在使用它的查询之前，在顶部给一个查询起一个名称。结果与[派生表](/zh/tutorial/derived-tables)相同，而且它的阅读顺序与您的思路一致：先定义各个部分，然后使用它们。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## CTE 的工作原理 {#how-a-cte-works}

```sql
WITH CTE_NAME AS (
  SELECT COLUMN_LIST FROM TABLE_NAME
)
SELECT COLUMN_LIST FROM CTE_NAME;
```

把 `CTE_NAME` 换成中间结果的名称，把 `COLUMN_LIST` 换成您想要的列，把 `TABLE_NAME` 换成内层查询读取的表。然后主查询把 `CTE_NAME` 当作一个表来读取。

CTE 只持续 1 条语句。它不会被存储，下一个查询对它一无所知。

## 示例 {#examples}

### 1) 一个命名的步骤 {#1-one-named-step}

```sql
WITH counts AS (
  SELECT rating, COUNT(*) AS films FROM film GROUP BY rating
)
SELECT rating, films FROM counts WHERE films > 200 ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
+--------+-------+
2 rows in set (0.00 sec)
```

这与派生表课程中把子查询写在 `FROM` 里的查询相同，只是计数被从 `FROM` 中提出来并给了一个名称。

### 2) 多个步骤，每一个建立在前一个之上 {#2-several-steps-each-built-on-the-last}

用逗号分隔多个 CTE，后面的一个可以读取前面的一个。这是派生表不重复自己就做不到的事。

```sql
WITH counts AS (
  SELECT rating, COUNT(*) AS films FROM film GROUP BY rating
),
busiest AS (
  SELECT MAX(films) AS most FROM counts
)
SELECT c.rating, c.films
FROM counts AS c
INNER JOIN busiest AS b ON c.films = b.most;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
+--------+-------+
1 row in set (0.00 sec)
```

`busiest` 读取 `counts`，主查询读取两者。如果写成派生表，计数查询会出现两次。

## CTE 给您而派生表不给您的东西 {#what-a-cte-gives-you-that-a-derived-table-does-not}

两种方式的行都是一样的。有 2 点不同：

- CTE 带有名称，所以一个 3 阶段的查询可以从上到下读。`counts` 和 `busiest` 告诉下一位读者每个部分是做什么的。
- 一个 CTE 可以在同一条语句中被多次引用。派生表必须再写一遍。

优化器是否区别对待这 2 种形式是另一个问题，[什么时候 MySQL CTE 胜过派生表](/zh/guides/ctes-in-mysql)对此做了测量。

## 总结 {#summary}

- 用 `WITH name AS (...)` 在读取它的查询之前给一个查询命名。
- 用逗号分隔多个 CTE，并让后面的一个读取前面的一个。
- 预期 CTE 只持续 1 条语句。
- 当查询有多个阶段或重复一个子查询时，优先使用 CTE。
