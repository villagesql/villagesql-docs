`LIMIT` 限制查询返回多少行。想看一个大表的开头时您会用到它，它也是分页浏览结果背后的机制。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## LIMIT 的工作原理 {#how-limit-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
ORDER BY SORT_COLUMN
LIMIT ROW_COUNT OFFSET SKIP_COUNT;
```

把 `ROW_COUNT` 替换为您想要的行数，`SKIP_COUNT` 替换为先要跳过的行数。`LIMIT` 放在最后，在 `ORDER BY` 之后。`OFFSET` 部分是可选的。

## 示例 {#examples}

### 1) 开头的几行 {#1-the-first-few-rows}

```sql
SELECT title FROM film ORDER BY title LIMIT 5;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
| ACE GOLDFINGER   |
| ADAPTATION HOLES |
| AFFAIR PREJUDICE |
| AFRICAN EGG      |
+------------------+
5 rows in set (0.00 sec)
```

整个结果就是 5 行，所以结尾的边框和计数是它真正的结尾，而不是截断。

### 2) 先跳过一些行 {#2-skip-some-rows-first}

```sql
SELECT title FROM film ORDER BY title LIMIT 5 OFFSET 10;
```

```text
+-----------------+
| title           |
+-----------------+
| ALAMO VIDEOTAPE |
| ALASKA PHANTOM  |
| ALI FOREVER     |
| ALICE FANTASIA  |
| ALIEN CENTER    |
+-----------------+
5 rows in set (0.00 sec)
```

排序列表中的第 11 到第 15 行。

### 3) 2 个数字的形式 {#3-the-2-number-form}

MySQL 也接受把偏移量和行数写成以逗号分隔的一对，偏移量在前。它的含义完全相同。

```sql
SELECT title FROM film ORDER BY title LIMIT 10, 5;
```

```text
+-----------------+
| title           |
+-----------------+
| ALAMO VIDEOTAPE |
| ALASKA PHANTOM  |
| ALI FOREVER     |
| ALICE FANTASIA  |
| ALIEN CENTER    |
+-----------------+
5 rows in set (0.00 sec)
```

与示例 2 相同的 5 个片名。这 2 个数字在 2 种形式中的顺序正好相反，这很容易引起差一错误，所以本教程写 `LIMIT ROW_COUNT OFFSET SKIP_COUNT`。

## 没有 ORDER BY 的 LIMIT 要求的是任意的行 {#limit-without-order-by-asks-for-arbitrary-rows}

去掉 `ORDER BY`，查询仍然能运行。

```sql
SELECT title FROM film LIMIT 5;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
| ACE GOLDFINGER   |
| ADAPTATION HOLES |
| AFFAIR PREJUDICE |
| AFRICAN EGG      |
+------------------+
5 rows in set (0.00 sec)
```

这与排序查询返回的 5 个片名相同，而这正是它危险的地方。语句中没有任何东西要求按那个顺序返回它们。问问服务器它是如何运行这个查询的，它会说明为什么它们以那个顺序返回：

```sql
EXPLAIN SELECT title FROM film LIMIT 5;
```

```text
+----+-------------+-------+------------+-------+---------------+-----------+---------+------+------+----------+-------------+
| id | select_type | table | partitions | type  | possible_keys | key       | key_len | ref  | rows | filtered | Extra       |
+----+-------------+-------+------------+-------+---------------+-----------+---------+------+------+----------+-------------+
|  1 | SIMPLE      | film  | NULL       | index | NULL          | idx_title | 514     | NULL | 1000 |   100.00 | Using index |
+----+-------------+-------+------------+-------+---------------+-----------+---------+------+------+----------+-------------+
1 row in set, 1 warning (0.00 sec)
```

那个 `1 warning` 不需要追究。`EXPLAIN` 和 `EXPLAIN FORMAT=JSON` 会附带 `Note 1003`，它保存着优化器改写后的查询，`SHOW WARNINGS` 会打印它。

`key` 列指出了 `idx_title`，这是 `title` 上的一个索引，它已经按排序顺序保存了该列，所以读取索引是回答查询最省力的方式。行按排序顺序到达，是这个选择的副作用。删掉那个索引、给选择列表再加一列，或者给服务器更多数据，这个选择就可能改变，而您的查询没有任何变化。

除非 `ORDER BY` 说明是哪些行，否则 `LIMIT` 的意思是"任意的行"。

## 小结 {#summary}

- 用 `LIMIT` 限制返回多少行。
- 加上 `OFFSET`，在取行之前先跳过一些行。
- 优先使用 `LIMIT ROW_COUNT OFFSET SKIP_COUNT`，而不是把数字顺序颠倒的逗号形式。
- 每次都把 `LIMIT` 与 `ORDER BY` 搭配使用，否则您要求的就是任意的行。
