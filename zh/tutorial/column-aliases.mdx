结果集的列标题取自您放在选择列表中的任何东西。对于普通的列，标题就是列名，这通常没有问题。对于计算，标题是您输入的表达式，这就不好了。别名用您选择的名称替换那个标题。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## 别名的工作原理 {#how-an-alias-works}

```sql
SELECT COLUMN_OR_EXPRESSION AS ALIAS_NAME
FROM TABLE_NAME;
```

把 `COLUMN_OR_EXPRESSION` 换成您想要的列或计算，把 `ALIAS_NAME` 换成您希望它拥有的标题，把 `TABLE_NAME` 换成表。

别名只作用于结果。表本身没有任何改变，下一个查询对它一无所知。

## 示例 {#examples}

### 1) 重命名一列 {#1-rename-a-column}

```sql
SELECT title AS film_title FROM film;
```

```text
+-----------------------------+
| film_title                  |
+-----------------------------+
| ACADEMY DINOSAUR            |
| ACE GOLDFINGER              |
| ADAPTATION HOLES            |
| AFFAIR PREJUDICE            |
| AFRICAN EGG                 |
...
+-----------------------------+
1000 rows in set (0.00 sec)
```

标题显示为 `film_title`。值没有改动。

### 2) 给计算命名 {#2-name-a-calculation}

这是别名真正发挥作用的地方。没有别名时，标题就是那段算式。

```sql
SELECT title, rental_rate * 1.1 AS price_with_tax FROM film;
```

```text
+-----------------------------+----------------+
| title                       | price_with_tax |
+-----------------------------+----------------+
| ACADEMY DINOSAUR            |          1.089 |
| ACE GOLDFINGER              |          5.489 |
| ADAPTATION HOLES            |          3.289 |
| AFFAIR PREJUDICE            |          3.289 |
| AFRICAN EGG                 |          3.289 |
...
+-----------------------------+----------------+
1000 rows in set (0.00 sec)
```

应用程序代码按列名读取结果，所以一个未命名的表达式会让那段代码依赖于您所写算式的确切文本。

### 3) 包含空格的别名 {#3-an-alias-containing-a-space}

由字母、数字和下划线组成的别名不需要引号。其他任何东西都需要，包括空格，或者 MySQL 保留给自己使用的词，例如 `order` 或 `select`。反引号是该用的引号样式。

```sql
SELECT title AS `Film Title` FROM film;
```

```text
+-----------------------------+
| Film Title                  |
+-----------------------------+
| ACADEMY DINOSAUR            |
| ACE GOLDFINGER              |
| ADAPTATION HOLES            |
...
+-----------------------------+
1000 rows in set (0.00 sec)
```

单引号产生同样的标题：

```sql
SELECT title AS 'Film Title' FROM film;
```

```text
+-----------------------------+
| Film Title                  |
+-----------------------------+
| ACADEMY DINOSAUR            |
| ACE GOLDFINGER              |
| ADAPTATION HOLES            |
...
+-----------------------------+
1000 rows in set (0.00 sec)
```

不过它们并非处处等价。反引号标记一个名称，而单引号标记一个字符串，后面引用这个别名的子句能分辨出区别。下一课会展示这种出错的情况。用反引号，这个问题就永远不会出现。

完全不加引号，服务器会停在空格处：

```sql
SELECT title AS Film Title FROM film;
```

```text
ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'Title FROM film' at line 1
```

`ERROR 1064` 是通用的语法错误。消息末尾引号中的片段是服务器放弃的地方，通常在真正的错误之后一两个词。

## AS 是可选的，而省略它会掩盖笔误 {#as-is-optional-and-leaving-it-out-hides-a-typo}

列后面的一个裸名称与 `AS` 的意思相同。这也是一个漏掉的逗号伪装自己的方式。

```sql
SELECT title release_year FROM film;
```

```text
+-----------------------------+
| release_year                |
+-----------------------------+
| ACADEMY DINOSAUR            |
| ACE GOLDFINGER              |
| ADAPTATION HOLES            |
...
+-----------------------------+
1000 rows in set (0.00 sec)
```

这本来想要的是 2 列。漏掉的逗号把 `release_year` 变成了 `title` 的别名，所以结果只有 1 列，标题为 `release_year`，内容是电影标题。服务器没有报任何错误，因为这条语句是有效的。

在每个别名上写 `AS` 并不会让服务器拒绝这种写法，因为这里的两列都没有别名。但它确实能让您在回读查询时看见这个错误：列后面一个裸名称，前面没有 `AS`，就是一个漏掉的逗号。

## 总结 {#summary}

- 用 `AS` 给结果列起一个您自己的名称。
- 总是给计算列加别名，因为它的默认标题是表达式。
- 当别名包含空格或保留字时，用反引号引起来。
- 在每个别名上写 `AS`，这样一个裸名称读起来就是一个漏掉的逗号。
