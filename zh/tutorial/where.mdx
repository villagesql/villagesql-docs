`WHERE` 保留满足条件的行，丢弃其余的行。到目前为止，每一课返回的都是整个表。这个子句把一个表变成一个答案。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## WHERE 的工作原理 {#how-where-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE SEARCH_CONDITION;
```

把 `COLUMN_LIST` 替换为您想要的列，`TABLE_NAME` 替换为表，`SEARCH_CONDITION` 替换为服务器可以一次对一行应用的测试。服务器读取每一行，根据该行的值计算条件，结果为真时保留该行。结果为假或为 NULL 的行会被丢弃。

`WHERE` 放在 `FROM` 之后、`ORDER BY` 之前，这也是结果被定义的顺序：先筛选，再对留下的行排序，然后应用 `LIMIT`。所以 `WHERE` 之后的 `LIMIT 5` 给您的是 5 个匹配的行，而不是其中部分匹配的 5 行。服务器可以用它喜欢的任何方式得出这个答案，`EXPLAIN` 会显示它选了哪种方式。

## 示例 {#examples}

### 1) 匹配一个值 {#1-match-one-value}

Sakila 给每部影片都定了分级。这个查询保留分级为 `G` 的影片。

```sql
SELECT film_id, title, rating
FROM film
WHERE rating = 'G'
ORDER BY title
LIMIT 5;
```

```text
+---------+-------------------+--------+
| film_id | title             | rating |
+---------+-------------------+--------+
|       2 | ACE GOLDFINGER    | G      |
|       4 | AFFAIR PREJUDICE  | G      |
|       5 | AFRICAN EGG       | G      |
|      11 | ALAMO VIDEOTAPE   | G      |
|      22 | AMISTAD MIDSUMMER | G      |
+---------+-------------------+--------+
5 rows in set (0.00 sec)
```

字符串放在单引号里。数字不用。

### 2) 比较数字 {#2-compare-a-number}

```sql
SELECT title, length
FROM film
WHERE length > 180
ORDER BY length DESC, title
LIMIT 5;
```

```text
+----------------+--------+
| title          | length |
+----------------+--------+
| CHICAGO NORTH  |    185 |
| CONTROL ANTHEM |    185 |
| DARN FORRESTER |    185 |
| GANGS PRIDE    |    185 |
| HOME PITY      |    185 |
+----------------+--------+
5 rows in set (0.00 sec)
```

185 分钟是目录中最长的影片时长，有 10 部影片这么长，所以前 5 行全是并列的。再按 `title` 排序可以打破并列，这正是每次都返回同样 5 行的原因。

### 3) 按未选取的列筛选 {#3-filter-on-a-column-you-did-not-select}

条件测试的是行，不是结果。`rental_rate` 在这里完全不出现在输出中，筛选仍然有效。

```sql
SELECT title
FROM film
WHERE rental_rate = 4.99
ORDER BY title
LIMIT 5;
```

```text
+------------------+
| title            |
+------------------+
| ACE GOLDFINGER   |
| AIRPLANE SIERRA  |
| AIRPORT POLLOCK  |
| ALADDIN CALENDAR |
| ALI FOREVER      |
+------------------+
5 rows in set (0.00 sec)
```

### 4) 除一个值之外的所有行 {#4-everything-except-one-value}

```sql
SELECT title, rating
FROM film
WHERE rating <> 'G'
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACADEMY DINOSAUR | PG     |
| ADAPTATION HOLES | NC-17  |
| AGENT TRUMAN     | PG     |
| AIRPLANE SIERRA  | PG-13  |
| AIRPORT POLLOCK  | R      |
+------------------+--------+
5 rows in set (0.00 sec)
```

`<>` 是不等于。`!=` 含义相同，用哪个都可以。

## WHERE 看不到列别名 {#where-cannot-see-a-column-alias}

别名命名的是结果中的一列。`WHERE` 在结果存在之前运行，所以在那里写别名会失败。

```sql
SELECT title, rental_rate * 2 AS double_rate
FROM film
WHERE double_rate > 8
ORDER BY title;
```

```text
ERROR 1054 (42S22): Unknown column 'double_rate' in 'where clause'
```

改为在条件中再写一遍表达式。

```sql
SELECT title, rental_rate * 2 AS double_rate
FROM film
WHERE rental_rate * 2 > 8
ORDER BY title
LIMIT 5;
```

```text
+------------------+-------------+
| title            | double_rate |
+------------------+-------------+
| ACE GOLDFINGER   |        9.98 |
| AIRPLANE SIERRA  |        9.98 |
| AIRPORT POLLOCK  |        9.98 |
| ALADDIN CALENDAR |        9.98 |
| ALI FOREVER      |        9.98 |
+------------------+-------------+
5 rows in set (0.00 sec)
```

`ORDER BY` 是能使用别名的子句，因为它在结果构建完成之后运行。[ORDER BY](/zh/tutorial/order-by) 课程展示了这一点。

## 没有匹配不是错误 {#nothing-matching-is-not-an-error}

```sql
SELECT title FROM film WHERE rating = 'X';
```

```text
Empty set (0.00 sec)
```

`Empty set` 表示查询运行了，但没有任何行满足条件。服务器打印它来代替表格，所以也没有列标题。它是一个答案。

## 总结 {#summary}

- 用 `WHERE` 只保留满足条件的行。
- 字符串放在单引号里，数字不加引号。
- 预期服务器先筛选，再排序，然后应用 `LIMIT`。
- 测试表中的任何列，无论您是否选取了它。
- 在 `WHERE` 中重复表达式而不是写别名，写别名会得到 `ERROR 1054`。
