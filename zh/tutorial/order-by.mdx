表没有顺序。行以服务器觉得方便的任何顺序返回，而这个顺序在两次运行之间可能变化。`ORDER BY` 是唯一决定结果顺序的东西。

开始之前，请用 `mysql -u root -p sakila` 打开客户端。

## ORDER BY 的工作原理 {#how-order-by-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
ORDER BY SORT_COLUMN DIRECTION;
```

把 `SORT_COLUMN` 替换为用来排序的列。`DIRECTION` 是 `ASC`（最小的在前）或 `DESC`（最大的在前）。它是可选的，省略它表示 `ASC`。

## 示例 {#examples}

### 1) 按一列排序 {#1-sort-by-one-column}

```sql
SELECT title FROM film ORDER BY title;
```

```text
+-----------------------------+
| title                       |
+-----------------------------+
| ACADEMY DINOSAUR            |
| ACE GOLDFINGER              |
| ADAPTATION HOLES            |
| AFFAIR PREJUDICE            |
| AFRICAN EGG                 |
...
+-----------------------------+
1000 rows in set (0.01 sec)
```

### 2) 反向排序 {#2-sort-the-other-way}

```sql
SELECT title, rental_rate FROM film ORDER BY rental_rate DESC;
```

```text
+-----------------------------+-------------+
| title                       | rental_rate |
+-----------------------------+-------------+
| ACE GOLDFINGER              |        4.99 |
| AIRPLANE SIERRA             |        4.99 |
| AIRPORT POLLOCK             |        4.99 |
| ALADDIN CALENDAR            |        4.99 |
| ALI FOREVER                 |        4.99 |
...
+-----------------------------+-------------+
1000 rows in set (0.00 sec)
```

Sakila 给每部影片定价只用 3 种费率中的 1 种，而 336 部影片共用最高费率 4.99。这 336 行并列的行之间的顺序不由这个查询决定，所以它可能与您在这里看到的顺序不同。

### 3) 用第二列打破并列 {#3-break-the-tie-with-a-second-column}

按优先级顺序列出排序列，用逗号分隔。每一列有自己的方向。

```sql
SELECT title, rental_rate, length
FROM film
ORDER BY rental_rate DESC, length;
```

```text
+-----------------------------+-------------+--------+
| title                       | rental_rate | length |
+-----------------------------+-------------+--------+
| IRON MOON                   |        4.99 |     46 |
| HANOVER GALAXY              |        4.99 |     47 |
| ACE GOLDFINGER              |        4.99 |     48 |
| MIDSUMMER GROUNDHOG         |        4.99 |     48 |
| PELICAN COMFORTS            |        4.99 |     48 |
...
+-----------------------------+-------------+--------+
1000 rows in set (0.00 sec)
```

`rental_rate` 仍是第一排序列，降序。在每种费率内部，最短的影片排在前面。时长相同的影片仍然并列，所以完全确定的顺序需要足够多的列，让每一行都唯一。

### 4) 按别名排序 {#4-sort-by-an-alias}

`ORDER BY` 可以引用同一个查询中的列别名。

```sql
SELECT title AS film_title FROM film ORDER BY film_title;
```

```text
+-----------------------------+
| film_title                  |
+-----------------------------+
| ACADEMY DINOSAUR            |
| ACE GOLDFINGER              |
| ADAPTATION HOLES            |
...
+-----------------------------+
1000 rows in set (0.00 sec)
```

## 用反引号而不是单引号括起别名 {#quote-an-alias-with-backticks-not-single-quotes}

含有空格的别名必须加引号，而在这里 2 种加引号的方式不再一致。单引号构成的是字符串而不是名称，按一个固定的字符串排序等于什么都没排。

```sql
SELECT title, rental_rate AS 'Rate' FROM film ORDER BY 'Rate';
```

```text
+-----------------------------+------+
| title                       | Rate |
+-----------------------------+------+
| ACADEMY DINOSAUR            | 0.99 |
| ACE GOLDFINGER              | 4.99 |
| ADAPTATION HOLES            | 2.99 |
| AFFAIR PREJUDICE            | 2.99 |
| AFRICAN EGG                 | 2.99 |
...
+-----------------------------+------+
1000 rows in set (0.00 sec)
```

费率依次是 0.99、4.99、2.99，所以什么都没有排序。服务器把 `'Rate'` 读作那个 4 个字母的单词，并按同一个值对每一行排序。没有错误，没有警告，也没有排序。

反引号引用的是别名，排序就会发生：

```sql
SELECT title, rental_rate AS `Rate` FROM film ORDER BY `Rate`;
```

```text
+-----------------------------+------+
| title                       | Rate |
+-----------------------------+------+
| ACADEMY DINOSAUR            | 0.99 |
| ALAMO VIDEOTAPE             | 0.99 |
| ALASKA PHANTOM              | 0.99 |
| ALICE FANTASIA              | 0.99 |
| ALONE TRIP                  | 0.99 |
...
+-----------------------------+------+
1000 rows in set (0.00 sec)
```

显示的每一行都是 0.99，所以它们之间的顺序在这里同样不由查询决定。

## NULL 落在哪里 {#where-null-lands}

列可以保存 `NULL`，它记录的是那里根本没有值。它不是零，也不是空字符串。MySQL 在排序时把 `NULL` 视为小于每一个真实值，所以升序会把 NULL 放在最前面。`address` 的 603 行中，有 4 行没有 `address2`。

```sql
SELECT address_id, address2 FROM address ORDER BY address2;
```

```text
+------------+----------+
| address_id | address2 |
+------------+----------+
|          1 | NULL     |
|          2 | NULL     |
|          3 | NULL     |
|          4 | NULL     |
|        303 |          |
|        605 |          |
...
+------------+----------+
603 rows in set (0.00 sec)
```

4 个 NULL 行排在最前面。它们之后的行保存的是空字符串，这是一个真实的值，所以它在排序时大于 `NULL`、小于任何文本。这 4 个 NULL 行彼此并列，所以它们之间的顺序不由这个查询决定。

`DESC` 反转顺序，NULL 就到了底部。这是同一个结果反向排序后的末尾：

```sql
SELECT address_id, address2 FROM address ORDER BY address2 DESC;
```

```text
+------------+----------+
| address_id | address2 |
+------------+----------+
...
|        532 |          |
|          1 | NULL     |
|          2 | NULL     |
|          3 | NULL     |
|          4 | NULL     |
+------------+----------+
603 rows in set (0.00 sec)
```

## 小结 {#summary}

- 用 `ORDER BY` 决定结果的顺序，因为没有别的东西会决定它。
- 写 `DESC` 让最大的在前；`ASC` 是默认值。
- 按优先级顺序列出多个排序列，以打破并列。
- 按别名排序时用反引号括起它，因为单引号构成的是字符串。
- 升序排序时 `NULL` 在最前面，降序排序时在最后面。
