在 2 个账户之间转账需要 2 条语句，而两者之间的失败会让钱哪儿都不在。事务把语句组合在一起，使它们要么全部算数，要么全部不算。

这些示例使用来自 [INSERT](/zh/tutorial/insert) 的 `sakila_practice` 数据库。开始之前，请再次运行那里的设置代码块，然后用 `mysql -u root -p sakila_practice` 打开客户端。

## 事务的工作原理 {#how-a-transaction-works}

```sql
START TRANSACTION;
FIRST_STATEMENT;
SECOND_STATEMENT;
COMMIT;
```

把 `FIRST_STATEMENT` 和 `SECOND_STATEMENT` 替换为必须一起成功的语句。

`COMMIT` 让工作成为永久的，并对其他所有人可见。`ROLLBACK` 把它丢弃，并把行恢复原样。在您输入这 2 条之一之前，修改只属于您：另一个会话看到的仍是旧值。

事务之外的每条语句都自行提交，因为 `autocommit` 是打开的。

```sql
SELECT @@autocommit AS autocommit;
```

```text
+------------+
| autocommit |
+------------+
|          1 |
+------------+
1 row in set (0.00 sec)
```

这就是为什么前面的课程不需要 `COMMIT`：每条 `INSERT` 和 `UPDATE` 都是一个只有 1 条语句的事务。`START TRANSACTION` 暂停这种行为，直到您结束。

## 示例 {#examples}

### 1) 用 ROLLBACK 撤销工作 {#1-undo-the-work-with-rollback}

```sql
SELECT * FROM account;
```

```text
+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |  500.00 |
|          2 | Patricia Johnson |  250.00 |
+------------+------------------+---------+
2 rows in set (0.00 sec)
```

把 100 从 Mary 转给 Patricia，看一下结果，然后改变主意。

```sql
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE account_id = 1;
UPDATE account SET balance = balance + 100 WHERE account_id = 2;
SELECT * FROM account;
ROLLBACK;
```

```text
Query OK, 0 rows affected (0.00 sec)

Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0

Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0

+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |  400.00 |
|          2 | Patricia Johnson |  350.00 |
+------------+------------------+---------+
2 rows in set (0.00 sec)

Query OK, 0 rows affected (0.00 sec)
```

事务内的 `SELECT` 报告 400 和 350，因为会话能看到自己未提交的工作。随后 `ROLLBACK` 撤销了这两次更新。

```sql
SELECT * FROM account;
```

```text
+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |  500.00 |
|          2 | Patricia Johnson |  250.00 |
+------------+------------------+---------+
2 rows in set (0.00 sec)
```

这是 MySQL 仅有的撤销手段。一旦事务之外的语句运行了，旧值就没了。

### 2) 用 COMMIT 保留工作 {#2-keep-the-work-with-commit}

```sql
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE account_id = 1;
UPDATE account SET balance = balance + 100 WHERE account_id = 2;
COMMIT;
```

```text
Query OK, 0 rows affected (0.00 sec)

Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0

Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0

Query OK, 0 rows affected (0.00 sec)
```

```sql
SELECT * FROM account;
```

```text
+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |  400.00 |
|          2 | Patricia Johnson |  350.00 |
+------------+------------------+---------+
2 rows in set (0.00 sec)
```

这 2 次更新一起落地。没有任何其他会话曾同时看到 400 和 250，这正是这样写的全部理由。

## 有些语句不经询问就提交 {#some-statements-commit-without-being-asked}

改变数据库结构的语句无法回滚。更糟的是，运行这样一条语句会把当前打开的事务到那一刻为止所做的一切都提交。

```sql
START TRANSACTION;
UPDATE account SET balance = 0 WHERE account_id = 1;
CREATE TABLE note (id INT);
ROLLBACK;
```

```text
Query OK, 0 rows affected (0.00 sec)

Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0

Query OK, 0 rows affected (0.00 sec)

Query OK, 0 rows affected (0.00 sec)
```

每一行都报告成功，包括 `ROLLBACK`。

```sql
SELECT * FROM account;
```

```text
+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |    0.00 |
|          2 | Patricia Johnson |  350.00 |
+------------+------------------+---------+
2 rows in set (0.00 sec)
```

余额是 0。`CREATE TABLE` 在运行之前提交了那次更新，所以 `ROLLBACK` 已经没有东西可撤销，却仍然报告成功。`ALTER TABLE`、`DROP TABLE`、`TRUNCATE TABLE` 和 `RENAME TABLE` 的行为相同。请把这 5 条语句全部排除在保护数据的事务之外。

临时表是例外。`CREATE TEMPORARY TABLE` 和 `DROP TEMPORARY TABLE` 不提交任何东西，所以同样的测试中间换成临时表，余额仍停留在事务开始之前的值。

## 总结 {#summary}

- 写 `START TRANSACTION`，然后是语句，然后是 `COMMIT` 或 `ROLLBACK`。
- 预期事务之外的每条语句都自行提交，因为 `autocommit` 是打开的。
- 预期您的会话能看到自己未提交的修改，而其他会话看不到。
- 把 `ROLLBACK` 当作唯一的撤销手段。
- 把 `CREATE TABLE`、`ALTER TABLE`、`DROP TABLE`、`TRUNCATE TABLE` 和 `RENAME TABLE` 排除在事务之外，因为每一条都会提交事务。
- 预期 `CREATE` 和 `DROP` 的 `TEMPORARY` 形式不提交任何东西。
