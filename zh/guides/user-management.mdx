MySQL 的访问控制模型将身份验证（您是谁）与授权（您能做什么）分开。您先创建一个用户账户，然后单独为它授予权限。

## 创建用户 {#creating-users}

```sql
CREATE USER 'alice'@'localhost' IDENTIFIED BY 'Str0ng#Passw0rd';
```

`@'localhost'` 部分是主机限制——这个账户只能从本机连接。常见的主机模式：

| 主机 | 含义 |
|:-----|:--------|
| `'localhost'` | 套接字连接，以及服务器将环回地址解析为 `localhost` 时来自该地址的 TCP 连接 |
| `'127.0.0.1'` | 仅 TCP 环回 |
| `'%'` | 任何主机（网络访问） |
| `'192.168.1.%'` | 该子网中的任何主机 |
| `'app.example.com'` | 特定主机名 |

`'alice'@'localhost'` 和 `'alice'@'%'` 是两个不同的账户，尽管用户名相同。

## 授予权限 {#granting-privileges}

```sql
-- Read-only access to one database
GRANT SELECT ON myapp.* TO 'alice'@'localhost';

-- Full access to one database
GRANT ALL PRIVILEGES ON myapp.* TO 'alice'@'localhost';

-- Specific privileges on one table
GRANT SELECT, INSERT, UPDATE ON myapp.orders TO 'alice'@'localhost';

-- Global privilege (all databases)
GRANT PROCESS ON *.* TO 'alice'@'localhost';
```

权限对象使用 `database.table` 表示法：
- `*.*`——所有数据库、所有表（全局）
- `myapp.*`——`myapp` 数据库中的所有表
- `myapp.orders`——仅 `orders` 表

## 权限级别 {#privilege-levels}

| 级别 | 范围 | 示例 |
|:------|:------|:--------|
| 全局 | 所有数据库 | `GRANT RELOAD ON *.*` |
| 数据库 | 一个数据库 | `GRANT CREATE ON myapp.*` |
| 表 | 一个表 | `GRANT SELECT ON myapp.users` |
| 列 | 特定的列 | `GRANT SELECT (id, name) ON myapp.users` |
| 存储例程 | 过程或函数 | `GRANT EXECUTE ON PROCEDURE myapp.get_user` |

常见权限：

| 权限 | 允许的操作 |
|:----------|:---------------|
| `SELECT` | 读取行 |
| `INSERT` | 插入行 |
| `UPDATE` | 修改行 |
| `DELETE` | 删除行 |
| `CREATE` | 创建表和数据库 |
| `DROP` | 删除表和数据库 |
| `INDEX` | 创建和删除索引 |
| `ALTER` | 修改表结构 |
| `EXECUTE` | 运行存储过程和函数 |
| `PROCESS` | 查看所有正在运行的查询（`SHOW PROCESSLIST`） |
| `SUPER` | 覆盖限制；管理操作 |
| `ALL PRIVILEGES` | 指定范围内的所有权限 |

## 查看授权 {#viewing-grants}

```sql
-- Show grants for the current user
SHOW GRANTS;

-- Show grants for a specific user
SHOW GRANTS FOR 'alice'@'localhost';
```

## 撤销权限 {#revoking-privileges}

```sql
REVOKE INSERT ON myapp.* FROM 'alice'@'localhost';
REVOKE ALL PRIVILEGES ON myapp.* FROM 'alice'@'localhost';
```

撤销从未授予过的权限会返回 `ERROR 1141: There is no such grant defined for user`。用户保留在其他级别授予的任何权限——如果 `SELECT ON myapp.orders` 是单独授予的，撤销 `SELECT ON myapp.*` 不会移除它。

## 更改密码 {#changing-passwords}

```sql
ALTER USER 'alice'@'localhost' IDENTIFIED BY 'new_password';
```

强制在下次登录时更改密码：

```sql
ALTER USER 'alice'@'localhost' PASSWORD EXPIRE;
```

## 角色（MySQL 8.0+） {#roles-mysql-80}

角色是具名的权限集合。与其为每个用户授予单独的权限，不如授予一个角色。

```sql
-- Create a role
CREATE ROLE 'app_reader', 'app_writer';

-- Grant privileges to the role
GRANT SELECT ON myapp.* TO 'app_reader';
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp.* TO 'app_writer';

-- Grant the role to a user
GRANT 'app_reader' TO 'alice'@'localhost';
CREATE USER 'bob'@'%' IDENTIFIED BY 'Str0ng#Passw0rd';
GRANT 'app_writer' TO 'bob'@'%';
```

用户必须激活角色才能使用其权限（或将其设为默认角色）：

```sql
-- Activate in session
SET ROLE 'app_reader';

-- Set default role so it activates automatically on login
SET DEFAULT ROLE 'app_reader' TO 'alice'@'localhost';
```

## 删除用户 {#dropping-users}

```sql
DROP USER 'alice'@'localhost';
```

删除用户会自动撤销其所有权限，并将其从所有角色中移除。如果该用户当前已连接，会话会持续到结束为止。

## 最小权限最佳实践 {#least-privilege-best-practices}

只给每个账户它需要的权限：
- 应用程序只读副本：仅 `SELECT`
- 应用程序写入账户：`SELECT`、`INSERT`、`UPDATE`、`DELETE`
- 应用程序模式账户（迁移）：另加 `CREATE`、`ALTER`、`DROP`、`INDEX`
- DBA 账户：`*.*` 上的 `ALL PRIVILEGES`
- 绝不向应用程序账户授予 `SUPER` 或 `ALL`

尽可能严格地限制主机。`app.example.com` 上的应用程序应使用 `'appuser'@'app.example.com'`，而不是 `'appuser'@'%'`。

## 常见问题 {#frequently-asked-questions}

#### MySQL 会自动刷新授权吗？ {#does-mysql-flush-grants-automatically}

通过 `CREATE USER`、`GRANT`、`REVOKE` 和 `ALTER USER` 进行的所有更改都立即生效——不需要 `FLUSH PRIVILEGES`。只有当您用 `INSERT`/`UPDATE` 直接修改授权表时（您不应该这样做），才需要 `FLUSH PRIVILEGES`。

#### `localhost` 和 `127.0.0.1` 有什么区别？ {#whats-the-difference-between-localhost-and-127001}

连接到 `localhost` 的客户端使用 Unix 套接字，服务器把该连接的主机报告为 `localhost`。`127.0.0.1` 是 TCP 环回。来自 `127.0.0.1` 的 TCP 连接匹配 `'user'@'127.0.0.1'` 账户；当服务器把该地址解析为 `localhost` 时（这是默认行为），它也匹配 `'user'@'localhost'` 账户。

## 故障排除 {#troubleshooting}

| 问题 | 解决方案 |
|:--------|:---------|
| `ERROR 1045: Access denied for user` | 密码错误、主机错误或账户不存在——用 `SELECT user, host FROM mysql.user` 验证 |
| 用户可以连接但无法查询 | 用 `SHOW GRANTS FOR 'user'@'host'` 检查授权——权限级别必须与范围匹配（数据库与全局） |
| `GRANT` 失败并报 `ERROR 1044` | 当前用户缺少 `GRANT OPTION` 权限——以 root 或拥有 `GRANT OPTION` 的用户连接 |
| 用户已创建但无法从应用服务器登录 | `@'host'` 模式与应用服务器的主机名或 IP 不匹配——添加或更新账户的主机模式 |
| `DROP USER` 失败 | 验证确切的用户/主机组合：`SELECT user, host FROM mysql.user WHERE user = 'alice'` |
