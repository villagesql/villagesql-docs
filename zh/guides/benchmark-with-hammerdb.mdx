HammerDB 是由 [TPC-Council 在 GitHub 上](https://github.com/TPC-Council/HammerDB)托管的开源数据库基准测试工具。它把 VillageSQL 作为一种独立的数据库来支持，提供两种工作负载：TPROC-C 是源自 TPC-C 规范的 OLTP 工作负载，TPROC-H 是源自 TPC-H 的分析型工作负载。本指南使用 Docker 针对一台 VillageSQL 服务器运行 TPROC-C。

## 前提条件 {#prerequisites}

- Docker。VillageSQL 服务器和 HammerDB 都在容器中运行，所以您不需要在宿主机上安装其中任何一个。
- 大约 5 GB 的可用磁盘空间：两个镜像约占 2 GB，下面的测试写入的数据约占 3 GB。这些数据大部分是服务器的二进制日志，它随运行时长而增长。

## 启动 VillageSQL 服务器 {#start-a-villagesql-server}

创建一个 Docker 网络，让 HammerDB 容器可以通过名称访问服务器，然后在该网络上启动服务器：

```bash
docker network create hammerdb-net
docker run -d --name vsql-bench --network hammerdb-net \
  -e MYSQL_ROOT_PASSWORD=hammerdb villagesql/server:latest
```

服务器需要几秒钟来初始化。当下面的命令打印出版本号时，服务器就准备好了：

```bash
docker exec vsql-bench mysql -uroot -phammerdb -e "SELECT VERSION();"
```

要对您已经在运行的服务器进行基准测试，请跳过这一步。把下面脚本中的 `vsql_host`、`vsql_user` 和 `vsql_pass` 设置为该服务器的地址和凭据，并从 HammerDB 命令中去掉 `--network hammerdb-net`。

## 编写 HammerDB 脚本 {#write-the-hammerdb-scripts}

HammerDB 从它的命令行界面 `hammerdbcli` 运行，该界面读取一个包含设置和命令的脚本。为脚本创建一个文件夹：

```bash
mkdir hammerdb-scripts && cd hammerdb-scripts
```

把下面的内容保存为 `build.tcl`。它在名为 `tpcc` 的数据库中构建 TPROC-C schema：

```tcl
dbset db vsql
dbset bm TPROC-C
diset connection vsql_host vsql-bench
diset connection vsql_port 3306
diset connection vsql_ssl true
diset connection vsql_ssl_linux_capath ""
diset connection vsql_ssl_ca ""
diset connection vsql_ssl_cert ""
diset connection vsql_ssl_key ""
diset tpcc vsql_user root
diset tpcc vsql_pass hammerdb
diset tpcc vsql_dbase tpcc
diset tpcc vsql_count_ware 4
diset tpcc vsql_num_vu 4
buildschema
```

把下面的内容保存为 `run.tcl`。它运行一次计时测试：一分钟预热，然后两分钟测量，使用四个虚拟用户：

```tcl
dbset db vsql
dbset bm TPROC-C
diset connection vsql_host vsql-bench
diset connection vsql_port 3306
diset connection vsql_ssl true
diset connection vsql_ssl_linux_capath ""
diset connection vsql_ssl_ca ""
diset connection vsql_ssl_cert ""
diset connection vsql_ssl_key ""
diset tpcc vsql_user root
diset tpcc vsql_pass hammerdb
diset tpcc vsql_dbase tpcc
diset tpcc vsql_driver timed
diset tpcc vsql_rampup 1
diset tpcc vsql_duration 2
loadscript
vuset vu 4
vucreate
vurun
```

`dbset db vsql` 选择 VillageSQL。五行 `ssl` 设置在不使用证书文件的情况下开启 TLS。`root` 账户使用 `caching_sha2_password` 进行身份验证，这种验证方式通过 TCP 连接时需要加密连接，而 HammerDB 的默认证书文件夹 `/etc/mysql/certs` 在镜像中不存在。

## 构建 schema {#build-the-schema}

挂载脚本文件夹，从 HammerDB 的 VillageSQL 镜像运行 `build.tcl`：

```bash
docker run --rm --network hammerdb-net -v "$PWD":/scripts \
  tpcorg/hammerdb:v6.1.1-villagesql ./hammerdbcli auto /scripts/build.tcl
```

每个虚拟用户加载仓库数据，然后 HammerDB 创建存储过程并收集统计信息。构建以下面几行结束：

```text
Vuser 1:TPCC SCHEMA COMPLETE
Vuser 1:FINISHED SUCCESS
ALL VIRTUAL USERS COMPLETE
```

即使构建失败，HammerDB 也会打印 `ALL VIRTUAL USERS COMPLETE`，所以请在输出中查找 `FINISHED FAILED`。如果有这一行，请参阅[故障排除](#troubleshooting)。

## 运行测试 {#run-the-test}

```bash
docker run --rm --network hammerdb-net -v "$PWD":/scripts \
  tpcorg/hammerdb:v6.1.1-villagesql ./hammerdbcli auto /scripts/run.tcl
```

预热和计时运行结束后，HammerDB 打印结果：

```text
Vuser 1:TEST RESULT : System achieved <nopm> NOPM from <tpm> VillageSQL TPM
```

NOPM（每分钟新订单数）是 HammerDB 推荐的主要指标。HammerDB 从测试 schema 本身测量它，所以它不取决于某个特定数据库如何统计事务。

HammerDB 的结果不是 TPC-C 结果。请不要把它们与已发布的 TPC-C 结果进行比较，也不要把它们报告为 tpmC。

## 扩大测试规模 {#scale-the-test}

上面的测试用于检查环境是否能正常工作。要测量一台服务器的性能，请调高这些设置：

| 设置 | 在上面的测试中 | 它控制什么 |
|---|---|---|
| `vsql_count_ware` | 4 | 仓库的数量，它决定数据的大小 |
| `vsql_num_vu` | 4 | 并行加载 schema 的虚拟用户数量 |
| `vuset vu` | 4 | 运行测试的虚拟用户数量 |
| `vsql_rampup` / `vsql_duration` | 1 / 2 分钟 | 测量前预热的分钟数，以及测量的分钟数 |

[HammerDB 文档](https://www.hammerdb.com/docs/)涵盖每一项 TPROC-C 设置、TPROC-H 工作负载和 HammerDB 图形界面。

## 故障排除 {#troubleshooting}

| 错误 | 原因和解决方法 |
|---|---|
| `Authentication plugin 'caching_sha2_password' reported error: Authentication requires secure connection.` | 脚本在没有 TLS 的情况下连接。请添加上面脚本中的五行 `ssl` 设置。 |
| `Database tpcc exists but is not empty, specify a new or empty database name` | 之前的构建留下了 `tpcc` 数据库。请用 `docker exec vsql-bench mysql -uroot -phammerdb -e "DROP DATABASE tpcc;"` 删除它，或者把 `vsql_dbase` 设置为一个新名称。 |
| `SSL connection error: SSL_CTX_set_default_verify_paths failed` | `vsql_ssl` 为 `true`，但 HammerDB 正在查找证书文件。请把 `vsql_ssl_linux_capath`、`vsql_ssl_ca`、`vsql_ssl_cert` 和 `vsql_ssl_key` 设置为 `""`。 |

## 清理 {#clean-up}

删除服务器容器及其数据卷，并删除网络：

```bash
docker rm -fv vsql-bench
docker network rm hammerdb-net
```
