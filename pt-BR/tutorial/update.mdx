`UPDATE` altera linhas que já estão lá. O `WHERE` decide quais,
e ele é a única coisa entre 1 linha e a tabela inteira.

Estes exemplos usam o banco de dados `sakila_practice` da lição sobre
[INSERT](/pt-BR/tutorial/insert). Execute o bloco de configuração de lá novamente antes de começar,
depois abra o cliente com `mysql -u root -p sakila_practice`.

## Como UPDATE funciona {#how-update-works}

```sql
UPDATE TABLE_NAME
SET COLUMN_NAME = NEW_VALUE
WHERE CONDITION;
```

Substitua `TABLE_NAME` pela tabela, `COLUMN_NAME` pela coluna a alterar,
`NEW_VALUE` pelo que colocar nela, e `CONDITION` pelo teste que escolhe
as linhas.

O `WHERE` funciona exatamente como em um `SELECT`, e essa é a forma mais segura
de escrever um `UPDATE`: execute-o como um `SELECT` primeiro, olhe as linhas, depois mude
`SELECT ...` para `UPDATE ... SET ...` e deixe o `WHERE` como está.

## Exemplos {#examples}

### 1) Altere 1 linha {#1-change-1-row}

```sql
UPDATE member SET active = 0 WHERE member_id = 2;
```

```text
Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0
```

```sql
SELECT member_id, first_name, last_name, active FROM member;
```

```text
+-----------+------------+-----------+--------+
| member_id | first_name | last_name | active |
+-----------+------------+-----------+--------+
|         1 | Mary       | Smith     |      1 |
|         2 | Patricia   | Johnson   |      0 |
|         3 | Linda      | Williams  |      0 |
+-----------+------------+-----------+--------+
3 rows in set (0.00 sec)
```

### 2) Matched e Changed contam coisas diferentes {#2-matched-and-changed-count-different-things}

Execute a mesma instrução uma segunda vez.

```sql
UPDATE member SET active = 0 WHERE member_id = 2;
```

```text
Query OK, 0 rows affected (0.00 sec)
Rows matched: 1  Changed: 0  Warnings: 0
```

O `WHERE` ainda encontrou a linha, então `Rows matched` é 1. A linha já tinha
0, então nada foi gravado e `Changed` é 0. Leia os 2 números juntos:
`matched 0` significa que o `WHERE` não encontrou nada, que é um problema diferente de
`changed 0`, que significa que você pediu um valor que as linhas já têm.

### 3) Altere várias colunas de uma vez {#3-change-several-columns-at-once}

Separe as atribuições com vírgulas, não com `AND`.

```sql
UPDATE member
SET last_name = 'Smith-Davis', email = 'mary.smith-davis@example.com'
WHERE member_id = 1;
```

```text
Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0
```

```sql
SELECT member_id, first_name, last_name, email FROM member WHERE member_id = 1;
```

```text
+-----------+------------+-------------+------------------------------+
| member_id | first_name | last_name   | email                        |
+-----------+------------+-------------+------------------------------+
|         1 | Mary       | Smith-Davis | mary.smith-davis@example.com |
+-----------+------------+-------------+------------------------------+
1 row in set (0.00 sec)
```

## Um UPDATE encontra as mesmas restrições que um INSERT {#an-update-meets-the-same-constraints-an-insert-does}

Mover para uma coluna `UNIQUE` um valor que outra linha já tem falha da mesma
forma, e a linha mantém o que tinha.

```sql
UPDATE member SET email = 'patricia.johnson@example.com' WHERE member_id = 3;
```

```text
ERROR 1062 (23000): Duplicate entry 'patricia.johnson@example.com' for key 'member.uq_member_email'
```

## Sem um WHERE, ele altera todas as linhas {#without-a-where-it-changes-every-row}

Não há etapa de confirmação. A instrução é executada e todas as linhas da tabela
recebem o novo valor.

Uma configuração de sessão pode recusar essa forma por você. O modo de atualização segura rejeita um
`UPDATE` ou um `DELETE` que não testa uma coluna de chave no seu `WHERE` nem
carrega um `LIMIT`, e ele fica desligado a menos que você o peça.

```sql
SET SESSION sql_safe_updates = 1;
UPDATE member SET active = 1;
```

```text
Query OK, 0 rows affected (0.00 sec)

ERROR 1175 (HY000): You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.
```

Inicie o cliente com `mysql -u root -p --safe-updates sakila_practice` para ter
a proteção desde a primeira instrução. Essa flag faz mais do que definir essa única
variável: ela também limita um `SELECT` a 1.000 linhas por meio de `sql_select_limit` e
restringe um join por meio de `max_join_size`, então uma leitura de uma tabela grande volta
incompleta sem avisar. `ERROR 1175` significa que a proteção interrompeu você.

Desligue-a novamente quando a instrução realmente deve atingir todas as linhas.

```sql
SET SESSION sql_safe_updates = 0;
```

```text
Query OK, 0 rows affected (0.00 sec)
```

Com a proteção desligada, a instrução é executada.

```sql
UPDATE member SET active = 1;
```

```text
Query OK, 2 rows affected (0.00 sec)
Rows matched: 3  Changed: 2  Warnings: 0
```

```sql
SELECT member_id, first_name, active FROM member;
```

```text
+-----------+------------+--------+
| member_id | first_name | active |
+-----------+------------+--------+
|         1 | Mary       |      1 |
|         2 | Patricia   |      1 |
|         3 | Linda      |      1 |
+-----------+------------+--------+
3 rows in set (0.00 sec)
```

`Rows matched: 3  Changed: 2` porque 1 membro já estava ativo.

Uma atualização da tabela inteira às vezes é exatamente o certo. Aumentar todos os saldos em 5%
é 1 instrução, e o novo valor é calculado a partir do antigo.

```sql
UPDATE account SET balance = balance * 1.05;
```

```text
Query OK, 2 rows affected (0.00 sec)
Rows matched: 2  Changed: 2  Warnings: 0
```

```sql
SELECT * FROM account;
```

```text
+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |  525.00 |
|          2 | Patricia Johnson |  262.50 |
+------------+------------------+---------+
2 rows in set (0.00 sec)
```

`balance = balance * 1.05` lê o valor atual de cada linha, então cada linha recebe
sua própria resposta.

## Resumo {#summary}

- Escreva `UPDATE table SET column = value WHERE condition` para alterar linhas existentes.
- Execute o `WHERE` como um `SELECT` primeiro, depois mude apenas o início da instrução.
- Leia `Rows matched` e `Changed` como 2 fatos separados.
- Separe várias atribuições com vírgulas.
- Espere que um `UPDATE` encontre as mesmas regras `UNIQUE` e `NOT NULL` que um `INSERT`.
- Ligue o modo de atualização segura, e leia `ERROR 1175` como a proteção fazendo o seu trabalho.
