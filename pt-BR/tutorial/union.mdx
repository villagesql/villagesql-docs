Um join coloca tabelas lado a lado e alarga o resultado. `UNION` empilha resultados
um sobre o outro e o alonga. Recorra a ele quando 2 consultas produzem a
mesma forma de linha e você as quer em 1 lista.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como UNION funciona {#how-union-works}

```sql
SELECT COLUMN_LIST FROM FIRST_TABLE
UNION
SELECT COLUMN_LIST FROM SECOND_TABLE;
```

Substitua cada `COLUMN_LIST` pelas colunas que você quer, e `FIRST_TABLE` e
`SECOND_TABLE` pelas tabelas a ler.

As 2 consultas precisam retornar o mesmo número de colunas, e o servidor casa
essas colunas pela posição, e não pelo nome.

`UNION` remove linhas duplicadas. `UNION ALL` as mantém, e é mais rápido porque
não precisa comparar nada.

## Exemplos {#examples}

### 1) UNION remove duplicatas {#1-union-removes-duplicates}

As duas metades aqui são a mesma consulta, então toda linha da segunda é uma duplicata
de uma linha da primeira.

```sql
SELECT rating FROM film UNION SELECT rating FROM film;
```

```text
+--------+
| rating |
+--------+
| PG     |
| G      |
| NC-17  |
| PG-13  |
| R      |
+--------+
5 rows in set (0.00 sec)
```

5 linhas de 2.000. `UNION` desduplica o resultado combinado em 1 passagem, então
as repetições dentro de uma metade são tratadas da mesma forma que as repetições entre as metades. A resposta
é igual à de [SELECT DISTINCT](/pt-BR/tutorial/select-distinct) na mesma coluna.

### 2) UNION ALL as mantém {#2-union-all-keeps-them}

```sql
SELECT rating FROM film UNION ALL SELECT rating FROM film;
```

```text
+--------+
| rating |
+--------+
| PG     |
| G      |
| NC-17  |
...
+--------+
2000 rows in set (0.00 sec)
```

Todas as linhas das duas metades. Use `UNION ALL` sempre que souber que não há
duplicatas, ou quando as duplicatas são o objetivo.

### 3) Empilhe linhas de tabelas diferentes {#3-stack-rows-from-different-tables}

É para isto que `UNION` realmente serve: 2 tabelas que guardam o mesmo tipo de coisa.
Uma coluna literal diz de qual metade cada linha veio.

```sql
SELECT 'staff' AS source, first_name, last_name FROM staff
UNION ALL
SELECT 'actor', first_name, last_name FROM actor WHERE actor_id <= 3;
```

```text
+--------+------------+-----------+
| source | first_name | last_name |
+--------+------------+-----------+
| staff  | Mike       | Hillyer   |
| staff  | Jon        | Stephens  |
| actor  | PENELOPE   | GUINESS   |
| actor  | NICK       | WAHLBERG  |
| actor  | ED         | CHASE     |
+--------+------------+-----------+
5 rows in set (0.00 sec)
```

A segunda consulta não nomeia nenhum alias para seu literal. Ela não precisa de um, porque
os cabeçalhos das colunas vêm apenas da primeira consulta.

## UNION não promete uma ordem {#union-does-not-promise-an-order}

Nenhuma das metades tem garantia de chegar inteira, ou primeiro. O servidor retorna as
linhas na ordem em que seu plano as produziu, então um `UNION ALL` de 2 consultas
idênticas pode intercalar. `ORDER BY` no final é a única forma de fixar a ordem, o
mesmo que acontece com [LIMIT](/pt-BR/tutorial/limit) e [GROUP BY](/pt-BR/tutorial/group-by).

## As metades precisam ter o mesmo número de colunas {#the-halves-must-have-the-same-number-of-columns}

```sql
SELECT first_name FROM actor UNION SELECT first_name, last_name FROM actor;
```

```text
ERROR 1222 (21000): The used SELECT statements have a different number of columns
```

Os nomes das colunas não precisam ser iguais. Apenas a contagem é estrita, e ela é
verificada antes de qualquer coisa ser executada.

## ORDER BY se aplica ao resultado inteiro {#order-by-applies-to-the-whole-result}

Um `ORDER BY` no final ordena as linhas combinadas, e não a última consulta. Nomeie o
alias da primeira metade, que é como a coluna do resultado se chama.

```sql
SELECT first_name AS name FROM staff
UNION
SELECT last_name FROM staff
ORDER BY name;
```

```text
+----------+
| name     |
+----------+
| Hillyer  |
| Jon      |
| Mike     |
| Stephens |
+----------+
4 rows in set (0.00 sec)
```

Para ordenar ou limitar 1 metade sozinha, envolva essa metade em parênteses e coloque seu
`ORDER BY` e `LIMIT` dentro deles.

## Resumo {#summary}

- Use `UNION` para empilhar as linhas de 2 consultas em 1 resultado.
- Espere que `UNION` remova as duplicatas e que `UNION ALL` as mantenha.
- Prefira `UNION ALL` quando souber que não há nenhuma, porque ele faz menos trabalho.
- Dê às duas metades o mesmo número de colunas, ou receba `ERROR 1222`.
- Espere que os cabeçalhos venham da primeira consulta, e que um `ORDER BY` no final ordene tudo.
