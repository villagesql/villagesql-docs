`BETWEEN` testa se um valor cai dentro de um intervalo. É uma abreviação de um par de
comparações, e é a cláusula que as pessoas mais erram de forma sutil com datas.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como BETWEEN funciona {#how-between-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME BETWEEN LOW_BOUND AND HIGH_BOUND;
```

Substitua `LOW_BOUND` e `HIGH_BOUND` pelas 2 extremidades do intervalo.

`x BETWEEN a AND b` significa `x >= a AND x <= b`. O intervalo inclui os dois limites,
e você escreve o limite inferior primeiro.

## Exemplos {#examples}

### 1) Um intervalo de números {#1-a-range-of-numbers}

```sql
SELECT title, length
FROM film
WHERE length BETWEEN 60 AND 70
ORDER BY length, title
LIMIT 5;
```

```text
+-----------------------+--------+
| title                 | length |
+-----------------------+--------+
| BUBBLE GROSSE         |     60 |
| JERSEY SASSY          |     60 |
| MOCKINGBIRD HOLLYWOOD |     60 |
| PHANTOM GLORY         |     60 |
| PITY BOUND            |     60 |
+-----------------------+--------+
5 rows in set (0.00 sec)
```

Filmes de exatamente 60 minutos estão no resultado, o que mostra que o limite inferior
conta como correspondência.

### 2) A mesma coisa escrita por extenso {#2-the-same-thing-written-out}

```sql
SELECT title, length
FROM film
WHERE length >= 60 AND length <= 70
ORDER BY length, title
LIMIT 5;
```

```text
+-----------------------+--------+
| title                 | length |
+-----------------------+--------+
| BUBBLE GROSSE         |     60 |
| JERSEY SASSY          |     60 |
| MOCKINGBIRD HOLLYWOOD |     60 |
| PHANTOM GLORY         |     60 |
| PITY BOUND            |     60 |
+-----------------------+--------+
5 rows in set (0.00 sec)
```

Linhas idênticas. `BETWEEN` poupa você de nomear a coluna duas vezes e nada mais.

### 3) Fora do intervalo {#3-outside-the-range}

```sql
SELECT title, length
FROM film
WHERE length NOT BETWEEN 60 AND 70
ORDER BY length, title
LIMIT 5;
```

```text
+---------------------+--------+
| title               | length |
+---------------------+--------+
| ALIEN CENTER        |     46 |
| IRON MOON           |     46 |
| KWAI HOMEWARD       |     46 |
| LABYRINTH LEAGUE    |     46 |
| RIDGEMONT SUBMARINE |     46 |
+---------------------+--------+
5 rows in set (0.01 sec)
```

`NOT BETWEEN` mantém as linhas abaixo do limite inferior e acima do limite superior. 46
minutos é o filme mais curto do catálogo.

## O limite inferior tem de vir primeiro {#the-low-bound-has-to-come-first}

`BETWEEN` não ordena os limites para você. Dê a ele um valor alto primeiro e ele
pede números que sejam ao mesmo tempo pelo menos 70 e no máximo 60, o que nenhum número é.

```sql
SELECT title, length
FROM film
WHERE length BETWEEN 70 AND 60
ORDER BY length, title;
```

```text
Empty set (0.00 sec)
```

Nenhum erro e nenhum aviso. Um resultado vazio de um intervalo que você esperava que correspondesse
merece primeiro uma verificação de limites trocados.

## BETWEEN com datas para à meia-noite {#between-on-dates-stops-at-midnight}

Este é o que custa tempo real às pessoas, e começa com o tipo da
coluna.

```sql
SHOW COLUMNS FROM payment LIKE 'payment_date';
```

```text
+--------------+----------+------+-----+---------+-------+
| Field        | Type     | Null | Key | Default | Extra |
+--------------+----------+------+-----+---------+-------+
| payment_date | datetime | NO   |     | NULL    |       |
+--------------+----------+------+-----+---------+-------+
1 row in set (0.00 sec)
```

`payment_date` é um `datetime`, então todo valor carrega uma hora do dia. Uma data
escrita sem hora significa meia-noite no início daquele dia.

```sql
SELECT payment_id
FROM payment
WHERE payment_date BETWEEN '2005-05-25' AND '2005-05-26'
ORDER BY payment_id;
```

```text
+------------+
| payment_id |
+------------+
|          1 |
|        146 |
|        174 |
...
+------------+
137 rows in set (0.01 sec)
```

Isso se lê como "o dia 25 e o dia 26" e retorna 137 linhas. Pedir os mesmos
2 dias como um intervalo semiaberto retorna 311.

```sql
SELECT payment_id
FROM payment
WHERE payment_date >= '2005-05-25' AND payment_date < '2005-05-27'
ORDER BY payment_id;
```

```text
+------------+
| payment_id |
+------------+
|          1 |
|        146 |
|        174 |
...
+------------+
311 rows in set (0.00 sec)
```

O limite superior `'2005-05-26'` virou `2005-05-26 00:00:00`. Todo pagamento recebido
durante o dia 26 é posterior a esse instante, então `BETWEEN` excluiu todos eles.
As 137 linhas são o dia 25 sozinho, e elas teriam incluído um pagamento
que caísse exatamente na batida da meia-noite se houvesse um.

Escreva um intervalo de datas como `>= início AND < o dia seguinte ao fim`. Essa forma não exige
pensar se a coluna carrega uma hora, e continua correta se a
coluna ganhar uma mais tarde.

## Resumo {#summary}

- Use `BETWEEN` para um intervalo, e espere que ele inclua os dois limites.
- Escreva o limite inferior primeiro, porque um intervalo invertido não corresponde a nada e não diz nada.
- Leia `x BETWEEN a AND b` como `x >= a AND x <= b`.
- Use `>= start AND < day_after_end` para datas em vez de `BETWEEN`.
