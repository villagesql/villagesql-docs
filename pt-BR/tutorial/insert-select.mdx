`VALUES` fornece linhas que você digita. Um `SELECT` no lugar dele fornece linhas que o
servidor calcula, então um resumo que você pode consultar é um resumo que você pode armazenar. É
assim que uma tabela de relatório é preenchida e como linhas passam de uma tabela para outra.

Estes exemplos usam o banco de dados `sakila_practice` de
[INSERT](/pt-BR/tutorial/insert). Rode o bloco de configuração de lá de novo antes de começar,
depois abra o cliente com `mysql -u root -p sakila_practice`.

## Como o INSERT SELECT funciona {#how-insert-select-works}

```sql
INSERT INTO TARGET_TABLE (COLUMN_LIST)
SELECT SOURCE_COLUMNS FROM SOURCE_TABLE;
```

Substitua `TARGET_TABLE` pela tabela que está sendo gravada, `COLUMN_LIST` pelas
colunas dela, `SOURCE_COLUMNS` pelo que a consulta retorna, e `SOURCE_TABLE` pela
tabela que está sendo lida.

Não existe a palavra-chave `VALUES`. As colunas se emparelham por posição, então a primeira
coisa que o `SELECT` retorna vai para a primeira coluna nomeada, sejam quais forem os nomes das 2.
Cada linha que a consulta retorna vira uma linha na tabela de destino.

## Exemplos {#examples}

### 1) Armazenar um resumo {#1-store-a-summary}

`rating_count` está vazia e `sakila.film` tem a resposta. Nomear uma tabela como
`database.table` a lê de outro banco de dados, então 1 instrução pode cruzar
entre os 2.

```sql
INSERT INTO rating_count (rating, films)
SELECT rating, COUNT(*) FROM sakila.film GROUP BY rating;
```

```text
Query OK, 5 rows affected (0.00 sec)
Records: 5  Duplicates: 0  Warnings: 0
```

O `GROUP BY` produziu 5 linhas e 5 linhas foram gravadas.

```sql
SELECT * FROM rating_count ORDER BY films DESC;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
| R      |   195 |
| PG     |   194 |
| G      |   178 |
+--------+-------+
5 rows in set (0.00 sec)
```

Agora elas são linhas comuns, e são um instantâneo. Nada as atualiza
quando `film` muda.

### 2) Construir valores no caminho {#2-build-values-on-the-way-in}

O `SELECT` pode calcular qualquer coisa, então as linhas que entram não precisam existir
em lugar nenhum com aquela forma.

```sql
INSERT INTO member (first_name, last_name, email, joined)
SELECT first_name, last_name, CONCAT(LOWER(first_name), '.', LOWER(last_name), '@example.net'), '2026-05-01'
FROM sakila.staff;
```

```text
Query OK, 2 rows affected (0.01 sec)
Records: 2  Duplicates: 0  Warnings: 0
```

```sql
SELECT member_id, first_name, last_name, email FROM member WHERE joined = '2026-05-01';
```

```text
+-----------+------------+-----------+--------------------------+
| member_id | first_name | last_name | email                    |
+-----------+------------+-----------+--------------------------+
|         4 | Mike       | Hillyer   | mike.hillyer@example.net |
|         5 | Jon        | Stephens  | jon.stephens@example.net |
+-----------+------------+-----------+--------------------------+
2 rows in set (0.00 sec)
```

A coluna de endereço foi feita por `CONCAT` e a data é uma constante repetida em
cada linha.

## ERROR 1136 significa que as 2 listas têm comprimentos diferentes {#error-1136-means-the-2-lists-are-different-lengths}

```sql
INSERT INTO rating_count (rating, films)
SELECT rating FROM sakila.film GROUP BY rating;
```

```text
ERROR 1136 (21S01): Column count doesn't match value count at row 1
```

2 colunas nomeadas, 1 retornada. As 2 listas sempre diferem em comprimento quando este
erro aparece, então conte-as. Nada verifica os nomes ou os significados, então um `SELECT`
que retorna o número certo das colunas erradas é aceito e grava
bobagem. Rode o `SELECT` sozinho primeiro e leia o que volta.

## Uma segunda execução encontra as chaves da tabela {#a-second-run-meets-the-tables-keys}

Cada linha que a consulta retorna é oferecida à tabela, e as regras da tabela
continuam valendo.

```sql
INSERT INTO rating_count (rating, films)
SELECT rating, COUNT(*) FROM sakila.film WHERE rating = 'G' GROUP BY rating;
```

```text
ERROR 1062 (23000): Duplicate entry 'G' for key 'rating_count.PRIMARY'
```

`rating` é a chave primária e `G` já está armazenado. Um resumo que você quer
atualizar em vez de construir uma vez precisa de [upsert](/pt-BR/tutorial/upsert), que atualiza
a linha armazenada em vez de falhar.

## Resumo {#summary}

- Coloque um `SELECT` onde `VALUES` iria, e não escreva a palavra-chave `VALUES`.
- Espere que as colunas se emparelhem por posição, nunca por nome.
- Leia `ERROR 1136` como 2 listas de comprimentos diferentes.
- Nomeie uma tabela como `database.table` para ler de outro banco de dados na mesma instrução.
- Espere que uma segunda execução esbarre nas chaves da tabela de destino, como qualquer outro insert.
