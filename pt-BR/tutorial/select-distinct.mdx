`SELECT DISTINCT` retorna cada linha do resultado uma vez, não importa quantas vezes ela ocorra.
Ele responde a perguntas do tipo "quais valores aparecem nesta coluna", que é
muitas vezes a primeira coisa que você quer saber sobre uma tabela que ainda não conhece.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como DISTINCT funciona {#how-distinct-works}

```sql
SELECT DISTINCT COLUMN_LIST
FROM TABLE_NAME;
```

Substitua `COLUMN_LIST` pelas colunas que você quer e `TABLE_NAME` pela
tabela. `DISTINCT` fica imediatamente depois de `SELECT` e se aplica à lista de seleção
inteira, não à coluna ao lado dele. Esse único fato explica a maioria das
surpresas com ele.

## Exemplos {#examples}

### 1) Os valores de uma coluna {#1-the-values-in-one-column}

O Sakila classifica todos os filmes. Isto pergunta quais classificações existem.

```sql
SELECT DISTINCT rating FROM film;
```

```text
+--------+
| rating |
+--------+
| PG     |
| G      |
| NC-17  |
| PG-13  |
| R      |
+--------+
5 rows in set (0.00 sec)
```

5 classificações em 1.000 filmes. Elas chegam sem nenhuma ordem útil, porque `DISTINCT`
remove duplicatas e não diz nada sobre ordem. Adicione `ORDER BY` quando quiser
uma.

### 2) Outra coluna {#2-another-column}

```sql
SELECT DISTINCT rental_rate FROM film;
```

```text
+-------------+
| rental_rate |
+-------------+
|        0.99 |
|        4.99 |
|        2.99 |
+-------------+
3 rows in set (0.00 sec)
```

Todo filme do catálogo tem 1 de 3 taxas de aluguel.

### 3) Combinações distintas {#3-distinct-combinations}

Nomeie 2 colunas e você obtém cada par distinto, e não os valores de cada coluna
separadamente.

```sql
SELECT DISTINCT rating, rental_rate
FROM film
ORDER BY rating, rental_rate;
```

```text
+--------+-------------+
| rating | rental_rate |
+--------+-------------+
| G      |        0.99 |
| G      |        2.99 |
| G      |        4.99 |
| PG     |        0.99 |
| PG     |        2.99 |
| PG     |        4.99 |
| PG-13  |        0.99 |
| PG-13  |        2.99 |
| PG-13  |        4.99 |
| R      |        0.99 |
| R      |        2.99 |
| R      |        4.99 |
| NC-17  |        0.99 |
| NC-17  |        2.99 |
| NC-17  |        4.99 |
+--------+-------------+
15 rows in set (0.00 sec)
```

5 classificações vezes 3 taxas dá 15, e todas as combinações por acaso ocorrem.

## Por que as classificações ordenadas não estão em ordem alfabética {#why-the-sorted-ratings-are-not-alphabetical}

Esse resultado está ordenado por `rating`, e mesmo assim a sequência é `G`, `PG`, `PG-13`, `R`,
`NC-17`. Em ordem alfabética, `NC-17` viria em segundo lugar. O `ORDER BY` funcionou, e a
razão é o tipo da coluna:

`SHOW COLUMNS` lista as colunas de uma tabela, e o padrão depois de `LIKE` restringe
a lista a 1 nome.

```sql
SHOW COLUMNS FROM film LIKE 'rating';
```

```text
+--------+------------------------------------+------+-----+---------+-------+
| Field  | Type                               | Null | Key | Default | Extra |
+--------+------------------------------------+------+-----+---------+-------+
| rating | enum('G','PG','PG-13','R','NC-17') | YES  |     | G       |       |
+--------+------------------------------------+------+-----+---------+-------+
1 row in set (0.00 sec)
```

`rating` é um `ENUM`, um tipo de coluna que aceita apenas uma lista fixa de valores.
O MySQL armazena cada valor como a posição dele nessa lista e ordena pela posição,
então um `ENUM` é ordenado na ordem em que os valores foram declarados. Aqui, a ordem
declarada vai da classificação menos restritiva à mais restritiva.

## Adicionar uma coluna pode desfazer o efeito {#adding-a-column-can-undo-it}

Como `DISTINCT` olha para a linha inteira, adicionar uma coluna que é quase
única remove quase nada.

```sql
SELECT DISTINCT rating, title FROM film;
```

```text
+--------+-----------------------------+
| rating | title                       |
+--------+-----------------------------+
| PG     | ACADEMY DINOSAUR            |
| G      | ACE GOLDFINGER              |
| NC-17  | ADAPTATION HOLES            |
...
+--------+-----------------------------+
1000 rows in set (0.00 sec)
```

Todas as 1.000 linhas voltam. Cada título é diferente, então cada par `rating` e `title`
é diferente, e nada é duplicata. `DISTINCT` não consegue dar a você 5
linhas aqui, porque você pediu uma coluna que tem 1.000 valores diferentes
nela. Reduzir muitas linhas a 1 por classificação é uma operação diferente, e
[GROUP BY](/pt-BR/tutorial/group-by) é a cláusula para isso.

## Resumo {#summary}

- Use `SELECT DISTINCT` para retornar cada linha do resultado uma vez.
- Espere que ele se aplique a todas as colunas da lista de seleção de uma só vez.
- Adicione `ORDER BY` quando quiser os valores distintos ordenados.
- Espere que uma coluna `ENUM` seja ordenada pela ordem declarada, e não em ordem alfabética.
