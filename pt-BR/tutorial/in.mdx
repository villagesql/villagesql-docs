`IN` testa uma coluna contra vários valores de uma vez. Ele diz o que uma cadeia de
`OR` diz, em uma cláusula, e é a cláusula que a maioria das pessoas usa quando um
filtro passa de 2 valores.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como o IN funciona {#how-in-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME IN (FIRST_VALUE, SECOND_VALUE);
```

Substitua `COLUMN_NAME` pela coluna a testar, e `FIRST_VALUE` e
`SECOND_VALUE` pelos valores a aceitar.

A condição é verdadeira quando a coluna é igual a qualquer valor entre os parênteses. Separe
os valores com vírgulas, e use quantos precisar.

`x IN (a, b)` significa o mesmo que `x = a OR x = b`. Escreva o que ficar mais legível,
e espere que `IN` fique mais legível a partir de 2 valores.

## Exemplos {#examples}

### 1) Corresponder a qualquer um de vários valores {#1-match-any-of-several-values}

```sql
SELECT title, rating
FROM film
WHERE rating IN ('G', 'PG')
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACADEMY DINOSAUR | PG     |
| ACE GOLDFINGER   | G      |
| AFFAIR PREJUDICE | G      |
| AFRICAN EGG      | G      |
| AGENT TRUMAN     | PG     |
+------------------+--------+
5 rows in set (0.00 sec)
```

### 2) Não corresponder a nenhum deles {#2-match-none-of-them}

```sql
SELECT title, rating
FROM film
WHERE rating NOT IN ('G', 'PG')
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ADAPTATION HOLES | NC-17  |
| AIRPLANE SIERRA  | PG-13  |
| AIRPORT POLLOCK  | R      |
| ALABAMA DEVIL    | PG-13  |
| ALADDIN CALENDAR | NC-17  |
+------------------+--------+
5 rows in set (0.00 sec)
```

### 3) Uma lista de números {#3-a-list-of-numbers}

```sql
SELECT first_name, last_name
FROM actor
WHERE actor_id IN (1, 5, 10)
ORDER BY actor_id;
```

```text
+------------+--------------+
| first_name | last_name    |
+------------+--------------+
| PENELOPE   | GUINESS      |
| JOHNNY     | LOLLOBRIGIDA |
| CHRISTIAN  | GABLE        |
+------------+--------------+
3 rows in set (0.00 sec)
```

Números não levam aspas. As linhas voltam na ordem de `actor_id` porque o
`ORDER BY` pediu isso, não porque a lista está nessa ordem.

### 4) Uma lista que o servidor calcula sozinho {#4-a-list-the-server-works-out-for-itself}

Os parênteses podem conter uma consulta em vez de uma lista. `film_actor` é a tabela que
emparelha cada filme com cada ator que aparece nele, então isto pede os filmes em que o ator 1
aparece, sem que você saiba nenhum id de filme.

```sql
SELECT title
FROM film
WHERE film_id IN (SELECT film_id FROM film_actor WHERE actor_id = 1)
ORDER BY title
LIMIT 5;
```

```text
+-----------------------+
| title                 |
+-----------------------+
| ACADEMY DINOSAUR      |
| ANACONDA CONFESSIONS  |
| ANGELS LIFE           |
| BULWORTH COMMANDMENTS |
| CHEAPER CLYDE         |
+-----------------------+
5 rows in set (0.00 sec)
```

Uma consulta escrita dentro de outra consulta é uma subconsulta. Uma seção posterior as cobre
de forma completa. Vale a pena conhecer uma aqui porque uma lista `IN` é onde a maioria das pessoas
escreve a primeira.

## Um NULL na lista quebra o NOT IN {#a-null-in-the-list-breaks-not-in}

`IN` e `NOT IN` não tratam um NULL na lista do mesmo jeito, e nenhum dos dois
avisa você.

Com `IN`, um NULL na lista é inofensivo. Uma linha que corresponde a um valor real é
mantida mesmo assim.

```sql
SELECT title, rating
FROM film
WHERE rating IN ('G', NULL)
ORDER BY title
LIMIT 3;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACE GOLDFINGER   | G      |
| AFFAIR PREJUDICE | G      |
| AFRICAN EGG      | G      |
+------------------+--------+
3 rows in set (0.00 sec)
```

Com `NOT IN`, a mesma lista não retorna nada.

```sql
SELECT title, rating
FROM film
WHERE rating NOT IN ('G', NULL)
ORDER BY title
LIMIT 3;
```

```text
Empty set (0.01 sec)
```

Todo filme tem uma classificação, e 822 deles não são classificados como `G`, então um resultado vazio
é uma surpresa. A razão é que `NOT IN` pergunta se a coluna difere de
cada valor da lista, e nada pode ser mostrado como diferente de NULL.
Comparar qualquer coisa com NULL dá NULL em vez de verdadeiro ou falso, então a
condição inteira nunca é verdadeira e nenhuma linha sobrevive.

Isso importa mais quando a lista é uma subconsulta, porque uma subconsulta que você não
escreveu à mão pode retornar um NULL que você não esperava. Adicione
`WHERE COLUMN_NAME IS NOT NULL` dentro da subconsulta quando isso for possível. A
lição sobre [IS NULL](/pt-BR/tutorial/is-null) cobre como NULL se compara.

## Resumo {#summary}

- Use `IN` para testar uma coluna contra uma lista de valores em uma cláusula.
- Leia `x IN (a, b)` como `x = a OR x = b`.
- Coloque strings da lista entre aspas e deixe os números sem aspas.
- Coloque uma subconsulta entre os parênteses quando a lista for ela mesma uma resposta.
- Mantenha NULL fora de uma lista `NOT IN`, porque ela não retorna nenhuma linha.
