Uma expressão de tabela comum dá um nome a uma consulta, no topo, antes da consulta
que a usa. O resultado é o mesmo de uma [tabela
derivada](/pt-BR/tutorial/derived-tables), e se lê na ordem em que você pensa: defina
as partes, depois use-as.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como uma CTE funciona {#how-a-cte-works}

```sql
WITH CTE_NAME AS (
  SELECT COLUMN_LIST FROM TABLE_NAME
)
SELECT COLUMN_LIST FROM CTE_NAME;
```

Substitua `CTE_NAME` por um nome para o resultado intermediário, `COLUMN_LIST` pelas
colunas que você quer, e `TABLE_NAME` pela tabela que a consulta interna lê. A consulta principal então lê `CTE_NAME` como se fosse
uma tabela.

Uma CTE dura 1 instrução. Ela não é armazenada, e a próxima consulta não sabe nada
sobre ela.

## Exemplos {#examples}

### 1) Um passo com nome {#1-one-named-step}

```sql
WITH counts AS (
  SELECT rating, COUNT(*) AS films FROM film GROUP BY rating
)
SELECT rating, films FROM counts WHERE films > 200 ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
+--------+-------+
2 rows in set (0.00 sec)
```

As mesmas linhas que a lição de tabela derivada retorna, com a contagem tirada de dentro do
`FROM` e recebendo um nome.

### 2) Vários passos, cada um construído sobre o anterior {#2-several-steps-each-built-on-the-last}

Separe as CTEs com vírgula, e uma posterior pode ler uma anterior. É isso
que uma tabela derivada não consegue fazer sem se repetir.

```sql
WITH counts AS (
  SELECT rating, COUNT(*) AS films FROM film GROUP BY rating
),
busiest AS (
  SELECT MAX(films) AS most FROM counts
)
SELECT c.rating, c.films
FROM counts AS c
INNER JOIN busiest AS b ON c.films = b.most;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
+--------+-------+
1 row in set (0.00 sec)
```

`busiest` lê `counts`, e a consulta principal lê as duas. Escrita com tabelas
derivadas, a consulta de contagem apareceria duas vezes.

## O que uma CTE dá a você que uma tabela derivada não dá {#what-a-cte-gives-you-that-a-derived-table-does-not}

As linhas são as mesmas de qualquer forma. 2 coisas diferem:

- Uma CTE carrega um nome, então uma consulta de 3 estágios se lê de cima para baixo. `counts` e
  `busiest` dizem ao próximo leitor para que serve cada parte.
- Uma CTE pode ser referenciada pelo nome mais de uma vez na mesma instrução. Uma tabela derivada tem
  de ser escrita de novo.

Se o otimizador trata as 2 formas de modo diferente é uma questão separada,
e [Quando uma CTE do MySQL supera uma tabela derivada](/pt-BR/guides/ctes-in-mysql) mede
isso.

## Resumo {#summary}

- Use `WITH name AS (...)` para dar nome a uma consulta antes da consulta que a lê.
- Separe várias CTEs com vírgulas, e deixe uma posterior ler uma anterior.
- Espere que uma CTE dure apenas 1 instrução.
- Prefira uma CTE quando uma consulta tem vários estágios ou repete uma subconsulta.
