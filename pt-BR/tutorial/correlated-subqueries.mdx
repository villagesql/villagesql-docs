Uma subconsulta comum executa uma vez e devolve uma resposta. Uma subconsulta correlacionada
nomeia uma coluna da consulta externa, então ela tem uma resposta diferente para cada
linha externa e o servidor tem de executá-la de novo para cada uma.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como uma subconsulta correlacionada funciona {#how-a-correlated-subquery-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME AS OUTER_ALIAS
WHERE COLUMN_NAME > (
  SELECT AGGREGATE_FUNCTION(COLUMN_NAME)
  FROM TABLE_NAME AS INNER_ALIAS
  WHERE INNER_ALIAS.COLUMN_NAME = OUTER_ALIAS.COLUMN_NAME
);
```

Substitua `COLUMN_LIST` pelas colunas que você quer, `TABLE_NAME` pela tabela,
`COLUMN_NAME` pelas colunas que estão sendo comparadas, `AGGREGATE_FUNCTION` pela
função que a consulta interna executa, e `OUTER_ALIAS` e `INNER_ALIAS` por 2 nomes
para as tabelas envolvidas.
Os 2 aliases são o que faz funcionar: a consulta interna menciona a externa pelo
nome, e essa é a correlação.

Leia-a como uma pergunta feita uma vez por linha externa, com os valores dessa linha
preenchidos.

## A pergunta que ela responde {#the-question-it-answers}

"Quais filmes são mais longos do que a média" precisa de 1 média. "Quais filmes são mais longos
do que a média **para sua classificação**" precisa de uma média diferente por linha, e é isso
que uma subconsulta correlacionada dá a você.

```sql
SELECT f.title, f.rating, f.length
FROM film AS f
WHERE f.length > (SELECT AVG(f2.length) FROM film AS f2 WHERE f2.rating = f.rating)
ORDER BY f.rating, f.title
LIMIT 5;
```

```text
+------------------+--------+--------+
| title            | rating | length |
+------------------+--------+--------+
| AFFAIR PREJUDICE | G      |    117 |
| AFRICAN EGG      | G      |    130 |
| ALAMO VIDEOTAPE  | G      |    126 |
...
+------------------+--------+--------+
5 rows in set (0.12 sec)
```

`f2.rating = f.rating` é a linha que importa. Ela amarra a consulta interna à
linha que está sendo testada, então um filme `G` é comparado com a média dos `G` e um filme
`R` com a média dos `R`.

Tire essa linha e a subconsulta calcula a média do catálogo inteiro, o mesmo
valor todas as vezes, e a consulta responde a uma pergunta diferente.

## Ela executa uma vez por linha {#it-runs-once-per-row}

Compare o tempo acima com as consultas da lição
[Subconsultas](/pt-BR/tutorial/subqueries), que retornam rápido demais para medir.
Esta leva um décimo de segundo em 1.000 linhas, e o seu número exato vai
diferir, porque o servidor avalia a consulta interna por linha externa em vez de
uma vez.

Essa é a troca inteira. Uma subconsulta correlacionada é a forma mais clara de escrever
"compare cada linha com seu próprio grupo", e o custo cresce com a tabela.

O MySQL reescreve algumas subconsultas correlacionadas como joins por conta própria, e há
outras formas que respondem à mesma pergunta em 1 passagem.
[Subconsultas vs JOINs no MySQL](/pt-BR/guides/subqueries-vs-joins) cobre as duas, e
a leitura do plano que diz a você qual delas você obteve.

## Resumo {#summary}

- Use uma subconsulta correlacionada para comparar cada linha com algo calculado a partir de seu próprio grupo.
- Dê aliases às duas tabelas, porque a consulta interna tem de nomear a externa.
- Espere que ela execute uma vez por linha externa.
- Reescreva-a como uma tabela derivada e um join quando a tabela é grande.
