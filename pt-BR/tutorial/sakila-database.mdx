Toda lição deste tutorial consulta o mesmo banco de dados, então você o carrega uma vez
e depois não pensa mais nele. Esse banco de dados é o Sakila, que modela uma rede
de 2 locadoras de DVD: os filmes que elas têm, os clientes que os alugam, os
funcionários que os atendem, e os pagamentos que resultam disso.

O Sakila serve bem para um tutorial por causa do seu tamanho. 1.000 filmes e 16.044 aluguéis são
o suficiente para que uma consulta retorne algo que valha a pena olhar, e há poucas
tabelas o bastante para que você consiga guardar a forma dele na cabeça.

## O que há nele {#what-is-in-it}

O Sakila tem 16 tabelas de dados. Estas são as contagens em uma cópia recém-carregada.

| Tabela | Linhas | O que ela contém |
|---|---|---|
| `actor` | 200 | Uma linha por ator |
| `address` | 603 | Endereços, compartilhados por clientes, funcionários e lojas |
| `category` | 16 | Gêneros de filme |
| `city` | 600 | Cidades, cada uma pertencente a um país |
| `country` | 109 | Países |
| `customer` | 599 | Uma linha por cliente de qualquer uma das lojas |
| `film` | 1000 | O catálogo de filmes, com taxa de aluguel e duração |
| `film_actor` | 5462 | Quais atores aparecem em quais filmes |
| `film_category` | 1000 | A qual categoria cada filme pertence |
| `film_text` | 1000 | Títulos e descrições de filmes, para busca de texto completo |
| `inventory` | 4581 | Cópias físicas de filmes, mantidas em uma loja |
| `language` | 6 | Idiomas em que um filme pode estar |
| `payment` | 16044 | Uma linha por pagamento recebido |
| `rental` | 16044 | Uma linha por aluguel, com as datas de saída e de devolução |
| `staff` | 2 | Os 2 funcionários |
| `store` | 2 | As 2 lojas |

Você pode verificar qualquer uma dessas contagens por conta própria depois que a próxima lição carregar
o Sakila. `COUNT(*)` informa quantas linhas uma tabela contém:

```sql
SELECT COUNT(*) FROM actor;
```

```text
+----------+
| COUNT(*) |
+----------+
|      200 |
+----------+
1 row in set (0.00 sec)
```

O Sakila também traz 7 views, que são consultas salvas, e não linhas armazenadas:
`actor_info`, `customer_list`, `film_list`, `nicer_but_slower_film_list`,
`sales_by_film_category`, `sales_by_store` e `staff_list`. Nenhuma lição as usa,
mas elas estão lá se você quiser ler como outra pessoa escreveu os mesmos
joins.

## As tabelas em que as lições se apoiam {#the-tables-the-lessons-lean-on}

Você não precisa de todas as 16. Um punhado delas carrega a maior parte dos exemplos.

- `film` é a tabela que faz o trabalho pesado. Ela tem texto, números, datas e uma chave estrangeira, então
  a maioria das ideias pode ser mostrada só com ela.
- `language` tem 6 linhas, então uma consulta a ela imprime um resultado completo que você pode
  conferir a olho.
- `customer`, `address` e `city` se encadeiam por meio de chaves estrangeiras, o que
  faz delas o conjunto natural para as lições sobre join.

## De onde ele vem {#where-it-comes-from}

A Oracle publica o Sakila como um banco de dados de exemplo. Seu arquivo de esquema e seu arquivo de dados
são cobertos pela licença New BSD, que permite o uso comercial desde que o
aviso acompanhe os arquivos. Esse aviso é reproduzido na íntegra no
[arquivo `NOTICE`](https://github.com/villagesql/villagesql-docs/blob/main/NOTICE)
do repositório que contém esta documentação.

A próxima lição baixa o Sakila da Oracle e o carrega no seu servidor.
