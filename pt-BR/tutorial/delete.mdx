`DELETE` remove linhas inteiras. Não há como desfazer fora de uma
[transação](/pt-BR/tutorial/transactions), então o hábito que vale a pena criar é escrever
o `WHERE` primeiro e olhar o que ele seleciona.

Estes exemplos usam o banco de dados `sakila_practice` de
[INSERT](/pt-BR/tutorial/insert). Execute o bloco de configuração de lá de novo antes de começar,
e então abra o cliente com `mysql -u root -p sakila_practice`.

## Como DELETE funciona {#how-delete-works}

```sql
DELETE FROM TABLE_NAME
WHERE CONDITION;
```

Substitua `TABLE_NAME` pela tabela e `CONDITION` pelo teste que escolhe
as linhas a remover.

Não há lista de colunas. Um `DELETE` leva a linha inteira, então esvaziar 1 coluna
é um [UPDATE](/pt-BR/tutorial/update) que a define como NULL.

## Exemplos {#examples}

### 1) Olhe primeiro, depois apague {#1-look-first-then-delete}

Escreva o `WHERE` como um `SELECT` e leia as linhas que você está prestes a perder.

```sql
SELECT member_id, first_name, last_name FROM member WHERE active = 0;
```

```text
+-----------+------------+-----------+
| member_id | first_name | last_name |
+-----------+------------+-----------+
|         3 | Linda      | Williams  |
+-----------+------------+-----------+
1 row in set (0.00 sec)
```

Uma linha, e é a que você queria. Agora mude o início da instrução
e deixe o `WHERE` intocado.

```sql
DELETE FROM member WHERE active = 0;
```

```text
Query OK, 1 row affected (0.00 sec)
```

```sql
SELECT member_id, first_name, last_name, active FROM member;
```

```text
+-----------+------------+-----------+--------+
| member_id | first_name | last_name | active |
+-----------+------------+-----------+--------+
|         1 | Mary       | Smith     |      1 |
|         2 | Patricia   | Johnson   |      1 |
+-----------+------------+-----------+--------+
2 rows in set (0.00 sec)
```

Um `DELETE` informa as linhas afetadas e nada mais. Um `UPDATE` imprime uma segunda
linha com `Rows matched` e `Changed`; um `DELETE` não tem equivalente.

### 2) Um WHERE que não corresponde a nada não é um erro {#2-a-where-that-matches-nothing-is-not-an-error}

```sql
DELETE FROM member WHERE member_id = 99;
```

```text
Query OK, 0 rows affected (0.00 sec)
```

Nada deu errado e nada aconteceu. `0 rows affected` depois de um delete que você
esperava que funcionasse significa que o `WHERE` está errado, e a instrução não vai
dizer isso a você.

## Sem um WHERE ele esvazia a tabela {#without-a-where-it-empties-the-table}

```sql
DELETE FROM member;
```

```text
Query OK, 2 rows affected (0.00 sec)
```

```sql
SELECT COUNT(*) AS members FROM member;
```

```text
+---------+
| members |
+---------+
|       0 |
+---------+
1 row in set (0.00 sec)
```

O modo de atualização segura recusa esta forma, exatamente como recusa um `UPDATE` sem
chave em seu `WHERE`. [UPDATE](/pt-BR/tutorial/update) mostra o `ERROR 1175` que ele
gera, e `mysql -u root -p --safe-updates sakila_practice` o ativa para
a sessão inteira.

## TRUNCATE esvazia de outra forma {#truncate-empties-it-differently}

A tabela está vazia, então insira uma linha e olhe o id dela.

```sql
INSERT INTO member (first_name, last_name, joined) VALUES ('Sam', 'Reed', '2026-06-01');
```

```text
Query OK, 1 row affected (0.00 sec)
```

```sql
SELECT member_id, first_name FROM member;
```

```text
+-----------+------------+
| member_id | first_name |
+-----------+------------+
|         4 | Sam        |
+-----------+------------+
1 row in set (0.00 sec)
```

O contador continuou de onde as linhas que o `DELETE` removeu pararam. `TRUNCATE TABLE`
não faz isso.

```sql
TRUNCATE TABLE member;
```

```text
Query OK, 0 rows affected (0.00 sec)
```

```sql
INSERT INTO member (first_name, last_name, joined) VALUES ('Sam', 'Reed', '2026-06-01');
```

```text
Query OK, 1 row affected (0.00 sec)
```

```sql
SELECT member_id, first_name FROM member;
```

```text
+-----------+------------+
| member_id | first_name |
+-----------+------------+
|         1 | Sam        |
+-----------+------------+
1 row in set (0.00 sec)
```

`TRUNCATE` descarta a tabela e constrói uma vazia, e é por isso que informa
`0 rows affected` não importa quantas linhas removeu, e por isso o contador recomeça.
Ele não aceita `WHERE`, não pode ser revertido, e não dispara nenhum trigger de
`DELETE`. Use `TRUNCATE` para zerar uma tabela, e `DELETE` para
todo o resto.

## Resumo {#summary}

- Escreva `DELETE FROM table WHERE condition`, e execute o `WHERE` como um `SELECT` primeiro.
- Espere uma contagem de linhas e nenhuma linha `Rows matched`.
- Leia `0 rows affected` como um `WHERE` que não encontrou nada, e não como uma falha.
- Deixe o `WHERE` de fora e a tabela é esvaziada, sem passo de confirmação.
- Use `TRUNCATE TABLE` para esvaziar e zerar uma tabela, sabendo que não pode ser desfeito.
