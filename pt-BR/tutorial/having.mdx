`WHERE` descarta linhas antes de elas serem agrupadas. `HAVING` descarta grupos
inteiros depois de eles serem construídos. Essa única frase é a lição inteira, e tudo
abaixo é consequência dela.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como o HAVING funciona {#how-having-works}

```sql
SELECT GROUPING_COLUMN, AGGREGATE_FUNCTION(COLUMN_NAME)
FROM TABLE_NAME
GROUP BY GROUPING_COLUMN
HAVING GROUP_CONDITION;
```

Substitua `GROUPING_COLUMN` pela coluna que define os grupos, `TABLE_NAME`
pela tabela, `AGGREGATE_FUNCTION(COLUMN_NAME)` pelo que calcular por
grupo, e `GROUP_CONDITION` por um teste que se aplica a um grupo inteiro, como
`COUNT(*) > 200`.

O servidor constrói cada grupo primeiro, depois mantém os grupos em que a condição
é verdadeira.

## Exemplos {#examples}

### 1) Manter só os grupos grandes {#1-keep-only-the-large-groups}

```sql
SELECT rating, COUNT(*) AS films
FROM film
GROUP BY rating
HAVING COUNT(*) > 200
ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
+--------+-------+
2 rows in set (0.01 sec)
```

Todas as 5 classificações foram contadas. 3 dos grupos falharam no teste em seguida e foram
descartados.

### 2) HAVING pode usar um alias {#2-having-can-use-an-alias}

Um alias nomeia uma coluna do resultado, e quando o `HAVING` roda o resultado
já existe.

```sql
SELECT rating, COUNT(*) AS films
FROM film
GROUP BY rating
HAVING films > 200
ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
+--------+-------+
2 rows in set (0.00 sec)
```

As mesmas 2 linhas, e menos para escrever. `WHERE` não consegue fazer isso, porque roda
antes de existir um resultado para nomear: a lição sobre [WHERE](/pt-BR/tutorial/where) mostra o
`ERROR 1054` que você recebe em vez disso.

### 3) As duas cláusulas em uma consulta {#3-both-clauses-in-one-query}

A maioria das consultas reais usa as duas: `WHERE` para escolher as linhas, `HAVING` para escolher os
grupos.

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE length > 120
GROUP BY rating
HAVING COUNT(*) > 100
ORDER BY rating;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   118 |
+--------+-------+
1 row in set (0.00 sec)
```

`WHERE` manteve os filmes com mais de 120 minutos, o agrupamento os contou por classificação,
e `HAVING` manteve a única classificação com mais de 100 deles.

## Um agregado não pode ir no WHERE {#an-aggregate-cannot-go-in-where}

Mova essa condição do `HAVING` para o `WHERE` e o servidor a recusa de imediato.

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE COUNT(*) > 200
GROUP BY rating;
```

```text
ERROR 1111 (HY000): Invalid use of group function
```

`WHERE` roda antes do agrupamento, então não existe contagem para ele testar. O mesmo
vale para o alias de um agregado, com um erro diferente.

```sql
SELECT rating, COUNT(*) AS films
FROM film
WHERE films > 200
GROUP BY rating;
```

```text
ERROR 1054 (42S22): Unknown column 'films' in 'where clause'
```

Os dois significam a mesma coisa e os dois se corrigem do mesmo jeito: mova a condição para o
`HAVING`.

`ERROR 1054` em um alias no `WHERE` tem 2 remédios, e o agregado é o que
os distingue. Um alias de uma expressão simples pode ser repetido no `WHERE`,
como a lição sobre [WHERE](/pt-BR/tutorial/where) mostra. Um alias de um agregado
não pode ser repetido ali de jeito nenhum, por causa do `ERROR 1111` acima, então ele tem de
ir para o `HAVING`.

## Qual cláusula testa o quê {#which-clause-tests-what}

| Cláusula | Roda | Testa | Exemplo |
|---|---|---|---|
| `WHERE` | antes do agrupamento | 1 linha | `WHERE length > 120` |
| `HAVING` | depois do agrupamento | 1 grupo inteiro | `HAVING COUNT(*) > 50` |

Coloque uma condição no `WHERE` sempre que ela testar uma linha, e reserve o `HAVING` para o que
só faz sentido depois que um grupo existe. Essa também é a disposição mais barata, por
razões que o guia
[Desempenho de GROUP BY no MySQL](/pt-BR/guides/group-by-having) mede.

<Note>
Nomear um alias da lista de seleção no `HAVING` é uma extensão do MySQL. Repita o
agregado em vez do alias quando o mesmo SQL tiver de rodar em outro
banco de dados.
</Note>

## Resumo {#summary}

- Use `HAVING` para descartar grupos inteiros, e `WHERE` para descartar linhas.
- Espere que o `HAVING` rode depois do `GROUP BY`, por isso ele pode testar um agregado.
- Leia `ERROR 1111` como um agregado no `WHERE` que pertence ao `HAVING`.
- Nomeie um alias de coluna no `HAVING`, o que o `WHERE` não pode fazer.
- Coloque uma condição no `WHERE` quando ela testar uma linha em vez de um grupo.
