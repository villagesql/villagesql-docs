Um `INSERT` pode carregar quantas linhas você quiser. Separe os parênteses de cada linha
com uma vírgula. Isso é menos digitação do que 1 instrução por linha, e é 1 viagem ao
servidor em vez de muitas.

Estes exemplos usam o banco de dados `sakila_practice` de
[INSERT](/pt-BR/tutorial/insert). Rode o bloco de configuração de lá de novo antes de começar,
depois abra o cliente com `mysql -u root -p sakila_practice`.

## Como um INSERT de várias linhas funciona {#how-a-multi-row-insert-works}

```sql
INSERT INTO TABLE_NAME (COLUMN_LIST) VALUES
  (FIRST_ROW_VALUES),
  (SECOND_ROW_VALUES);
```

Substitua `TABLE_NAME` pela tabela, `COLUMN_LIST` pelas colunas que você está
fornecendo, e cada um de `FIRST_ROW_VALUES` e `SECOND_ROW_VALUES` por 1 valor
para cada uma dessas colunas.

A lista de colunas é escrita uma vez e governa todas as linhas. Cada par de parênteses
fornece valores nessa ordem.

## Exemplos {#examples}

### 1) 3 linhas em 1 instrução {#1-3-rows-in-1-statement}

```sql
INSERT INTO member (first_name, last_name, email, joined) VALUES
  ('Jennifer', 'Davis',  'jennifer.davis@example.com',  '2026-03-18'),
  ('Barbara',  'Jones',  'barbara.jones@example.com',   '2026-03-19'),
  ('Elizabeth','Brown',  'elizabeth.brown@example.com', '2026-03-21');
```

```text
Query OK, 3 rows affected (0.00 sec)
Records: 3  Duplicates: 0  Warnings: 0
```

A segunda linha aparece sempre que uma instrução pode gravar mais de 1 linha, o que
cobre uma lista `VALUES` de várias linhas e qualquer
[INSERT SELECT](/pt-BR/tutorial/insert-select). `Records` conta as linhas que você enviou,
`Duplicates` as linhas que colidiram com uma linha já armazenada, e `Warnings`
qualquer coisa que o servidor teve de ajustar. Os 3 números coincidirem com o que você enviou é o
sinal de que nada foi alterado em silêncio.

```sql
SELECT member_id, first_name, last_name FROM member;
```

```text
+-----------+------------+-----------+
| member_id | first_name | last_name |
+-----------+------------+-----------+
|         1 | Mary       | Smith     |
|         2 | Patricia   | Johnson   |
|         3 | Linda      | Williams  |
|         4 | Jennifer   | Davis     |
|         5 | Barbara    | Jones     |
|         6 | Elizabeth  | Brown     |
+-----------+------------+-----------+
6 rows in set (0.00 sec)
```

Os ids continuam na ordem em que as linhas foram escritas.

## Uma linha ruim joga a instrução inteira fora {#one-bad-row-throws-the-whole-statement-away}

A instrução abaixo carrega 3 linhas. A do meio reutiliza o endereço de Mary Smith,
que o índice `UNIQUE` em `email` recusa.

```sql
INSERT INTO member (first_name, last_name, email, joined) VALUES
  ('Maria',  'Miller', 'maria.miller@example.com', '2026-04-02'),
  ('Susan',  'Wilson', 'mary.smith@example.com',   '2026-04-03'),
  ('Margaret','Moore', 'margaret.moore@example.com','2026-04-04');
```

```text
ERROR 1062 (23000): Duplicate entry 'mary.smith@example.com' for key 'member.uq_member_email'
```

As outras 2 linhas também não entraram.

```sql
SELECT COUNT(*) AS members FROM member;
```

```text
+---------+
| members |
+---------+
|       6 |
+---------+
1 row in set (0.00 sec)
```

Uma única instrução é tudo ou nada, então um lote de 10.000 linhas com 1 valor
ruim não grava nada. Tudo ou nada também significa que um lote grande precisa ter os
dados verificados antes de ser enviado, porque o servidor nomeia 1 linha ofensora e
para.

## INSERT IGNORE transforma o erro em um aviso {#insert-ignore-turns-the-error-into-a-warning}

`INSERT IGNORE` mantém as linhas que consegue e pula o resto.

```sql
INSERT IGNORE INTO member (first_name, last_name, email, joined) VALUES
  ('Maria',  'Miller', 'maria.miller@example.com', '2026-04-02'),
  ('Susan',  'Wilson', 'mary.smith@example.com',   '2026-04-03');
SHOW WARNINGS;
```

```text
Query OK, 1 row affected, 1 warning (0.00 sec)
Records: 2  Duplicates: 1  Warnings: 1

+---------+------+---------------------------------------------------------------------------+
| Level   | Code | Message                                                                   |
+---------+------+---------------------------------------------------------------------------+
| Warning | 1062 | Duplicate entry 'mary.smith@example.com' for key 'member.uq_member_email' |
+---------+------+---------------------------------------------------------------------------+
1 row in set (0.00 sec)
```

`Records: 2  Duplicates: 1` relata exatamente o que aconteceu: 2 linhas oferecidas, 1
recusada. `SHOW WARNINGS` então a nomeia, e o mesmo texto do `ERROR 1062` chega
como um aviso em vez de uma falha.

```sql
SELECT COUNT(*) AS members FROM member;
```

```text
+---------+
| members |
+---------+
|       7 |
+---------+
1 row in set (0.00 sec)
```

Use `IGNORE` quando uma duplicata significar de fato "já tenho isso". Fora disso, é um
instrumento grosseiro, porque rebaixa outros erros também, incluindo um valor
longo demais para a coluna e uma linha sem valor para uma coluna obrigatória. Rode
`SHOW WARNINGS` depois de cada `INSERT IGNORE` ou você não vai saber o que ele
descartou. Quando a resposta certa for atualizar a linha já armazenada, use
[upsert](/pt-BR/tutorial/upsert) em vez disso.

## Resumo {#summary}

- Separe os parênteses de cada linha com uma vírgula, e escreva a lista de colunas uma vez.
- Leia `Records`, `Duplicates` e `Warnings` para confirmar que nada foi ajustado.
- Espere que 1 linha rejeitada aborte a instrução inteira e não grave nada.
- Use `INSERT IGNORE` para manter as linhas boas, e leia `SHOW WARNINGS` em seguida.
- Prefira 1 instrução de várias linhas a muitas instruções de uma linha.
