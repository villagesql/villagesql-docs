NULL significa que o valor não está lá. Não é 0, e não é uma string vazia.
Ele precisa de um operador próprio, porque os operadores de comparação que você já conhece
não conseguem enxergá-lo.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como o IS NULL funciona {#how-is-null-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE COLUMN_NAME IS NULL;
```

Substitua `COLUMN_NAME` pela coluna a testar.

`IS NULL` é verdadeiro quando a coluna não tem valor. `IS NOT NULL` é verdadeiro quando ela
tem um. Esses 2 são os únicos testes confiáveis, e a razão é a regra
por baixo deles: qualquer comparação que envolva NULL dá NULL, que não é
verdadeiro nem falso, então o `WHERE` descarta a linha.

## Exemplos {#examples}

### 1) Encontrar os valores ausentes {#1-find-the-missing-values}

O Sakila registra o idioma em que um filme foi feito originalmente, e nunca preenche
isso.

```sql
SELECT title, original_language_id
FROM film
ORDER BY title
LIMIT 3;
```

```text
+------------------+----------------------+
| title            | original_language_id |
+------------------+----------------------+
| ACADEMY DINOSAUR |                 NULL |
| ACE GOLDFINGER   |                 NULL |
| ADAPTATION HOLES |                 NULL |
+------------------+----------------------+
3 rows in set (0.00 sec)
```

O cliente imprime `NULL` onde um valor ficaria.

```sql
SELECT title FROM film WHERE original_language_id IS NULL ORDER BY title LIMIT 3;
```

```text
+------------------+
| title            |
+------------------+
| ACADEMY DINOSAUR |
| ACE GOLDFINGER   |
| ADAPTATION HOLES |
+------------------+
3 rows in set (0.00 sec)
```

### 2) Encontrar as linhas que têm um valor {#2-find-the-rows-that-have-a-value}

Todos os 1.000 filmes deixam essa coluna vazia, então o teste oposto não retorna nada.

```sql
SELECT title FROM film WHERE original_language_id IS NOT NULL ORDER BY title;
```

```text
Empty set (0.00 sec)
```

### 3) Uma coluna que às vezes está ausente {#3-a-column-that-is-sometimes-missing}

`address2` é a segunda linha de um endereço. O Sakila tem 603 endereços, e
registra a segunda linha como ausente em 4 deles e como uma string vazia nos
outros 599.

```sql
SELECT address_id, address, address2
FROM address
WHERE address2 IS NULL
ORDER BY address_id;
```

```text
+------------+----------------------+----------+
| address_id | address              | address2 |
+------------+----------------------+----------+
|          1 | 47 MySakila Drive    | NULL     |
|          2 | 28 MySQL Boulevard   | NULL     |
|          3 | 23 Workhaven Lane    | NULL     |
|          4 | 1411 Lillydale Drive | NULL     |
+------------+----------------------+----------+
4 rows in set (0.00 sec)
```

## Um valor ausente e um valor vazio são diferentes {#a-missing-value-and-an-empty-one-are-different}

Só 4 dos 603 endereços não têm a segunda linha registrada. Os outros 599 têm uma
string vazia, que é um valor: alguém escreveu nada ali de propósito.

```sql
SELECT address_id, address2
FROM address
WHERE address2 = ''
ORDER BY address_id
LIMIT 3;
```

```text
+------------+----------+
| address_id | address2 |
+------------+----------+
|          5 |          |
|          6 |          |
|          7 |          |
+------------+----------+
3 rows in set (0.00 sec)
```

O cliente imprime `NULL` para um valor ausente e não imprime nada para uma string
vazia, então os 2 parecem quase iguais na tela e se comportam de forma nada parecida em uma
consulta. `IS NULL` encontra as primeiras 4 linhas e `= ''` encontra as outras 599. Nenhum
dos testes encontra os dois, então uma coluna que mistura os dois precisa de
`address2 IS NULL OR address2 = ''` para pegar todo valor em branco.

## = NULL não corresponde a nada, nunca {#-null-matches-nothing-ever}

Todo filme tem um NULL em `original_language_id`, então isto parece que deveria
retornar 1.000 linhas.

```sql
SELECT title FROM film WHERE original_language_id = NULL ORDER BY title;
```

```text
Empty set (0.01 sec)
```

Nenhuma linha, nenhum erro, nenhum aviso. `=` pergunta se 2 valores são iguais, e NULL
não é um valor, então a resposta não é sim nem não. É NULL, e o `WHERE`
mantém só as linhas em que a condição é verdadeira.

A mesma armadilha pega `<> NULL`, que também não corresponde a nada. `IS NULL` e
`IS NOT NULL` são os operadores feitos para esse trabalho.

Um operador escapa da regra. `<=>` é a igualdade segura para NULL: ele sempre responde
1 ou 0, e considera 2 NULLs como iguais. Use-o quando comparar 2 colunas
que podem estar ambas ausentes e você quer que isso conte como uma correspondência. A
lição sobre [Operadores](/pt-BR/tutorial/operators) o mostra ao lado das comparações que ele
substitui.

## Resumo {#summary}

- Use `IS NULL` e `IS NOT NULL` para testar um valor ausente.
- Nunca escreva `= NULL` ou `<> NULL`, porque os dois não correspondem a nenhuma linha e não dizem nada.
- Espere que qualquer comparação com NULL dê NULL, que o `WHERE` trata como não verdadeiro.
- Use `<=>` quando 2 NULLs devem contar como iguais.
- Teste uma string vazia separadamente, porque `IS NULL` não encontra uma.
