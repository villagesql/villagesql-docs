Uma subconsulta no `WHERE` fornece um valor. Uma subconsulta no `FROM` fornece uma
tabela inteira, que a consulta externa então lê como se fosse real. Isso é uma tabela
derivada, e é assim que você consulta o resultado de uma consulta.

Abra o cliente com `mysql -u root -p sakila` antes de começar.

## Como uma tabela derivada funciona {#how-a-derived-table-works}

```sql
SELECT COLUMN_LIST
FROM (SELECT COLUMN_LIST FROM TABLE_NAME) AS ALIAS_NAME;
```

Substitua `COLUMN_LIST` pelas colunas que você quer, `TABLE_NAME` pela tabela que a
consulta interna lê, e `ALIAS_NAME` por um nome para o resultado. Os nomes de coluna da consulta interna,
incluindo quaisquer aliases, se tornam as colunas da tabela derivada.

O servidor constrói o resultado interno primeiro, e então executa a consulta externa sobre ele.

## O que ela torna possível {#what-it-makes-possible}

Um `GROUP BY` substitui as linhas de detalhe por 1 linha por grupo, então uma consulta agrupada
não consegue mostrar a você as linhas em si. Uma tabela derivada mantém os dois: agrupe na
consulta interna, e então junte o resultado de volta ao detalhe.

Isto lista os filmes mais longos do que a média para sua própria classificação, e mostra essa
média ao lado de cada um.

```sql
SELECT f.title, f.length, r.mean_for_rating
FROM film AS f
INNER JOIN (
  SELECT rating, AVG(length) AS mean_for_rating
  FROM film
  GROUP BY rating
) AS r ON r.rating = f.rating
WHERE f.length > r.mean_for_rating
ORDER BY f.rating, f.title
LIMIT 5;
```

```text
+------------------+--------+-----------------+
| title            | length | mean_for_rating |
+------------------+--------+-----------------+
| AFFAIR PREJUDICE |    117 |        111.0506 |
| AFRICAN EGG      |    130 |        111.0506 |
| ALAMO VIDEOTAPE  |    126 |        111.0506 |
| ATLANTIS CAUSE   |    170 |        111.0506 |
| BAKED CLEOPATRA  |    182 |        111.0506 |
+------------------+--------+-----------------+
5 rows in set (0.00 sec)
```

Nem `WHERE` nem [HAVING](/pt-BR/tutorial/having) consegue escrever isto sozinho.
`HAVING` filtra grupos e teria descartado os títulos; `WHERE` executa
antes de qualquer média existir. As 5 médias são calculadas uma vez na consulta
interna, e o join anexa a certa a cada filme.

A lição [Subconsultas correlacionadas](/pt-BR/tutorial/correlated-subqueries) responde à
mesma pergunta uma linha de cada vez. Esta forma calcula as médias uma vez em vez disso.

## O alias não é opcional {#the-alias-is-not-optional}

```sql
SELECT rating, films
FROM (SELECT rating, COUNT(*) AS films FROM film GROUP BY rating)
WHERE films > 200;
```

```text
ERROR 1248 (42000): Every derived table must have its own alias
```

`ERROR 1248` sempre significa isto, e a correção é sempre a mesma: coloque
`AS SOME_NAME` depois do parêntese de fechamento. O nome pode ser qualquer um, e vale
a pena fazê-lo descrever as linhas, porque um leitor o encontra antes de ler
a consulta que o produziu.

## Tabela derivada ou CTE {#derived-table-or-cte}

Uma [expressão de tabela comum](/pt-BR/tutorial/cte) faz o mesmo trabalho com a subconsulta
levada para o topo e recebendo um nome. As 2 formas produzem as mesmas linhas, e
a próxima lição cobre a diferença.
[Quando uma CTE do MySQL supera uma tabela derivada](/pt-BR/guides/ctes-in-mysql) mede qual
delas o otimizador trata de modo diferente.

## Resumo {#summary}

- Use uma tabela derivada para consultar o resultado de uma consulta.
- Dê um alias a ela, porque `ERROR 1248` é o que você recebe sem um.
- Espere que os aliases de coluna da consulta interna se tornem as colunas da tabela derivada.
- Use-a quando precisar filtrar ou fazer join por uma coluna calculada.
- Prefira uma CTE quando a consulta tem vários estágios ou repete a mesma subconsulta.
