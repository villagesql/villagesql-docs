O VillageSQL Server é um substituto direto para o MySQL. Para uma instalação simples do MySQL 8.4 com uma única instância e sem plugins de terceiros, migrar para o VillageSQL é funcionalmente idêntico a uma atualização de versão menor (por exemplo, de 8.4.5 para 8.4.6), preservando os seus dados existentes. Qualquer coisa que dependa de plugins não padrão deve ser testada primeiro em uma cópia.

## Pré-requisitos {#prerequisites}

- **Binários do VillageSQL**: Garanta que você tenha os binários do VillageSQL prontos (compilados a partir do código-fonte ou baixados).
- **Versão do MySQL**: O VillageSQL é baseado no MySQL 8.4 LTS. Atualizar a partir do MySQL 8.4 é o caminho suportado.

<Warning>
  **Sempre faça backup dos seus dados antes de realizar uma atualização.**
  Embora o processo tenha sido projetado para ser seguro, atualizações de banco de dados sempre envolvem um risco.
</Warning>

## Etapa 1: Faça Backup dos Seus Dados {#step-1-backup-your-data}

Antes de tocar em qualquer arquivo de sistema ou serviço, crie um backup completo do seu banco de dados.

### Opção A: Backup Lógico (mysqldump) {#option-a-logical-backup-mysqldump}
Crie um dump SQL de todos os bancos de dados. Este é o método mais seguro e mais portátil.

```bash
mysqldump -u root -p --all-databases --events --routines --triggers > full_backup.sql
```

### Opção B: Backup Físico (Diretório de Dados) {#option-b-physical-backup-data-directory}
Se o seu conjunto de dados for grande, pare o servidor e copie o diretório de dados.

```bash
# Stop the server first (see Step 2)
cp -r /var/lib/mysql /var/lib/mysql-backup
```

## Etapa 2: Pare o Servidor MySQL {#step-2-stop-the-mysql-server}

Pare a instância do servidor MySQL em execução para liberar os bloqueios sobre os arquivos de dados.

**Usando Systemd (Linux):**
```bash
sudo systemctl stop mysql
# OR
sudo systemctl stop mysqld
```

**Usando SysV Init:**
```bash
sudo service mysql stop
```

**Instalação Manual:**
```bash
mysqladmin -u root -p shutdown
```

## Etapa 3: Substitua os Binários {#step-3-replace-binaries}

O núcleo da atualização consiste em trocar os arquivos executáveis (`mysqld`, `mysql`, etc.) das versões do MySQL upstream pelas versões do VillageSQL.

### Método A: Trocando os Diretórios de Instalação (Recomendado) {#method-a-swapping-installation-directories-recommended}

Se você instalou o MySQL via tarball (por exemplo, em `/usr/local/mysql`), o método mais limpo é instalar o VillageSQL ao lado dele e trocar o link simbólico.

1.  **Extraia/Instale o VillageSQL** em um novo diretório, por exemplo, `/usr/local/villagesql-8.4`.
2.  **Atualize o link simbólico**:
    ```bash
    # Remove link to old MySQL
    sudo unlink /usr/local/mysql

    # Link to VillageSQL
    sudo ln -s /usr/local/villagesql-8.4 /usr/local/mysql
    ```
3.  **Verifique as permissões**: Garanta que o usuário que executa o banco de dados (geralmente `mysql`) tenha permissão de execução sobre os novos binários.

### Método B: Sobrescrevendo os Binários {#method-b-overwriting-binaries}

Se você compilou o VillageSQL a partir do código-fonte e quer sobrescrever a instalação do sistema (por exemplo, `/usr/bin` ou `/usr/local/bin`):

```bash
# Assuming you are in the VillageSQL build directory
sudo make install
```

<Note>
  Se você instalou o MySQL por meio de um gerenciador de pacotes (`apt`, `yum`), sobrescrever os binários manualmente é arriscado, pois o gerenciador de pacotes pode sobrescrevê-los de volta durante as atualizações. Recomenda-se desinstalar o pacote `mysql-server` (mantendo os arquivos de dados!) ou usar `update-alternatives`, se disponível.
</Note>

## Etapa 4: Verificação da Configuração {#step-4-configuration-check}

Garanta que o seu arquivo de configuração (geralmente `/etc/my.cnf` ou `/etc/mysql/my.cnf`) aponte para o seu diretório de dados existente.

```ini
[mysqld]
datadir=/var/lib/mysql  # Should point to your EXISTING data
socket=/var/run/mysqld/mysqld.sock
```

O VillageSQL usa as opções de configuração padrão do MySQL, portanto o seu `my.cnf` existente deve funcionar sem modificações.

## Etapa 5: Inicie o VillageSQL {#step-5-start-villagesql}

Inicie o servidor usando o seu gerenciador de serviços ou manualmente.

**Usando Systemd:**
```bash
sudo systemctl start mysql
```

**Início Manual:**
```bash
/usr/local/mysql/bin/mysqld_safe --user=mysql &
```

### Atualização Automática {#automatic-upgrade}
Na inicialização, o VillageSQL detecta automaticamente se os arquivos de dados são de uma versão mais antiga e realiza as atualizações necessárias nas tabelas de sistema.

Verifique o log de erros (geralmente em `/var/log/mysql/error.log` ou dentro do seu `datadir`) para confirmar que a atualização foi concluída com sucesso. Procure por:
`[System] [MY-013381] [Server] Server upgrade from '...' to '...' completed.`

## Etapa 6: Verifique a Instalação {#step-6-verify-installation}

Conecte-se ao servidor e verifique se você está executando o VillageSQL.

```bash
mysql -u root -p
```

Execute a seguinte consulta:

```sql
SELECT @@version, @@version_comment;
```

Agora você pode verificar se os seus dados estão intactos e começar a usar os recursos exclusivos do VillageSQL, como `INSTALL EXTENSION`.

## Solução de Problemas {#troubleshooting}

-   **"Data Dictionary Upgrade Failed"**: Se o servidor se recusar a iniciar, você pode estar tentando fazer um downgrade (por exemplo, de 8.4 para 8.0) ou os arquivos de dados estão corrompidos. Verifique o log de erros.
-   **Erros de Permissão**: Garanta que o usuário `mysql` do sistema operacional seja o dono do `datadir` e do novo diretório de instalação do VillageSQL.
    ```bash
    sudo chown -R mysql:mysql /var/lib/mysql
    ```
