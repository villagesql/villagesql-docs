`INFORMATION_SCHEMA` é um banco de dados virtual que expõe os metadados do servidor MySQL por meio de consultas SQL padrão. Tudo o que `SHOW TABLES`, `SHOW COLUMNS` e `DESCRIBE` podem dizer a você, o `INFORMATION_SCHEMA` também pode — e com todo o poder de `WHERE`, `JOIN` e agregação.

## Tabelas e Colunas {#tables-and-columns}

Liste todas as tabelas de um banco de dados:

```sql
SELECT table_name, table_type, engine, table_rows, create_time
FROM information_schema.tables
WHERE table_schema = 'myapp'
ORDER BY table_name;
```

`table_rows` é uma estimativa para tabelas InnoDB (derivada das estatísticas de índice), não uma contagem exata. Use `SELECT COUNT(*)` para precisão.

Liste todas as colunas de uma tabela:

```sql
SELECT column_name, column_type, is_nullable, column_default, extra
FROM information_schema.columns
WHERE table_schema = 'myapp'
  AND table_name = 'users'
ORDER BY ordinal_position;
```

Encontre todas as colunas de um tipo específico em todas as tabelas:

```sql
SELECT table_name, column_name, column_type
FROM information_schema.columns
WHERE table_schema = 'myapp'
  AND data_type = 'json';
```

## Índices {#indexes}

Liste todos os índices de uma tabela:

```sql
SELECT index_name, non_unique, seq_in_index, column_name, index_type
FROM information_schema.statistics
WHERE table_schema = 'myapp'
  AND table_name = 'orders'
ORDER BY index_name, seq_in_index;
```

Encontre tabelas sem chave primária:

```sql
SELECT t.table_name
FROM information_schema.tables t
WHERE t.table_schema = 'myapp'
  AND t.table_type = 'BASE TABLE'
  AND NOT EXISTS (
    SELECT 1
    FROM information_schema.table_constraints tc
    WHERE tc.table_schema = t.table_schema
      AND tc.table_name = t.table_name
      AND tc.constraint_type = 'PRIMARY KEY'
  );
```

## Restrições {#constraints}

Liste todas as restrições (PRIMARY KEY, UNIQUE, FOREIGN KEY, CHECK):

```sql
SELECT constraint_name, constraint_type, table_name
FROM information_schema.table_constraints
WHERE table_schema = 'myapp'
ORDER BY table_name, constraint_type;
```

Liste todas as chaves estrangeiras e o que elas referenciam:

```sql
SELECT
    kcu.table_name,
    kcu.column_name,
    kcu.constraint_name,
    kcu.referenced_table_name,
    kcu.referenced_column_name,
    rc.update_rule,
    rc.delete_rule
FROM information_schema.key_column_usage kcu
JOIN information_schema.referential_constraints rc
    ON rc.constraint_schema = kcu.constraint_schema
    AND rc.constraint_name = kcu.constraint_name
WHERE kcu.table_schema = 'myapp'
  AND kcu.referenced_table_name IS NOT NULL
ORDER BY kcu.table_name;
```

Liste as restrições CHECK:

```sql
SELECT constraint_name, check_clause
FROM information_schema.check_constraints
WHERE constraint_schema = 'myapp'
ORDER BY constraint_name;
```

## Rotinas Armazenadas {#stored-routines}

Liste todos os procedimentos e funções armazenados:

```sql
SELECT routine_name, routine_type, created, last_altered
FROM information_schema.routines
WHERE routine_schema = 'myapp'
ORDER BY routine_type, routine_name;
```

Veja a definição de uma rotina:

```sql
SELECT routine_definition
FROM information_schema.routines
WHERE routine_schema = 'myapp'
  AND routine_name = 'get_active_users'
  AND routine_type = 'PROCEDURE'\G
```

## Views e Triggers {#views-and-triggers}

Liste todas as views:

```sql
SELECT table_name, view_definition
FROM information_schema.views
WHERE table_schema = 'myapp'\G
```

Liste todos os triggers:

```sql
SELECT trigger_name, event_manipulation, event_object_table,
       action_timing, action_statement
FROM information_schema.triggers
WHERE trigger_schema = 'myapp'
ORDER BY event_object_table, action_timing;
```

## Privilégios {#privileges}

Veja os privilégios concedidos ao usuário atual. As tabelas não listam os privilégios que vêm de roles; uma conta com privilégios globais vê todas as contas.

```sql
SELECT * FROM information_schema.user_privileges;
SELECT * FROM information_schema.schema_privileges;
SELECT * FROM information_schema.table_privileges;
```

## Referência das Tabelas Principais {#key-tables-reference}

| Tabela | O que contém |
|:------|:----------------|
| `TABLES` | Todas as tabelas e views, com engine, estimativas de contagem de linhas, tamanhos |
| `COLUMNS` | Todas as colunas com tipos, valores padrão e aceitação de nulos |
| `STATISTICS` | Definições de índices e cardinalidade |
| `TABLE_CONSTRAINTS` | Todas as restrições (PK, UK, FK, CHECK) |
| `KEY_COLUMN_USAGE` | Colunas em restrições, com detalhes do destino da FK |
| `REFERENTIAL_CONSTRAINTS` | Regras de cascade/restrict das FKs |
| `CHECK_CONSTRAINTS` | Expressões de restrições CHECK |
| `ROUTINES` | Procedimentos e funções armazenados |
| `TRIGGERS` | Definições de triggers |
| `VIEWS` | Definições de views |
| `CHARACTER_SETS` | Conjuntos de caracteres disponíveis |
| `COLLATIONS` | Collations disponíveis |
| `SCHEMATA` | Todos os bancos de dados visíveis para o usuário atual |

## INFORMATION_SCHEMA vs Comandos SHOW {#information_schema-vs-show-commands}

Os comandos `SHOW` são atalhos que frequentemente têm um equivalente em `INFORMATION_SCHEMA`:

| Comando SHOW | Equivalente em INFORMATION_SCHEMA |
|:------------|:------------------------------|
| `SHOW TABLES` | `SELECT table_name FROM information_schema.tables WHERE table_schema = DATABASE()` |
| `SHOW COLUMNS FROM t` | `SELECT * FROM information_schema.columns WHERE table_schema = DATABASE() AND table_name = 't'` |
| `SHOW INDEX FROM t` | `SELECT * FROM information_schema.statistics WHERE table_schema = DATABASE() AND table_name = 't'` |
| `SHOW CREATE TABLE t` | Sem equivalente direto — `SHOW CREATE TABLE` ainda é a forma mais fácil |
| `SHOW PROCEDURE STATUS` | `SELECT * FROM information_schema.routines WHERE routine_type = 'PROCEDURE'` |

As consultas ao `INFORMATION_SCHEMA` são melhores quando você precisa de filtragem, joins ou agregação. Os comandos `SHOW` são adequados para inspeção interativa.

## Perguntas Frequentes {#frequently-asked-questions}

#### As consultas ao INFORMATION_SCHEMA são lentas? {#are-information_schema-queries-slow}

Para tabelas InnoDB, algumas consultas (especialmente contra `TABLES` e `STATISTICS`) disparam atualizações das estatísticas de índice, o que pode ser lento em schemas grandes. Se você consulta metadados com frequência, use `mysql.innodb_table_stats` e `mysql.innodb_index_stats` para um acesso mais rápido às estatísticas em cache.

#### Por que os valores de table_rows parecem errados? {#why-do-table_rows-values-look-wrong}

`information_schema.tables.table_rows` é uma estimativa a partir das estatísticas de índice do InnoDB, não uma contagem ao vivo. Ela pode errar em 40-50% em tabelas grandes. Execute `ANALYZE TABLE tablename` para atualizar as estatísticas, ou use `SELECT COUNT(*)` para uma contagem exata.

## Solução de Problemas {#troubleshooting}

| Problema | Solução |
|:--------|:---------|
| A consulta não retorna linhas para uma tabela conhecida | O usuário atual pode não ter nenhum privilégio na tabela — o `INFORMATION_SCHEMA` filtra os resultados para as tabelas que o usuário pode ver |
| `table_rows` é muito diferente de COUNT(*) | As contagens de linhas do InnoDB são estimativas — execute `ANALYZE TABLE` para atualizar as estatísticas de índice |
| Não consigo encontrar uma restrição pelo nome | Os nomes de `FOREIGN KEY` e `CHECK` têm escopo por banco de dados, e os de `PRIMARY` e `UNIQUE`, por tabela — verifique `constraint_schema` e `table_name` na cláusula WHERE |
| Consulta lenta contra `INFORMATION_SCHEMA.TABLES` | O InnoDB atualiza as estatísticas no acesso; use `information_schema_stats_expiry` (padrão 86400 segundos) para manter os resultados em cache por mais tempo |
