A row in one table often points at a row in another. In Sakila, each film
records the language it is in, but it stores only a number. The language name
lives in a second table. `INNER JOIN` reads both tables in one query, so you
get the name instead of the number.

An inner join keeps a row only when the match succeeds. If a film named no
language, that film would not appear in the result at all. The other kind, an
outer join, keeps the unmatched row and leaves the columns from the other table
empty. Hold on to that difference, because it explains most surprising join
results.

Open the client with `mysql -u root -p sakila` before you start.

## How INNER JOIN works

```sql
SELECT COLUMN_LIST
FROM LEFT_TABLE
INNER JOIN RIGHT_TABLE ON LEFT_TABLE.COLUMN = RIGHT_TABLE.COLUMN;
```

`LEFT_TABLE` is where you start. `RIGHT_TABLE` is the table you are pulling
extra columns out of.

The `ON` clause says which rows belong together. MySQL takes each row of the
left table, finds the rows of the right table where that condition holds, and
returns one combined row for each match.

When both tables hold a column of the same name, write
`TABLE_NAME.COLUMN_NAME` so the server knows which one you mean.

## Examples

### 1) Join two tables

`film.language_id` points at `language.language_id`. Match that pair and you
can print the language name beside the title.

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l ON f.language_id = l.language_id;
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
| AFFAIR PREJUDICE            | English |
| AFRICAN EGG                 | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

1,000 rows, the same count as `film` on its own. Every film matched exactly one
language, which is what you get when the joining column points at a single row.

`AS f` and `AS l` are table aliases. They rename a table for the length of the
query, which is why `f.title` works here in place of `film.title`.

### 2) Join across a foreign key

Customers keep their street address in a separate table.

```sql
SELECT c.first_name, c.last_name, a.address
FROM customer AS c
INNER JOIN address AS a ON c.address_id = a.address_id;
```

```text
+-------------+--------------+----------------------------------------+
| first_name  | last_name    | address                                |
+-------------+--------------+----------------------------------------+
| MARY        | SMITH        | 1913 Hanoi Way                         |
| PATRICIA    | JOHNSON      | 1121 Loja Avenue                       |
| LINDA       | WILLIAMS     | 692 Joliet Street                      |
| BARBARA     | JONES        | 1566 Inegöl Manor                      |
| ELIZABETH   | BROWN        | 53 Idfu Parkway                        |
...
+-------------+--------------+----------------------------------------+
599 rows in set (0.00 sec)
```

599 rows, one per customer.

### 3) Join three tables

Add another `INNER JOIN` clause for each further table. Sakila splits location
across `address`, `city` and `country`, so reaching the city name takes 2 hops.

```sql
SELECT c.first_name, c.last_name, ci.city
FROM customer AS c
INNER JOIN address AS a ON c.address_id = a.address_id
INNER JOIN city AS ci ON a.city_id = ci.city_id;
```

```text
+-------------+--------------+----------------------------+
| first_name  | last_name    | city                       |
+-------------+--------------+----------------------------+
| MARY        | SMITH        | Sasebo                     |
| PATRICIA    | JOHNSON      | San Bernardino             |
| LINDA       | WILLIAMS     | Athenai                    |
| BARBARA     | JONES        | Myingyan                   |
| ELIZABETH   | BROWN        | Nantou                     |
...
+-------------+--------------+----------------------------+
599 rows in set (0.00 sec)
```

Still 599 rows. Each join matched a single row, so the count did not move.

### 4) Shorten it with USING

When the 2 columns carry the same name, `USING` replaces `ON` and says the name
once.

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l USING (language_id);
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
| AFFAIR PREJUDICE            | English |
| AFRICAN EGG                 | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

The same 1,000 rows as example 1. `USING` works only when the names match on
both sides, so `ON` is the form that always applies.

## Unmatched rows disappear

Turn example 1 around and start from `language` instead. The `language` table
holds 6 rows, so you might expect every language to show up.

```sql
SELECT l.name, f.title
FROM language AS l
INNER JOIN film AS f ON l.language_id = f.language_id;
```

```text
+---------+-----------------------------+
| name    | title                       |
+---------+-----------------------------+
| English | ACADEMY DINOSAUR            |
| English | ACE GOLDFINGER              |
| English | ADAPTATION HOLES            |
| English | AFFAIR PREJUDICE            |
| English | AFRICAN EGG                 |
...
+---------+-----------------------------+
1000 rows in set (0.00 sec)
```

Only English appears. Every film in Sakila is English, so Italian, Japanese,
Mandarin, French and German match no film and drop out of the result. An inner
join reports what matched, never what is missing.

## Matching several rows multiplies them

A join returns one row per match, so a row that matches many rows comes back
many times. Each film has several actors.

```sql
SELECT f.title, fa.actor_id
FROM film AS f
INNER JOIN film_actor AS fa ON f.film_id = fa.film_id;
```

```text
+-----------------------------+----------+
| title                       | actor_id |
+-----------------------------+----------+
| ACADEMY DINOSAUR            |        1 |
| ACADEMY DINOSAUR            |       10 |
| ACADEMY DINOSAUR            |       20 |
| ACADEMY DINOSAUR            |       30 |
| ACADEMY DINOSAUR            |       40 |
...
+-----------------------------+----------+
5462 rows in set (0.00 sec)
```

5,462 rows from 1,000 films, with each title repeated once per actor. This is
the usual reason a join returns more rows than you expected.

## Leaving out ON gives you every combination

MySQL accepts `INNER JOIN` with no `ON` clause. It raises no error. It pairs
every row on the left with every row on the right.

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l;
```

```text
+-----------------------------+----------+
| title                       | name     |
+-----------------------------+----------+
| ACADEMY DINOSAUR            | German   |
| ACADEMY DINOSAUR            | French   |
| ACADEMY DINOSAUR            | Mandarin |
| ACADEMY DINOSAUR            | Japanese |
| ACADEMY DINOSAUR            | Italian  |
...
+-----------------------------+----------+
6000 rows in set (0.00 sec)
```

Every film now claims all 6 languages, and 1,000 times 6 is 6,000 rows. When a
join returns a suspiciously round and suspiciously large number, a missing `ON`
clause is the first thing to check.

## JOIN, INNER JOIN and CROSS JOIN behave the same way

Swap `INNER JOIN` for `CROSS JOIN` and keep the `ON` clause. The result does
not change.

```sql
SELECT f.title, l.name
FROM film AS f
CROSS JOIN language AS l ON f.language_id = l.language_id;
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

Writing `JOIN` on its own gives the same 1,000 rows again. So in MySQL the
keyword you choose does not decide what you get. The `ON` clause does. Write
`INNER JOIN` with an `ON` clause and your intent is plain to anyone reading it.

## Summary

- Use `INNER JOIN` with `ON` to combine rows from tables that match.
- Add one `INNER JOIN` clause per further table.
- Expect unmatched rows to vanish, because an inner join reports only matches.
- Expect the row count to grow when one row matches many.
- Always write `ON`, because MySQL reads a join without one as every combination.
