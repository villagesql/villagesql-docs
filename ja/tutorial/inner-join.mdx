`INNER JOIN` は一致が成立した行だけを残します。あるテーブルの行が別の
テーブルの行を指していて、その両方が欲しいときに使う結合です。

始める前に `mysql -u root -p sakila` でクライアントを開いてください。

## INNER JOIN の仕組み {#how-inner-join-works}

```sql
SELECT COLUMN_LIST
FROM LEFT_TABLE
INNER JOIN RIGHT_TABLE ON LEFT_TABLE.COLUMN_NAME = RIGHT_TABLE.COLUMN_NAME;
```

`COLUMN_LIST` を欲しい列に、`LEFT_TABLE` を起点にするテーブルに、
`RIGHT_TABLE` を追加の列を取り出すテーブルに、各 `COLUMN_NAME` をそれぞれの
側で両者をつなぐ列に置き換えます。

`ON` 句はどの行同士が対応するかを指定します。MySQL は左テーブルの各行を
取り、その条件が成り立つ右テーブルの行を見つけ、一致ごとに 1 つの結合された
行を返します。何も見つからなかった行は、どちら側でも除外されます。
[LEFT JOIN](/ja/tutorial/left-join) は、そうした行を代わりに残す句です。

## 例 {#examples}

### 1) 2 つのテーブルを結合する {#1-join-2-tables}

`film.language_id` は `language.language_id` を指しています。この組を
一致させれば、タイトルの横に言語名を表示できます。

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l ON f.language_id = l.language_id
ORDER BY f.title;
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

1,000 行で、`film` 単体と同じ件数です。すべての映画がちょうど 1 つの言語に
一致しました。結合列が単一の行を指しているときはこうなります。

### 2) 外部キーをたどって結合する {#2-join-across-a-foreign-key}

顧客の住所は別のテーブルに保存されています。

```sql
SELECT c.first_name, c.last_name, a.address
FROM customer AS c
INNER JOIN address AS a ON c.address_id = a.address_id
ORDER BY c.last_name, c.first_name;
```

```text
+-------------+--------------+----------------------------------------+
| first_name  | last_name    | address                                |
+-------------+--------------+----------------------------------------+
| RAFAEL      | ABNEY        | 48 Maracaíbo Place                     |
| NATHANIEL   | ADAM         | 786 Matsue Way                         |
| KATHLEEN    | ADAMS        | 334 Munger (Monghyr) Lane              |
...
+-------------+--------------+----------------------------------------+
599 rows in set (0.00 sec)
```

599 行、顧客 1 人につき 1 行です。

### 3) 3 つのテーブルを結合する {#3-join-3-tables}

テーブルを増やすごとに `INNER JOIN` 句を 1 つ追加します。Sakila は所在地を
`address`、`city`、`country` に分けているので、都市名にたどり着くには
2 段階必要です。

```sql
SELECT c.first_name, c.last_name, ci.city
FROM customer AS c
INNER JOIN address AS a ON c.address_id = a.address_id
INNER JOIN city AS ci ON a.city_id = ci.city_id
ORDER BY c.last_name, c.first_name;
```

```text
+-------------+--------------+----------------------------+
| first_name  | last_name    | city                       |
+-------------+--------------+----------------------------+
| RAFAEL      | ABNEY        | Talavera                   |
| NATHANIEL   | ADAM         | Joliet                     |
| KATHLEEN    | ADAMS        | Arak                       |
...
+-------------+--------------+----------------------------+
599 rows in set (0.00 sec)
```

依然として 599 行です。各結合が単一の行に一致したので、件数は動きませんでした。

### 4) USING で短く書く {#4-shorten-it-with-using}

2 つの列が同じ名前のとき、`USING` が `ON` の代わりになり、名前を 1 回だけ
書きます。

```sql
SELECT f.title, l.name
FROM film AS f
INNER JOIN language AS l USING (language_id)
ORDER BY f.title;
```

```text
+-----------------------------+---------+
| title                       | name    |
+-----------------------------+---------+
| ACADEMY DINOSAUR            | English |
| ACE GOLDFINGER              | English |
| ADAPTATION HOLES            | English |
...
+-----------------------------+---------+
1000 rows in set (0.00 sec)
```

例 1 と同じ 1,000 行です。`USING` は両側で名前が一致するときにしか使えない
ので、常に使えるのは `ON` の形です。

## 複数行への一致は行を増やす {#matching-several-rows-multiplies-them}

結合は一致ごとに 1 行を返すので、多数の行に一致する行は何度も返ってきます。
各映画には複数の俳優がいます。

```sql
SELECT f.title, fa.actor_id
FROM film AS f
INNER JOIN film_actor AS fa ON f.film_id = fa.film_id
ORDER BY f.title, fa.actor_id;
```

```text
+-----------------------------+----------+
| title                       | actor_id |
+-----------------------------+----------+
| ACADEMY DINOSAUR            |        1 |
| ACADEMY DINOSAUR            |       10 |
| ACADEMY DINOSAUR            |       20 |
...
+-----------------------------+----------+
5462 rows in set (0.00 sec)
```

1,000 本の映画から 5,462 行、各タイトルが俳優ごとに 1 回繰り返されています。
結合が予想より多くの行を返す通常の理由はこれであり、結合に対して計算した
合計が大きくなりすぎる理由でもあります。

## 人がつまずく 2 つのこと {#2-things-that-catch-people-out}

**一致しなかった行は空欄ではなく消える。** `film` ではなく `language` を
起点にしても、1,005 行ではなく 1,000 行が返ります。Sakila の他の 5 言語は
どの映画にも一致せず、脱落します。内部結合は一致したものを報告し、欠けて
いるものは決して報告しません。[LEFT JOIN](/ja/tutorial/left-join) が、もう
一方の問いを立てる方法です。

**`ON` の欠落はエラーにならない。** MySQL は `ON` のない `INNER JOIN` を
両テーブルのすべての組み合わせとして読むので、入力ミスはエラーではなく
1,000 × 6 行を返します。[CROSS JOIN](/ja/tutorial/cross-join) では、意図的な
場合と偶発的な場合の両方を扱います。

## まとめ {#summary}

- 一致するテーブルの行を組み合わせるには、`INNER JOIN` を `ON` と共に使います。
- テーブルを増やすごとに `INNER JOIN` 句を 1 つ追加します。
- 一致しない行は消えます。内部結合は一致したものだけを報告するからです。
- 1 行が多数の行に一致すると、行数が増えます。
- `USING` は、列が両側で同じ名前のときにだけ使います。
