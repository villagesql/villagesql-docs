`UPDATE` は既にある行を変更します。どの行かは `WHERE` が決め、1 行とテーブル
全体を隔てているのは `WHERE` だけです。

これらの例は、[INSERT](/ja/tutorial/insert) の `sakila_practice` データベースを
使います。始める前にそこにあるセットアップのブロックをもう一度実行し、次に
`mysql -u root -p sakila_practice` でクライアントを開いてください。

## UPDATE の仕組み {#how-update-works}

```sql
UPDATE TABLE_NAME
SET COLUMN_NAME = NEW_VALUE
WHERE CONDITION;
```

`TABLE_NAME` をテーブルに、`COLUMN_NAME` を変更する列に、`NEW_VALUE` をそこに
入れる値に、`CONDITION` を行を選ぶテストに置き換えます。

`WHERE` は `SELECT` の場合とまったく同じように動作し、それが `UPDATE` を書く
最も安全な方法です。まず `SELECT` として実行し、行を確認し、それから
`SELECT ...` を `UPDATE ... SET ...` に変え、`WHERE` はそのままにします。

## 例 {#examples}

### 1) 1 行を変更する {#1-change-1-row}

```sql
UPDATE member SET active = 0 WHERE member_id = 2;
```

```text
Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0
```

```sql
SELECT member_id, first_name, last_name, active FROM member;
```

```text
+-----------+------------+-----------+--------+
| member_id | first_name | last_name | active |
+-----------+------------+-----------+--------+
|         1 | Mary       | Smith     |      1 |
|         2 | Patricia   | Johnson   |      0 |
|         3 | Linda      | Williams  |      0 |
+-----------+------------+-----------+--------+
3 rows in set (0.00 sec)
```

### 2) Matched と Changed は別のものを数える {#2-matched-and-changed-count-different-things}

同じ文をもう一度実行します。

```sql
UPDATE member SET active = 0 WHERE member_id = 2;
```

```text
Query OK, 0 rows affected (0.00 sec)
Rows matched: 1  Changed: 0  Warnings: 0
```

`WHERE` は依然としてその行を見つけたため、`Rows matched` は 1 です。行は既に
0 を保持していたため、何も書き込まれず、`Changed` は 0 です。2 つの数を
一緒に読んでください。`matched 0` は `WHERE` が何も見つけなかったという意味で、
`changed 0` とは別の問題です。`changed 0` は、行が既に持っている値を指定した
という意味です。

### 3) 複数の列を一度に変更する {#3-change-several-columns-at-once}

代入は `AND` ではなくカンマで区切ります。

```sql
UPDATE member
SET last_name = 'Smith-Davis', email = 'mary.smith-davis@example.com'
WHERE member_id = 1;
```

```text
Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0
```

```sql
SELECT member_id, first_name, last_name, email FROM member WHERE member_id = 1;
```

```text
+-----------+------------+-------------+------------------------------+
| member_id | first_name | last_name   | email                        |
+-----------+------------+-------------+------------------------------+
|         1 | Mary       | Smith-Davis | mary.smith-davis@example.com |
+-----------+------------+-------------+------------------------------+
1 row in set (0.00 sec)
```

## UPDATE は INSERT と同じ制約を受ける {#an-update-meets-the-same-constraints-an-insert-does}

別の行が保持している値を `UNIQUE` 列に移すと、同じように失敗し、行は元の値を
保持します。

```sql
UPDATE member SET email = 'patricia.johnson@example.com' WHERE member_id = 3;
```

```text
ERROR 1062 (23000): Duplicate entry 'patricia.johnson@example.com' for key 'member.uq_member_email'
```

## WHERE がないとすべての行が変わる {#without-a-where-it-changes-every-row}

確認のステップはありません。文は実行され、テーブル内のすべての行が新しい値を
取ります。

セッションの設定でこの形を拒否させることができます。セーフアップデートモードは、
`WHERE` でキー列をテストせず、`LIMIT` も付けていない `UPDATE` または `DELETE` を
拒否します。このモードは、要求しない限りオフです。

```sql
SET SESSION sql_safe_updates = 1;
UPDATE member SET active = 1;
```

```text
Query OK, 0 rows affected (0.00 sec)

ERROR 1175 (HY000): You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.
```

最初の文からこの保護を得るには、`mysql -u root -p --safe-updates sakila_practice`
でクライアントを起動します。このフラグはこの 1 つの変数を設定する以上のことを
します。`sql_select_limit` によって `SELECT` を 1,000 行に制限し、`max_join_size`
によって結合を制限するため、大きなテーブルに対する読み取りは、何も言わずに
途中で打ち切られて返ってきます。`ERROR 1175` は、保護があなたを止めたという意味です。

文が本当にすべての行に触れることを意図しているときは、もう一度オフにします。

```sql
SET SESSION sql_safe_updates = 0;
```

```text
Query OK, 0 rows affected (0.00 sec)
```

保護をオフにすると、文は実行されます。

```sql
UPDATE member SET active = 1;
```

```text
Query OK, 2 rows affected (0.00 sec)
Rows matched: 3  Changed: 2  Warnings: 0
```

```sql
SELECT member_id, first_name, active FROM member;
```

```text
+-----------+------------+--------+
| member_id | first_name | active |
+-----------+------------+--------+
|         1 | Mary       |      1 |
|         2 | Patricia   |      1 |
|         3 | Linda      |      1 |
+-----------+------------+--------+
3 rows in set (0.00 sec)
```

`Rows matched: 3  Changed: 2` となるのは、1 人のメンバーが既にアクティブだった
ためです。

テーブル全体の更新がまさに正しいこともあります。すべての残高を 5% 上げるのは
1 つの文で、新しい値は古い値から計算されます。

```sql
UPDATE account SET balance = balance * 1.05;
```

```text
Query OK, 2 rows affected (0.00 sec)
Rows matched: 2  Changed: 2  Warnings: 0
```

```sql
SELECT * FROM account;
```

```text
+------------+------------------+---------+
| account_id | owner            | balance |
+------------+------------------+---------+
|          1 | Mary Smith       |  525.00 |
|          2 | Patricia Johnson |  262.50 |
+------------+------------------+---------+
2 rows in set (0.00 sec)
```

`balance = balance * 1.05` は各行の現在の値を読むため、すべての行がそれぞれ
自分の答えを得ます。

## まとめ {#summary}

- 既存の行を変更するには `UPDATE table SET column = value WHERE condition` と書きます。
- まず `WHERE` を `SELECT` として実行し、それから文の先頭だけを変えます。
- `Rows matched` と `Changed` は 2 つの別々の事実として読みます。
- 複数の代入はカンマで区切ります。
- `UPDATE` は `INSERT` と同じ `UNIQUE` と `NOT NULL` の規則に当たると考えてください。
- セーフアップデートモードをオンにし、`ERROR 1175` は保護が仕事をしているものとして読みます。
