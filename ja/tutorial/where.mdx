`WHERE` は条件を満たす行を保持し、残りを捨てます。これまでのすべてのレッスンは
テーブル全体を返しました。これが、テーブルを答えに変える句です。

始める前に、`mysql -u root -p sakila` でクライアントを開いてください。

## WHERE の仕組み {#how-where-works}

```sql
SELECT COLUMN_LIST
FROM TABLE_NAME
WHERE SEARCH_CONDITION;
```

`COLUMN_LIST` を欲しい列に、`TABLE_NAME` をテーブルに、`SEARCH_CONDITION` を
サーバーが一度に 1 行ずつ適用できるテストに置き換えます。サーバーは各行を
読み、その行の値に対して条件を評価し、結果が真のときに行を保持します。偽に
なる行、または NULL になる行は捨てられます。

`WHERE` は `FROM` の後、`ORDER BY` の前に置き、それが結果が定義される順序
です。絞り込み、次に残ったものの並べ替え、次に `LIMIT` の適用です。そのため、
`WHERE` の後の `LIMIT 5` は、一致する行のうちの 5 行を返すのであって、一部が
一致する 5 行を返すのではありません。サーバーはその答えにどんな方法でたどり
着いてもよく、`EXPLAIN` がどの方法を選んだかを示します。

## 例 {#examples}

### 1) 1 つの値に一致させる {#1-match-one-value}

Sakila はすべての映画にレーティングを付けています。これはレーティングが `G` の
映画を保持します。

```sql
SELECT film_id, title, rating
FROM film
WHERE rating = 'G'
ORDER BY title
LIMIT 5;
```

```text
+---------+-------------------+--------+
| film_id | title             | rating |
+---------+-------------------+--------+
|       2 | ACE GOLDFINGER    | G      |
|       4 | AFFAIR PREJUDICE  | G      |
|       5 | AFRICAN EGG       | G      |
|      11 | ALAMO VIDEOTAPE   | G      |
|      22 | AMISTAD MIDSUMMER | G      |
+---------+-------------------+--------+
5 rows in set (0.00 sec)
```

文字列は単一引用符で囲みます。数値は囲みません。

### 2) 数値を比較する {#2-compare-a-number}

```sql
SELECT title, length
FROM film
WHERE length > 180
ORDER BY length DESC, title
LIMIT 5;
```

```text
+----------------+--------+
| title          | length |
+----------------+--------+
| CHICAGO NORTH  |    185 |
| CONTROL ANTHEM |    185 |
| DARN FORRESTER |    185 |
| GANGS PRIDE    |    185 |
| HOME PITY      |    185 |
+----------------+--------+
5 rows in set (0.00 sec)
```

185 分はカタログ内で最も長い映画で、その長さの映画が 10 本あるため、最初の
5 行はすべて同点です。`title` でも並べ替えることで同点が解消され、そのおかげで
毎回同じ 5 本が返ってきます。

### 3) 選択していない列で絞り込む {#3-filter-on-a-column-you-did-not-select}

条件は結果ではなく行をテストします。ここで `rental_rate` は出力にまったく
現れませんが、フィルタは動作します。

```sql
SELECT title
FROM film
WHERE rental_rate = 4.99
ORDER BY title
LIMIT 5;
```

```text
+------------------+
| title            |
+------------------+
| ACE GOLDFINGER   |
| AIRPLANE SIERRA  |
| AIRPORT POLLOCK  |
| ALADDIN CALENDAR |
| ALI FOREVER      |
+------------------+
5 rows in set (0.00 sec)
```

### 4) 1 つの値を除くすべて {#4-everything-except-one-value}

```sql
SELECT title, rating
FROM film
WHERE rating <> 'G'
ORDER BY title
LIMIT 5;
```

```text
+------------------+--------+
| title            | rating |
+------------------+--------+
| ACADEMY DINOSAUR | PG     |
| ADAPTATION HOLES | NC-17  |
| AGENT TRUMAN     | PG     |
| AIRPLANE SIERRA  | PG-13  |
| AIRPORT POLLOCK  | R      |
+------------------+--------+
5 rows in set (0.00 sec)
```

`<>` は「等しくない」です。`!=` も同じ意味で、どちらでもかまいません。

## WHERE は列エイリアスを見られない {#where-cannot-see-a-column-alias}

エイリアスは結果の列に名前を付けます。`WHERE` は結果が存在する前に実行される
ため、そこでエイリアスを指定すると失敗します。

```sql
SELECT title, rental_rate * 2 AS double_rate
FROM film
WHERE double_rate > 8
ORDER BY title;
```

```text
ERROR 1054 (42S22): Unknown column 'double_rate' in 'where clause'
```

代わりに、条件の中で式をもう一度書きます。

```sql
SELECT title, rental_rate * 2 AS double_rate
FROM film
WHERE rental_rate * 2 > 8
ORDER BY title
LIMIT 5;
```

```text
+------------------+-------------+
| title            | double_rate |
+------------------+-------------+
| ACE GOLDFINGER   |        9.98 |
| AIRPLANE SIERRA  |        9.98 |
| AIRPORT POLLOCK  |        9.98 |
| ALADDIN CALENDAR |        9.98 |
| ALI FOREVER      |        9.98 |
+------------------+-------------+
5 rows in set (0.00 sec)
```

`ORDER BY` はエイリアスを使える句です。結果が構築された後に実行されるため
です。[ORDER BY](/ja/tutorial/order-by) のレッスンがそれを示しています。

## 一致なしはエラーではない {#nothing-matching-is-not-an-error}

```sql
SELECT title FROM film WHERE rating = 'X';
```

```text
Empty set (0.00 sec)
```

`Empty set` は、クエリが実行され、条件を満たす行がなかったという意味です。
サーバーは表の代わりにこれを表示するため、列の見出しもありません。これは
1 つの答えです。

## まとめ {#summary}

- 条件を満たす行だけを保持するには `WHERE` を使います。
- 文字列は単一引用符で囲み、数値はそのまま書きます。
- サーバーはまず絞り込み、次に並べ替え、次に `LIMIT` を適用すると考えてください。
- 選択したかどうかにかかわらず、テーブルのどの列でもテストできます。
- `WHERE` ではエイリアスを指定するのではなく式を繰り返します。エイリアスを指定すると `ERROR 1054` になります。
