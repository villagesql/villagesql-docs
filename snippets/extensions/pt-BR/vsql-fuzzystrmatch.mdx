O `vsql_fuzzystrmatch` é um port da extensão `fuzzystrmatch` do PostgreSQL. Ele
responde a duas perguntas diferentes sobre um par de strings: se elas soam
parecido e quantas edições as separam. Use-o para correspondência de nomes,
correção ortográfica e deduplicação de registros digitados à mão.

## Instalar

O `vsql_fuzzystrmatch.veb` já está no diretório `lib/veb/` do servidor se você
instalou o VillageSQL com o script de instalação, a imagem Docker ou um tarball
de release. Instale-o no servidor com uma única instrução:

```sql
INSTALL EXTENSION vsql_fuzzystrmatch;
```

Confirme que ele está lá:

```sql
SELECT EXTENSION_NAME
FROM INFORMATION_SCHEMA.EXTENSIONS
WHERE EXTENSION_NAME = 'vsql_fuzzystrmatch';
```

```
+--------------------+
| EXTENSION_NAME     |
+--------------------+
| vsql_fuzzystrmatch |
+--------------------+
```

Para compilá-lo você mesmo, siga as instruções de compilação no
[repositório](https://github.com/villagesql/vsql-fuzzystrmatch).

## O que ela adiciona

| Função | Retorna | O que faz |
|---|---|---|
| `vsql_fuzzystrmatch.soundex(s)` | texto | O código Soundex, de modo que nomes que soam parecido compartilham um valor. Qualifique esta função, veja a nota abaixo |
| `difference(a, b)` | int | Quantas das quatro posições do Soundex coincidem, de 0 a 4 |
| `levenshtein(a, b)` | int | A distância de edição |
| `levenshtein_cost(a, b, ins, del, sub)` | int | O mesmo, com o seu próprio custo por operação |
| `levenshtein_less_equal(a, b, max)` | int | A distância, desistindo assim que ultrapassa `max` e retornando `max` mais 1 |
| `levenshtein_less_equal_cost(a, b, ins, del, sub, max)` | int | As duas anteriores juntas |
| `metaphone(s, length)` | texto | O código Metaphone, truncado em `length` |
| `dmetaphone(s)` | texto | O código Double Metaphone primário |
| `dmetaphone_alt(s)` | texto | O código alternativo, recorrendo ao primário quando não há nenhum |

## Exemplo

Duas grafias do mesmo nome produzem o mesmo código Soundex, e `difference`
pontua a correspondência de 0 a 4:

```sql
SELECT vsql_fuzzystrmatch.soundex('Robert') AS robert,
       vsql_fuzzystrmatch.soundex('Rupert') AS rupert,
       difference('Robert', 'Rupert') AS same_sound;
```

```
+--------+--------+------------+
| robert | rupert | same_sound |
+--------+--------+------------+
| R163   | R163   |          4 |
+--------+--------+------------+
```

A distância de edição conta as alterações, em vez disso:

```sql
SELECT levenshtein('kitten', 'sitting') AS edits,
       levenshtein_less_equal('kitten', 'sitting', 2) AS capped_at_2;
```

```
+-------+-------------+
| edits | capped_at_2 |
+-------+-------------+
|     3 |           3 |
+-------+-------------+
```

O Metaphone lida com os sons que a grafia esconde, como o `Th` em Thompson:

```sql
SELECT metaphone('Thompson', 10) AS metaphone, dmetaphone('Thompson') AS dmetaphone;
```

```
+-----------+------------+
| metaphone | dmetaphone |
+-----------+------------+
| 0MPSN     | TMPSN      |
+-----------+------------+
```

<Warning>
  O MySQL tem um `SOUNDEX()` próprio, e a função nativa vence quando você
  escreve o nome sem qualificação. As duas discordam: `SOUNDEX('Ashcraft')`
  retorna `A2613`, enquanto `vsql_fuzzystrmatch.soundex('Ashcraft')` retorna
  `A261`. A versão do MySQL é documentada como retornando uma string de
  qualquer comprimento, e a da extensão segue a definição Soundex de quatro
  caracteres. Qualifique a chamada com o nome da extensão para obter a que você
  quer. Nenhuma outra função aqui é sobreposta.
</Warning>

<Note>
  O `levenshtein_less_equal` para assim que a distância real ultrapassa o
  limite que você deu, e então retorna o limite mais 1, seja qual for a
  distância real. Com um limite de 2, ele retorna 3 para um par com distância 3
  e 3 para um par com distância 7. Leia o limite mais 1 como "mais distantes do
  que você perguntou".
</Note>
