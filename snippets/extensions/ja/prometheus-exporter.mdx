Prometheus のために MySQL をスクレイプするには、通常、ログインしてポーリングする別のエクスポータープロセスを実行する必要があります。`prometheus_exporter` は代わりにサーバーの内部から `/metrics` エンドポイントを提供するため、デプロイし、認証し、稼働させ続けるプロセスが 1 つ減ります。

</Note>

## インストール {#install}

<Warning>
  リポジトリのデフォルトブランチのコードは、現在の SDK に対してビルドできません。2026 年 5 月に SDK から削除された `make_sys_var_bool` と `make_status_var_int` を呼び出しているためです。移植済みのコードはオープンなプルリクエスト [#4](https://github.com/ProxySQL/vsql-prometheus-exporter/pull/4) にあります。このコードはプレビュー機能を宣言しているため、それを読み込むサーバーは `--vsql_allow_preview_extensions=ON` で起動する必要があります。
</Warning>

VillageSQL のビルドツリー (`VillageSQL_BUILD_DIR`) に対してそのブランチからビルドし、`.veb` ファイルをサーバーの `veb_dir` にコピーして、インストールします。

```sql
INSTALL EXTENSION prometheus_exporter;
```

## 追加される機能 {#what-it-adds}

HTTP リスナーと 3 つの設定を追加します。SQL 関数は追加しません。

| 設定 | デフォルト | 制御内容 |
|---|---|---|
| `prometheus_exporter.enabled` | `OFF` | リスナーを実行するかどうか |
| `prometheus_exporter.port` | `9104` | リッスンするポート |
| `prometheus_exporter.bind_address` | `127.0.0.1` | バインドするアドレス |

5 つのメトリクスファミリーがエクスポートされ、それぞれ取得元にちなんで名付けられています。

| プレフィックス | 取得元 |
|---|---|
| `mysql_global_status_` | `SHOW GLOBAL STATUS` |
| `mysql_global_variables_` | 数値のサーバー変数 |
| `mysql_innodb_metrics_` | `information_schema.innodb_metrics` |
| `mysql_replica_` | レプリカ上の `performance_schema` レプリケーションテーブル |
| `mysql_binlog_` | `SHOW BINARY LOGS` |

エクスポーターは、`requests_total`、`scrape_duration_us`、および `errors_total` を通じて自身についても報告します。

## 例 {#example}

メンテナーのクイックスタートは、これを有効にしてポートを選びます。

```sql
INSTALL EXTENSION prometheus_exporter;
SET GLOBAL prometheus_exporter.port = 9104;
SET GLOBAL prometheus_exporter.enabled = ON;
```

Prometheus は `http://127.0.0.1:9104/metrics` をスクレイプします。スタンドアロンの `mysqld_exporter` など別のプロセスがすでにポート 9104 を使用している場合、`enabled` は `ON` と読めますが、拡張機能はリッスンせず、そのポートでは別のプロセスが応答します。そのため、`lsof -nP -iTCP:9104 -sTCP:LISTEN` で `mysqld` がポートを保持していることを確認してください。

<Warning>
  リスナーは変更しない限り localhost にバインドし、それが安全な選択です。メトリクスはあなたのトラフィックと設定を表すため、ループバックアドレスから移す前に、ポートを認証を行うものの内側に置いてください。
</Warning>
