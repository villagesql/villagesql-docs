## What is VillageSQL Server?

VillageSQL Server is a drop-in replacement for MySQL with extensions for the agentic AI era. Its extension framework lets anyone add custom data types and custom functions to the server, without asking permission and without changing the server's code.

## Extensions for MySQL
An extension adds features to a running VillageSQL server. Extensions can add:
- **Custom data types:** new types for InnoDB columns, such as `UUID`, `COMPLEX`, and `INET`, that you use like the built-in types.
- **Custom functions:** functions written in C++ or Rust that you call from SQL.

You add and remove an extension with SQL: `INSTALL EXTENSION` and `UNINSTALL EXTENSION`.

See the [extension catalog](/extensions/catalog) for the extensions you can install.

### Build an Extension
Start with the [extension template](https://github.com/villagesql/vsql-extension-template) and follow the [C++ guide](/guides/cpp-extensions) or [Rust guide](/guides/rust-extensions). For a guided, AI-assisted workflow, try the [Extension Builder](https://villagesql.com/agent-skills).

## Why VillageSQL?

  <Card title="Drop-in Compatibility" icon="check-double">
    VillageSQL speaks the MySQL protocol, so your MySQL clients and drivers connect to it.
  </Card>
  <Card title="Extensible Core" icon="puzzle-piece">
    Add features to a running server with `INSTALL EXTENSION`. The server does not need a restart.
  </Card>
  <Card title="Open Ecosystem" icon="users">
