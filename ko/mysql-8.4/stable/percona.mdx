VillageSQL은 **Percona Server** 기반으로도 빌드됩니다. Percona Server는 MySQL과
소스 호환되는 포크이며, 자체 스토리지, 성능, 관측 기능을 추가합니다.

## 이 빌드란 무엇인가 {#what-this-is}

업스트림 MySQL 8.4 대신 Percona 8.4 코드베이스를 기반으로 빌드한 VillageSQL
서버입니다. VillageSQL 확장 프레임워크와 그 SQL 명령, 확장은 두 빌드에서 동일하게
동작합니다 — Percona 빌드는 동일한 VillageSQL 표면 아래에 다른 기반을 둔 것입니다.

VillageSQL은 Percona 자체 기능을 문서화하지 않습니다. Percona Server 자체에 관한
내용 — 스토리지 엔진, 튜닝 옵션, 구성 — 은
[Percona 공식 문서](https://docs.percona.com/percona-server/8.4/)를 참조하세요.

## 포함되지 않은 것 {#what-is-not-included}

이 빌드에는 Percona 기능 중 세 가지가 포함되지 않습니다.

**MyRocks.** RocksDB 스토리지 엔진은 빌드되지 않으므로 `SHOW ENGINES`에
`ROCKSDB`가 나타나지 않고 `rocksdb_*` 시스템 변수도 없습니다. 이 엔진을 요청하는
테이블은 실패합니다:

```sql
CREATE TABLE t (i INT) ENGINE=ROCKSDB;
-- ERROR 1286 (42000): Unknown storage engine 'ROCKSDB'
```

Percona 서버에서 만든 덤프를 복원하면 이 엔진을 지정한 첫 번째 테이블에서
멈추므로, 그 이전에 생성된 테이블은 남고 이후는 건너뜁니다.

**KMIP 키링 컴포넌트.** `component_keyring_file`, `component_keyring_kms`,
`component_keyring_vault`는 모두 제공되며 설치됩니다. `component_keyring_kmip`은
빌드되지 않으며, 설치하면 `ERROR 1126`으로 실패합니다.

**Percona의 coredumper.** 서버는 라이브러리가 빌드되었는지와 무관하게 이 옵션을
등록하므로 `--coredumper` 옵션은 여전히 허용되지만, 여기서는 라이브러리가 빌드되지
않았습니다.

Percona의 다른 추가 기능은 정상적으로 동작하며, `percona_udf` 컴포넌트, 감사 로그
플러그인, `USER_STATISTICS` 및 `TABLE_STATISTICS` 뷰가 포함되며, 이 두 뷰는
`SET GLOBAL userstat = ON` 이후에 채워집니다.

## Percona 빌드 식별하기 {#identifying-a-percona-build}

Percona 빌드는 버전 문자열에 다른 코드베이스를 보고합니다:

```sql
SELECT @@villagesql_server_version;
-- Example output: percona-8.4_0.0.7
```

이 변수의 의미는 [시스템 참조](/ko/mysql-8.4/stable/reference#villagesql_server_version)를
참조하세요. VillageSQL은 한 코드베이스(예: `mysql-8.4`)의 데이터 디렉터리를 다른
코드베이스(예: `percona-8.4`)를 실행하는 서버로 업그레이드하는 것을 거부합니다.
