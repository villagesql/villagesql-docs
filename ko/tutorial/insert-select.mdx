`VALUES`는 직접 입력한 행을 제공합니다. 그 자리에 쓴 `SELECT`는 서버가 계산한 행을 제공하므로, 쿼리할 수 있는 요약은 저장할 수 있는 요약입니다. 보고서 테이블을 채우는 방법이고, 행을 한 테이블에서 다른 테이블로 옮기는 방법입니다.

이 예제들은 [INSERT](/ko/tutorial/insert)의 `sakila_practice` 데이터베이스를 사용합니다. 시작하기 전에 거기 있는 설정 블록을 다시 실행한 다음, `mysql -u root -p sakila_practice`로 클라이언트를 여세요.

## INSERT SELECT의 동작 방식 {#how-insert-select-works}

```sql
INSERT INTO TARGET_TABLE (COLUMN_LIST)
SELECT SOURCE_COLUMNS FROM SOURCE_TABLE;
```

`TARGET_TABLE`을 쓰기 대상 테이블로, `COLUMN_LIST`를 그 테이블의 열로, `SOURCE_COLUMNS`를 쿼리가 반환하는 것으로, `SOURCE_TABLE`을 읽는 테이블로 바꾸세요.

`VALUES` 키워드는 없습니다. 열은 위치로 짝지어지므로, `SELECT`가 반환하는 첫 번째 것이 첫 번째로 지정한 열에 들어가고, 둘의 이름이 무엇인지는 상관없습니다. 쿼리가 반환하는 모든 행이 대상 테이블의 행이 됩니다.

## 예제 {#examples}

### 1) 요약 저장 {#1-store-a-summary}

`rating_count`는 비어 있고 `sakila.film`이 답을 가지고 있습니다. 테이블을 `database.table`로 지정하면 다른 데이터베이스에서 읽으므로, 문 1개가 2개의 데이터베이스를 넘나들 수 있습니다.

```sql
INSERT INTO rating_count (rating, films)
SELECT rating, COUNT(*) FROM sakila.film GROUP BY rating;
```

```text
Query OK, 5 rows affected (0.00 sec)
Records: 5  Duplicates: 0  Warnings: 0
```

`GROUP BY`가 5개의 행을 만들었고 5개의 행이 쓰였습니다.

```sql
SELECT * FROM rating_count ORDER BY films DESC;
```

```text
+--------+-------+
| rating | films |
+--------+-------+
| PG-13  |   223 |
| NC-17  |   210 |
| R      |   195 |
| PG     |   194 |
| G      |   178 |
+--------+-------+
5 rows in set (0.00 sec)
```

이제 이것은 보통의 행이고, 스냅샷입니다. `film`이 바뀌어도 아무것도 이 행을 갱신하지 않습니다.

### 2) 들어가는 길에 값 만들기 {#2-build-values-on-the-way-in}

`SELECT`는 무엇이든 계산할 수 있으므로, 들어가는 행이 그 모양 그대로 어딘가에 존재할 필요는 없습니다.

```sql
INSERT INTO member (first_name, last_name, email, joined)
SELECT first_name, last_name, CONCAT(LOWER(first_name), '.', LOWER(last_name), '@example.net'), '2026-05-01'
FROM sakila.staff;
```

```text
Query OK, 2 rows affected (0.01 sec)
Records: 2  Duplicates: 0  Warnings: 0
```

```sql
SELECT member_id, first_name, last_name, email FROM member WHERE joined = '2026-05-01';
```

```text
+-----------+------------+-----------+--------------------------+
| member_id | first_name | last_name | email                    |
+-----------+------------+-----------+--------------------------+
|         4 | Mike       | Hillyer   | mike.hillyer@example.net |
|         5 | Jon        | Stephens  | jon.stephens@example.net |
+-----------+------------+-----------+--------------------------+
2 rows in set (0.00 sec)
```

주소 열은 `CONCAT`으로 만들었고 날짜는 모든 행에 반복되는 상수입니다.

## ERROR 1136은 2개의 목록 길이가 다르다는 뜻입니다 {#error-1136-means-the-2-lists-are-different-lengths}

```sql
INSERT INTO rating_count (rating, films)
SELECT rating FROM sakila.film GROUP BY rating;
```

```text
ERROR 1136 (21S01): Column count doesn't match value count at row 1
```

2개의 열을 지정했고, 1개가 반환되었습니다. 이 오류가 나타날 때는 언제나 2개의 목록 길이가 다르므로, 세어 보세요. 아무것도 이름이나 의미를 검사하지 않으므로, 개수는 맞지만 엉뚱한 열을 반환하는 `SELECT`는 받아들여지고 엉터리 데이터를 씁니다. 먼저 `SELECT`를 따로 실행해서 무엇이 돌아오는지 읽으세요.

## 두 번째 실행은 테이블의 키와 만납니다 {#a-second-run-meets-the-tables-keys}

쿼리가 반환하는 모든 행이 테이블에 제시되고, 테이블의 규칙은 여전히 적용됩니다.

```sql
INSERT INTO rating_count (rating, films)
SELECT rating, COUNT(*) FROM sakila.film WHERE rating = 'G' GROUP BY rating;
```

```text
ERROR 1062 (23000): Duplicate entry 'G' for key 'rating_count.PRIMARY'
```

`rating`이 기본 키이고 `G`는 이미 저장되어 있습니다. 한 번 만들고 마는 것이 아니라 새로 고치고 싶은 요약에는 [upsert](/ko/tutorial/upsert)가 필요한데, 실패하는 대신 저장된 행을 갱신합니다.

## 요약 {#summary}

- `VALUES`가 들어갈 자리에 `SELECT`를 두고, `VALUES` 키워드는 쓰지 마세요.
- 열은 이름이 아니라 언제나 위치로 짝지어집니다.
- `ERROR 1136`은 2개의 목록 길이가 다르다는 뜻으로 읽으세요.
- 같은 문에서 다른 데이터베이스를 읽으려면 테이블을 `database.table`로 지정하세요.
- 두 번째 실행은 다른 삽입과 마찬가지로 대상 테이블의 키에 부딪힙니다.
