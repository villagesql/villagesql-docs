HammerDB는 [GitHub의 TPC-Council](https://github.com/TPC-Council/HammerDB)이 호스팅하는 오픈 소스 데이터베이스 벤치마크입니다. HammerDB는 VillageSQL을 별도의 데이터베이스로 지원하며, 두 가지 워크로드를 제공합니다. TPROC-C는 TPC-C 사양에서 파생된 OLTP 워크로드이고, TPROC-H는 TPC-H에서 파생된 분석 워크로드입니다. 이 가이드는 Docker를 사용해 VillageSQL 서버를 대상으로 TPROC-C를 실행합니다.

## 사전 준비 {#prerequisites}

- Docker. VillageSQL 서버와 HammerDB가 모두 컨테이너에서 실행되므로 호스트에는 둘 다 설치하지 않습니다.
- 약 5 GB의 여유 디스크 공간: 두 이미지에 약 2 GB, 아래 테스트가 쓰는 데이터에 약 3 GB가 필요합니다. 그 데이터의 대부분은 서버의 바이너리 로그이며, 바이너리 로그는 실행 시간이 길수록 커집니다.

## VillageSQL 서버 시작하기 {#start-a-villagesql-server}

HammerDB 컨테이너가 이름으로 서버에 연결할 수 있도록 Docker 네트워크를 만든 다음, 그 네트워크에서 서버를 시작하세요:

```bash
docker network create hammerdb-net
docker run -d --name vsql-bench --network hammerdb-net \
  -e MYSQL_ROOT_PASSWORD=hammerdb villagesql/server:latest
```

서버가 초기화되는 데 몇 초가 걸립니다. 이 명령이 버전을 출력하면 서버가 준비된 것입니다:

```bash
docker exec vsql-bench mysql -uroot -phammerdb -e "SELECT VERSION();"
```

이미 실행 중인 서버를 벤치마크하려면 이 단계를 건너뛰세요. 아래 스크립트의 `vsql_host`, `vsql_user`, `vsql_pass`를 그 서버의 주소와 자격 증명으로 설정하고, HammerDB 명령에서 `--network hammerdb-net`을 빼세요.

## HammerDB 스크립트 작성하기 {#write-the-hammerdb-scripts}

HammerDB는 명령줄 인터페이스인 `hammerdbcli`에서 실행되며, `hammerdbcli`는 설정과 명령이 담긴 스크립트를 읽습니다. 스크립트를 둘 폴더를 만드세요:

```bash
mkdir hammerdb-scripts && cd hammerdb-scripts
```

다음을 `build.tcl`로 저장하세요. 이 스크립트는 `tpcc`라는 데이터베이스에 TPROC-C 스키마를 빌드합니다:

```tcl
dbset db vsql
dbset bm TPROC-C
diset connection vsql_host vsql-bench
diset connection vsql_port 3306
diset connection vsql_ssl true
diset connection vsql_ssl_linux_capath ""
diset connection vsql_ssl_ca ""
diset connection vsql_ssl_cert ""
diset connection vsql_ssl_key ""
diset tpcc vsql_user root
diset tpcc vsql_pass hammerdb
diset tpcc vsql_dbase tpcc
diset tpcc vsql_count_ware 4
diset tpcc vsql_num_vu 4
buildschema
```

다음을 `run.tcl`로 저장하세요. 이 스크립트는 시간 제한 테스트를 실행합니다. 가상 사용자 4명으로 1분 동안 램프업한 다음 2분 동안 측정합니다:

```tcl
dbset db vsql
dbset bm TPROC-C
diset connection vsql_host vsql-bench
diset connection vsql_port 3306
diset connection vsql_ssl true
diset connection vsql_ssl_linux_capath ""
diset connection vsql_ssl_ca ""
diset connection vsql_ssl_cert ""
diset connection vsql_ssl_key ""
diset tpcc vsql_user root
diset tpcc vsql_pass hammerdb
diset tpcc vsql_dbase tpcc
diset tpcc vsql_driver timed
diset tpcc vsql_rampup 1
diset tpcc vsql_duration 2
loadscript
vuset vu 4
vucreate
vurun
```

`dbset db vsql`은 VillageSQL을 선택합니다. 다섯 개의 `ssl` 줄은 인증서 파일 없이 TLS를 켭니다. `root` 계정은 `caching_sha2_password`로 인증하는데, 이 방식은 TCP에서 암호화된 연결이 필요하며, HammerDB의 기본 인증서 폴더인 `/etc/mysql/certs`는 이미지에 없습니다.

## 스키마 빌드하기 {#build-the-schema}

스크립트 폴더를 마운트한 상태로 HammerDB VillageSQL 이미지에서 `build.tcl`을 실행하세요:

```bash
docker run --rm --network hammerdb-net -v "$PWD":/scripts \
  tpcorg/hammerdb:v6.1.1-villagesql ./hammerdbcli auto /scripts/build.tcl
```

각 가상 사용자가 웨어하우스를 로드한 다음, HammerDB가 스토어드 프로시저를 만들고 통계를 수집합니다. 빌드는 다음 줄로 끝납니다:

```text
Vuser 1:TPCC SCHEMA COMPLETE
Vuser 1:FINISHED SUCCESS
ALL VIRTUAL USERS COMPLETE
```

HammerDB는 빌드가 실패해도 `ALL VIRTUAL USERS COMPLETE`를 출력하므로, 출력에 `FINISHED FAILED`가 있는지 확인하세요. 이 문자열이 있으면 [문제 해결](#troubleshooting)을 참고하세요.

## 테스트 실행하기 {#run-the-test}

```bash
docker run --rm --network hammerdb-net -v "$PWD":/scripts \
  tpcorg/hammerdb:v6.1.1-villagesql ./hammerdbcli auto /scripts/run.tcl
```

램프업과 시간 제한 실행이 끝나면 HammerDB가 결과를 출력합니다:

```text
Vuser 1:TEST RESULT : System achieved <nopm> NOPM from <tpm> VillageSQL TPM
```

NOPM(분당 신규 주문 수)은 HammerDB가 권장하는 주요 지표입니다. HammerDB는 NOPM을 테스트 스키마 자체에서 측정하므로, NOPM은 특정 데이터베이스가 트랜잭션을 세는 방식에 좌우되지 않습니다.

HammerDB 결과는 TPC-C 결과가 아닙니다. HammerDB 결과를 공개된 TPC-C 결과와 비교하거나 tpmC로 보고하지 마세요.

## 테스트 규모 키우기 {#scale-the-test}

위의 테스트는 구성이 동작하는지 확인합니다. 서버 성능을 측정하려면 다음 설정을 높이세요:

| 설정 | 위 테스트의 값 | 제어 항목 |
|---|---|---|
| `vsql_count_ware` | 4 | 웨어하우스 수. 데이터의 크기를 결정합니다 |
| `vsql_num_vu` | 4 | 스키마를 병렬로 로드하는 가상 사용자 수 |
| `vuset vu` | 4 | 테스트를 실행하는 가상 사용자 수 |
| `vsql_rampup` / `vsql_duration` | 1분 / 2분 | 측정 전 램프업 시간(분)과 측정 시간(분) |

[HammerDB 문서](https://www.hammerdb.com/docs/)는 모든 TPROC-C 설정, TPROC-H 워크로드, HammerDB GUI를 다룹니다.

## 문제 해결 {#troubleshooting}

| 오류 | 원인과 해결 방법 |
|---|---|
| `Authentication plugin 'caching_sha2_password' reported error: Authentication requires secure connection.` | 스크립트가 TLS 없이 연결합니다. 위 스크립트의 `ssl` 줄 다섯 개를 추가하세요. |
| `Database tpcc exists but is not empty, specify a new or empty database name` | 이전 빌드에서 생성된 `tpcc` 데이터베이스가 남아 있습니다. `docker exec vsql-bench mysql -uroot -phammerdb -e "DROP DATABASE tpcc;"`로 삭제하거나 `vsql_dbase`를 새 이름으로 설정하세요. |
| `SSL connection error: SSL_CTX_set_default_verify_paths failed` | `vsql_ssl`이 `true`이지만 HammerDB가 인증서 파일을 찾고 있습니다. `vsql_ssl_linux_capath`, `vsql_ssl_ca`, `vsql_ssl_cert`, `vsql_ssl_key`를 `""`로 설정하세요. |

## 정리하기 {#clean-up}

서버 컨테이너를 데이터 볼륨과 함께 제거하고, 네트워크도 제거하세요:

```bash
docker rm -fv vsql-bench
docker network rm hammerdb-net
```
